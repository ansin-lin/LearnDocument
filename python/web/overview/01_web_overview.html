    Python Web 开发与框架概览¶

    一、学习目标¶

    完成本章后，学员应能够：

    • 说明什么是 Python Web 开发
    • 说明 Python 后端在 Web 系统中的位置和主要职责
    • 列举 Python Web 常见的项目类型
    • 说明 Web 框架主要解决哪些问题
    • 区分 Flask、FastAPI 和 Django 的基本定位
    • 比较 Flask、FastAPI 和 Django 的适用场景
    • 说明 Python Web 在企业项目中的常见使用场景

    二、员工管理系统中的Python后端¶

    本章使用员工管理系统作为示例讲解 Python Web 开发。

    在这个系统中，浏览器页面负责显示员工列表和接收用户输入；Python后端负责接收请求、校验数据、执行员工管理规则、访问数据库并返回结果。

    例如，用户在页面点击“查询”后，请求会发送到Python后端。后端查询员工数据，再把JSON响应返回给页面：

    员工查询页面
    ↓ GET /api/v1/employees
Python Web后端
    ↓ 查询员工数据
数据库
    ↑ 查询结果
Python Web后端
    ↑ JSON响应
员工查询页面

    三、什么是 Python Web 开发¶

    Python Web 开发是使用 Python 编写 Web 系统后端程序的开发方式。

    Python 程序通常运行在服务器上，接收浏览器、Vue、React、手机应用或其他系统发送的请求，执行处理后再返回响应。

    浏览器 / Vue / React / 其他系统
                ↓ HTTP 请求
        Python Web 应用
                ↓
      业务处理、权限判断
                ↓
       数据库 / 文件 / 外部 API
                ↑
        Python Web 应用
                ↑ HTTP 响应
浏览器 / Vue / React / 其他系统

    Python Web 并不是让 Python 直接“显示网页”。在前后端分离项目中，页面通常由 HTML、CSS、JavaScript、Vue 或 React 构建，Python 主要负责后端接口和业务处理。

    四、Python 在 Web 系统中的主要职责¶

    4.1 接收和处理请求¶

    Python Web 应用根据请求地址和 HTTP 方法找到对应的处理程序。

    例如：

    GET  /api/users      查询用户列表
GET  /api/users/1001 查询指定用户
POST /api/users      新增用户
PUT  /api/users/1001 修改指定用户

    路由、HTTP方法和参数处理共同决定哪个Python函数接收请求。

    4.2 校验输入数据¶

    后端不能直接信任外部传入的数据，需要检查：

    • 必填项是否存在
    • 数据类型是否正确
    • 字符串长度是否符合要求
    • 数值是否在允许范围内
    • 数据是否符合业务规则

    例如，创建用户时需要检查用户名是否为空、邮箱格式是否正确以及账号是否已经存在。

    4.3 执行业务逻辑¶

    业务逻辑是系统真正需要完成的工作，例如：

    • 判断用户是否可以登录
    • 计算订单金额
    • 检查商品库存
    • 判断申请是否可以审批
    • 根据角色判断操作权限

    业务逻辑通常不应该全部写在路由处理函数中。企业项目会根据规模将其放入 Service 等业务层中。

    4.4 访问数据库¶

    Python 后端可以执行 SQL，也可以通过 ORM 操作数据库，完成：

    • 查询数据
    • 新增数据
    • 修改数据
    • 删除数据
    • 事务处理

    Web项目可以直接执行SQL，也可以使用SQLAlchemy等ORM工具访问数据库。

    4.5 认证和权限控制¶

    后端需要确认：

    • 当前用户是谁
    • 用户是否已经登录
    • 用户属于什么角色
    • 用户是否有权执行当前操作

    即使前端隐藏了按钮，后端仍然必须进行权限判断，因为请求可以绕过页面直接发送。

    4.6 处理文件和报表¶

    Python 适合处理 CSV、Excel、JSON、文本和图片等文件。在企业 Web 系统中，经常用于：

    • CSV 数据导入和导出
    • Excel 报表生成
    • 文件上传和下载
    • 批量数据校验
    • 统计结果输出

    4.7 调用外部系统¶

    Python 后端还可以通过 HTTP 调用其他系统的 API，例如：

    • 支付服务
    • 邮件和短信服务
    • 地址和物流服务
    • 公司内部其他业务系统

    调用外部接口时需要考虑超时、异常、重试、日志和数据校验。

    4.8 日志、测试和运行维护¶

    企业项目不仅需要实现功能，还需要：

    • 使用日志记录重要处理和异常
    • 使用自动化测试验证程序行为
    • 使用配置文件或环境变量区分不同环境
    • 管理第三方依赖和版本
    • 提供稳定的启动和部署方式

    这些内容在实际项目中都会用到。

    五、Python Web 可以开发什么¶

    5.1 REST API¶

    后端接收 HTTP 请求并返回 JSON，供 Vue、React、手机应用或其他系统使用。

    常见功能包括用户管理、商品查询、订单处理和权限验证。

    5.2 企业后台管理系统¶

    用于管理公司内部数据和业务流程，例如：

    • 员工和权限管理
    • 客户信息管理
    • 订单和库存管理
    • 审批和工作流管理
    • 数据查询和报表输出

    5.3 服务端渲染网站¶

    后端根据数据生成 HTML 页面，再将完整页面返回给浏览器。Django 和 Flask 都可以实现这种开发方式。

    5.4 文件、报表和数据处理系统¶

    Python 在文件处理和数据处理方面库较多，适合开发：

    • CSV 批量导入系统
    • Excel 报表生成系统
    • 数据清洗和统计后台
    • 文件转换和下载服务

    5.5 内部工具和小型业务系统¶

    Python 开发速度较快，适合构建内部 API、管理工具、验证系统和小型业务应用。

    5.6 后台任务和批处理¶

    有些工作不适合在一次网页请求中立即完成，例如大量邮件发送、大文件处理和定时统计。此时可以由 Python 批处理或任务队列在后台执行。

    六、Web 框架的主要作用¶

    Web 框架提供开发 Web 系统时常用的结构和工具。

    框架能力 解决的问题
    路由 根据 URL 和 HTTP 方法找到处理程序
    请求解析 读取路径参数、查询参数、表单和 JSON
    响应处理 返回 JSON、HTML、文件和状态码
    参数校验 检查请求数据的类型和规则
    异常处理 将程序异常转换为适当的错误响应
    中间件 统一处理日志、认证、跨域等公共逻辑
    模板 在服务端生成 HTML 页面
    数据库集成 配合 ORM 或数据访问工具操作数据库
    测试支持 模拟请求并验证接口行为

    框架可以减少重复代码，但业务规则、数据库设计、异常处理和测试仍然需要开发者自己完成。

    七、常见 Python Web 框架¶

    7.1 Flask¶

    Flask 是轻量级 Web 框架，只提供较基础的 Web 功能，其他能力可以根据项目需要组合扩展。

    适合：

    • 学习路由、请求和响应的基本原理
    • 开发小型 Web 应用或内部工具
    • 根据需要自由选择项目组件

    需要注意：项目规模扩大后，团队需要自行统一目录、参数校验、数据库和异常处理等规范。

    7.2 FastAPI¶

    FastAPI 主要面向现代 API 开发，重视类型提示、参数校验和接口文档。

    适合：

    • REST API
    • 前后端分离项目
    • 数据服务和内部接口
    • 需要自动生成接口文档的项目

    FastAPI 常用于前后端分离 API、参数校验、数据库访问和接口测试。

    7.3 Django¶

    Django 是功能较完整的 Web 框架，内置 ORM、模板、认证、管理后台等能力。

    适合：

    • 完整的企业后台系统
    • 数据管理类系统
    • 服务端渲染网站
    • 希望使用统一框架能力快速构建业务系统的项目

    Django 也可以结合 Django REST Framework 开发前后端分离 API。

    7.4 三个框架的定位对比¶

    对比项 Flask FastAPI Django
    框架定位 轻量 Web 框架 现代 API 框架 完整 Web 框架
    主要特点 轻量、灵活 类型提示和接口文档较完整 内置能力较多
    参数校验 通常自行组合 Pydantic 集成较好 Form、Serializer 等方式
    ORM 不强制指定 不强制指定 内置 Django ORM
    管理后台 无内置完整后台 无内置完整后台 内置 Admin
    常见使用方向 小型应用、内部工具 API、前后端分离 管理系统、完整网站

    这三个框架不是简单的“初级、中级、高级”关系。选择框架时，应根据项目目标、团队经验和维护要求判断。

    八、三个框架如何实现Web系统¶

    三个框架都可以开发员工管理系统，但提供的默认能力不同：

    FastAPI
    → 重点实现前后端分离REST API

Flask
    → 开发者自行组合路由、校验、ORM等组件

Django
    → 使用内置ORM、认证、模板和Admin开发完整系统

    框架选择不会改变员工、部门、登录和权限等业务需求。变化的是项目结构、框架提供的工具以及开发者需要自行实现的范围。

    九、Python Web 程序的基本运行过程¶

    下面通过一个简化示例观察Python Web程序的基本形式：

    from fastapi import FastAPI

app = FastAPI()


@app.get("/api/health")
def get_health() -> dict[str, str]:
    return {"status": "ok"}

    这个程序表达了四件事：

    1. 创建一个 FastAPI 应用对象。
    2. 声明后端接收 GET /api/health 请求。
    3. 请求到达后执行 get_health() 函数。
    4. 函数返回字典，框架将其转换为 JSON 响应。

    预期响应内容：

    {
  "status": "ok"
}

    完整安装、启动和访问方式将在“FastAPI 入门”章节讲解。这里的重点是理解：框架负责连接 HTTP 请求与 Python 函数，函数负责完成具体处理。

    十、Python Web 与前端、数据库的关系¶

    以用户查询功能为例：

    Vue / React 页面
  ↓ 发送 GET /api/users/1001
FastAPI 路由
  ↓ 调用用户查询业务
Service 业务层
  ↓ 调用数据访问功能
SQLAlchemy / SQL
  ↓ 查询
数据库
  ↑ 用户数据
Python 后端转换为响应
  ↑ 返回 JSON
Vue / React 显示用户信息

    Python 后端处在前端和数据库之间，但它不只是“转发数据”。后端还需要校验参数、执行权限判断、应用业务规则、处理异常并记录日志。

    十一、Python Web 的优势和限制¶

    11.1 常见优势¶

    • 语法相对清晰，便于快速开发和阅读
    • Web、文件、数据分析和自动化库较丰富
    • 适合 API、内部系统、数据服务和后台工具
    • 可以复用 Python 的数据处理和自动化能力
    • FastAPI、Django 等框架生态较成熟

    11.2 需要了解的限制¶

    • Python 不是所有企业 Web 项目的默认选择
    • CPU 密集型任务可能需要其他方案、并行处理或专用服务
    • 动态类型项目更需要类型提示、测试和 Code Review
    • 不合理使用同步阻塞操作会影响接口性能
    • 大型项目仍然需要明确分层、依赖管理和团队规范

    技术选型不能只比较语言语法，还要考虑既有系统、团队经验、性能要求、部署环境和长期维护成本。

    十二、企业项目中的 Python Web¶

    在企业项目中，Java 和 Spring Boot 常用于大型核心业务系统。Python Web 也可能出现在以下场景：

    • 公司内部管理工具
    • 数据查询和报表系统
    • AI 或数据处理功能的 API
    • CSV、Excel 和文件处理服务
    • 既有系统周边的小型服务
    • 自动化运维和管理后台
    • 采用 Django、Flask 或 FastAPI 的 Web 服务

    具体情况会因公司、客户、行业和既有技术栈而不同，不能简单认为只有某一种语言适合所有项目。

    12.1 项目开发中需要关注的内容¶

    • 根据接口设计书实现请求参数和响应字段
    • 确认正常流程、异常流程和边界条件
    • 明确本次修改的功能和影响范围
    • 使用日志保留可调查的信息
    • 编写并执行单体测试
    • 保存接口响应、数据库结果等测试证据
    • 接受 Code Review 并处理指摘
    • 修改接口时及时与前端和相关系统确认

    Python 代码较短并不代表可以省略设计、测试和文档。日本项目通常重视实现与设计一致、修改范围清楚以及结果可以确认。

    十三、常见认识误区¶

    13.1 会 Python 就会 Python Web¶

    Python 基础是前提，但 Web 开发还需要学习 HTTP、数据库、认证、测试、部署和项目结构。

    13.2 Web 框架会自动完成业务功能¶

    框架提供开发工具，业务规则仍然需要开发者根据需求和设计实现。

    13.3 前端已经校验，后端可以不校验¶

    请求可以绕过前端直接发送，因此后端必须进行参数和权限校验。

    13.4 FastAPI、Flask 和 Django 必须全部掌握¶

    新人应先完成一条主线，能够开发和测试完整功能，再根据项目需要学习其他框架。

    13.5 Python 只能用于小型系统¶

    Python 可以用于不同规模的系统，但系统能否稳定扩展取决于架构、代码质量、数据库、部署和运维等多方面因素，不能只根据语言判断。

    十六、本章总结¶

    • Python Web 开发主要使用 Python 编写服务器端程序。
    • Python 后端负责请求处理、业务逻辑、数据访问、权限、文件和外部接口等工作。
    • Web 框架负责连接 HTTP 请求和 Python 程序，并提供常用开发能力。
    • Flask、FastAPI 和 Django 的定位不同，不是简单的难度等级关系。
    • FastAPI、Flask和Django提供的默认能力不同，应根据项目需求选择。
    • Python Web 需要与前端、数据库、测试和部署共同组成完整项目。
    • 日本项目中的 Python 开发同样需要重视设计、测试、日志、Review 和影响范围。
