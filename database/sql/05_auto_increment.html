    第5章 自增列与主键设计¶

    本章目标：理解自增列的作用，掌握 MySQL、Oracle、PostgreSQL、SQL Server 中自增主键的创建、插入、查看、修改和删除相关写法。

    一、为什么需要自增列¶

    主键用于唯一识别一行数据。

    如果每次插入数据都手动指定 ID，容易重复或混乱。

    自增列可以让数据库自动生成 ID。

    例如插入员工时，只提供姓名：

    INSERT INTO employees (name)
VALUES ('Tanaka');

    数据库自动生成 id。

    二、四种数据库自增写法¶

    数据库 常见写法 说明
    MySQL AUTO_INCREMENT MySQL 常用自增列
    Oracle 12c+ GENERATED ... AS IDENTITY Oracle 12c 开始支持 Identity Column
    Oracle 旧项目 SEQUENCE.NEXTVAL Oracle 12c 以前常见做法
    PostgreSQL 10+ GENERATED ... AS IDENTITY PostgreSQL 10 开始支持 SQL 标准 Identity
    PostgreSQL 旧写法 SERIAL / BIGSERIAL 旧项目常见，本质上会创建序列
    SQL Server IDENTITY(起始值,增长值) SQL Server 常用自增列

    三、MySQL 自增主键¶

    3.1 创建自增主键¶

    语法：

    CREATE TABLE 表名 (
    主键列名 BIGINT PRIMARY KEY AUTO_INCREMENT,
    列名 数据类型 约束
);

    示例：

    CREATE TABLE employees (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    name VARCHAR(100) NOT NULL
);

    3.2 插入数据¶

    插入数据时通常省略自增列：

    INSERT INTO employees (name)
VALUES ('Tanaka');

    如果确实要手动指定 ID，也可以写：

    INSERT INTO employees (id, name)
VALUES (100, 'Suzuki');

    但手动指定 ID 时必须保证不重复。

    3.3 查看当前自增值¶

    SHOW TABLE STATUS LIKE 'employees';

    结果中 Auto_increment 表示下一次自动生成的值。

    3.4 修改自增起始值¶

    ALTER TABLE employees
AUTO_INCREMENT = 1000;

    这表示下一次自动生成的 ID 从 1000 附近开始。

    3.5 删除自增属性¶

    MySQL 中不能只删除 AUTO_INCREMENT 关键词，通常要重新修改列定义。

    ALTER TABLE employees
MODIFY id BIGINT NOT NULL;

    注意：如果该列仍然是主键，需要保留 NOT NULL。

    四、Oracle 自增主键¶

    Oracle 有两种常见方式：

    • Oracle 12c+：Identity Column
    • Oracle 旧项目：Sequence

    4.1 Oracle Identity 的两种常见写法¶

    Oracle 12c 以上支持：

    写法 是否允许手动插入 ID 说明
    GENERATED ALWAYS AS IDENTITY 默认不允许 ID 必须由数据库自动生成
    GENERATED BY DEFAULT AS IDENTITY 允许手动插入 如果没有提供 ID，则数据库自动生成

    4.2 默认自增：不手动指定 ID¶

    语法：

    CREATE TABLE 表名 (
    主键列名 NUMBER(19) GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    列名 数据类型 约束
);

    示例：

    CREATE TABLE employees (
    id NUMBER(19) GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    name VARCHAR2(100) NOT NULL
);

    插入数据：

    INSERT INTO employees (name)
VALUES ('Tanaka');

    这种写法下，下面这种手动指定 ID 的写法默认不允许：

    INSERT INTO employees (id, name)
VALUES (100, 'Suzuki');

    4.3 可以手动指定 ID：BY DEFAULT¶

    语法：

    CREATE TABLE 表名 (
    主键列名 NUMBER(19) GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    列名 数据类型 约束
);

    示例：

    CREATE TABLE employees (
    id NUMBER(19) GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    name VARCHAR2(100) NOT NULL
);

    省略 ID 时，数据库自动生成：

    INSERT INTO employees (name)
VALUES ('Tanaka');

    手动指定 ID 也允许：

    INSERT INTO employees (id, name)
VALUES (100, 'Suzuki');

    4.4 BY DEFAULT ON NULL¶

    BY DEFAULT ON NULL 表示插入 NULL 时也自动生成 ID。

    CREATE TABLE employees (
    id NUMBER(19) GENERATED BY DEFAULT ON NULL AS IDENTITY PRIMARY KEY,
    name VARCHAR2(100) NOT NULL
);

    下面写法会自动生成 ID：

    INSERT INTO employees (id, name)
VALUES (NULL, 'Tanaka');

    4.5 修改 Oracle Identity¶

    修改起始值或增长值：

    ALTER TABLE employees
MODIFY id GENERATED BY DEFAULT AS IDENTITY (START WITH 1000 INCREMENT BY 1);

    实际项目中修改 identity 前要确认当前已有最大 ID，避免主键冲突。

    4.6 删除 Oracle Identity 属性¶

    ALTER TABLE employees
MODIFY id DROP IDENTITY;

    删除后，id 不再自动生成。

    4.7 Oracle Sequence 旧写法¶

    Oracle 12c 以前常用 Sequence 生成编号。

    创建序列：

    CREATE SEQUENCE 序列名 START WITH 起始值 INCREMENT BY 增长值;

    示例：

    CREATE SEQUENCE employee_seq START WITH 1 INCREMENT BY 1;

    插入数据时使用 NEXTVAL：

    INSERT INTO employees (id, name)
VALUES (employee_seq.NEXTVAL, 'Tanaka');

    查看下一个序列值：

    SELECT employee_seq.NEXTVAL
FROM dual;

    删除序列：

    DROP SEQUENCE employee_seq;

    五、PostgreSQL 自增主键¶

    PostgreSQL 有两种常见写法：

    • PostgreSQL 10+ 推荐使用 Identity Column。
    • 旧项目常见 SERIAL / BIGSERIAL。

    5.1 PostgreSQL 10+ 推荐写法¶

    语法：

    CREATE TABLE 表名 (
    主键列名 BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    列名 数据类型 约束
);

    示例：

    CREATE TABLE employees (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    name VARCHAR(100) NOT NULL
);

    插入数据：

    INSERT INTO employees (name)
VALUES ('Tanaka');

    5.2 ALWAYS 和 BY DEFAULT¶

    写法 是否允许手动插入 ID 说明
    GENERATED ALWAYS AS IDENTITY 默认不允许 更严格，ID 由数据库生成
    GENERATED BY DEFAULT AS IDENTITY 允许手动插入 没有提供 ID 时自动生成

    如果使用 GENERATED ALWAYS AS IDENTITY，但确实要手动插入 ID，需要使用覆盖写法：

    INSERT INTO employees (id, name)
OVERRIDING SYSTEM VALUE
VALUES (100, 'Suzuki');

    5.3 SERIAL / BIGSERIAL 旧写法¶

    SERIAL 和 BIGSERIAL 是 PostgreSQL 旧项目中常见写法。

    CREATE TABLE employees (
    id BIGSERIAL PRIMARY KEY,
    name VARCHAR(100) NOT NULL
);

    说明：

    • SERIAL 通常对应整数序列。
    • BIGSERIAL 通常对应长整数序列。
    • 它本质上会创建一个序列，并让列默认使用该序列生成值。

    新项目优先使用 GENERATED ... AS IDENTITY，旧项目读代码时要能看懂 SERIAL。

    5.4 修改 Identity¶

    修改重新开始值：

    ALTER TABLE employees
ALTER COLUMN id RESTART WITH 1000;

    修改增长值：

    ALTER TABLE employees
ALTER COLUMN id SET INCREMENT BY 1;

    5.5 删除 Identity 属性¶

    ALTER TABLE employees
ALTER COLUMN id DROP IDENTITY;

    删除后，id 不再自动生成。

    5.6 查看序列¶

    如果使用 SERIAL / BIGSERIAL，可以查看表结构或序列。

    SELECT pg_get_serial_sequence('employees', 'id');

    六、SQL Server 自增主键¶

    6.1 创建自增主键¶

    语法：

    CREATE TABLE 表名 (
    主键列名 BIGINT IDENTITY(起始值,增长值) PRIMARY KEY,
    列名 数据类型 约束
);

    示例：

    CREATE TABLE employees (
    id BIGINT IDENTITY(1,1) PRIMARY KEY,
    name VARCHAR(100) NOT NULL
);

    IDENTITY(1,1) 表示从 1 开始，每次增加 1。

    6.2 插入数据¶

    通常省略 identity 列：

    INSERT INTO employees (name)
VALUES ('Tanaka');

    如果需要手动插入 identity 值，需要临时开启：

    SET IDENTITY_INSERT employees ON;

INSERT INTO employees (id, name)
VALUES (100, 'Suzuki');

SET IDENTITY_INSERT employees OFF;

    6.3 查看当前 Identity¶

    DBCC CHECKIDENT ('employees');

    6.4 修改 Identity 当前值¶

    DBCC CHECKIDENT ('employees', RESEED, 1000);

    下一次生成值会基于重新设置后的值继续增长。

    6.5 删除 Identity 属性¶

    SQL Server 不能直接把已有列的 IDENTITY 属性删除。

    常见处理方式：

    1. 新建一张没有 IDENTITY 的表。
    2. 迁移数据。
    3. 删除旧表。
    4. 重命名新表。

    这个操作风险较高，实际项目中需要先备份并确认依赖关系。

    七、自增主键操作对比¶

    操作 MySQL Oracle PostgreSQL SQL Server
    创建自增 AUTO_INCREMENT GENERATED ... AS IDENTITY GENERATED ... AS IDENTITY IDENTITY(1,1)
    允许手动插入 可以，但要避免重复 BY DEFAULT 允许，ALWAYS 默认不允许 BY DEFAULT 允许，ALWAYS 默认不允许 需要 SET IDENTITY_INSERT ON
    修改起始值 ALTER TABLE ... AUTO_INCREMENT = 值 ALTER TABLE ... MODIFY ... IDENTITY (...) ALTER TABLE ... ALTER COLUMN ... RESTART WITH 值 DBCC CHECKIDENT
    删除自增属性 修改列定义 DROP IDENTITY DROP IDENTITY 不能直接删除，通常重建表

    八、常见错误¶

    错误 原因 修正
    手动插入重复 ID 主键冲突 自增主键通常不手动指定
    Oracle ALWAYS 还手动插入 ID ALWAYS 默认不允许手动值 使用 BY DEFAULT 或调整插入方式
    PostgreSQL 不区分 Identity 和 Serial 新旧写法混淆 新项目优先 Identity，旧项目能看懂 Serial
    SQL Server 直接插入 identity 值失败 未开启 IDENTITY_INSERT 临时开启后插入，再关闭
    修改起始值小于已有最大 ID 后续可能主键冲突 修改前先确认当前最大 ID

    • 自增列用于自动生成主键。
