# LearnDocument structure context

Use this reference only for navigation, restructuring, cross-course ownership, or migration work. The live repository always overrides this descriptive map.

## Course ownership

- Java/Spring/MyBatis/database/PL/SQL form the backend route.
- Python has a shared foundation followed by Web, data analysis, and automation directions.
- Frontend covers Vue/React, UI, build tools and testing.
- Web fundamentals are shared; language routes summarize and link rather than reteach them.
- Linux, Shell, Git, AWS, deployment and troubleshooting belong to tools/operations.
- Comprehensive and interview documents consolidate learned content; they do not define prerequisites.

General SQL belongs in SQL lessons; framework-specific mapping and transactions belong in framework lessons. Git and shared deployment concepts remain in their canonical courses, with only task-specific workflow repeated elsewhere.

## Repository constraints

- Course generations differ in heading vocabulary and depth; normalize only the affected course unless a broader migration is authorized.
- Treat `mkdocs.yml`, course indexes, filenames and actual files as a four-way navigation check.
- Existing uncommitted changes may be intentional; do not overwrite unrelated work.
- JARs and images are support assets, not lesson prose.
- A rename or move requires repository-wide reference search; a structure migration requires an explicit old-to-new mapping.
- Modify non-teaching assets or build configuration only when required for lesson correctness or navigation.
