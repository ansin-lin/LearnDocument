# 第1章 数据库工具与连接基础

> 本章目标：理解连接数据库需要哪些信息，知道常见客户端工具的作用，能够看懂连接配置。

## 一、为什么需要数据库工具

数据库通常作为服务运行在本机或服务器上。

开发人员需要通过客户端工具连接数据库，执行 SQL，查看表结构和数据。

常见数据库工具：

| 工具 | 常见用途 |
| --- | --- |
| A5:SQL Mk-2 | 日本项目中常见，支持多种数据库 |
| DBeaver | 跨平台数据库客户端 |
| MySQL Workbench | MySQL 官方图形工具 |
| SQL Developer | Oracle 常用工具 |
| SQL Server Management Studio | SQL Server 官方工具 |
| pgAdmin | PostgreSQL 常用工具 |

## 二、连接数据库需要的信息

无论连接哪种数据库，通常都需要下面的信息。

| 项目 | 示例 | 说明 |
| --- | --- | --- |
| 主机名 | `localhost` | 数据库服务器地址 |
| 端口 | `3306` | 数据库服务端口 |
| 用户名 | `root` | 登录数据库的用户 |
| 密码 | `password` | 用户密码 |
| 数据库名 / 服务名 | `training_db` | 要连接的数据空间 |

## 三、四种数据库默认端口

| 数据库 | 默认端口 |
| --- | --- |
| MySQL | `3306` |
| Oracle | `1521` |
| PostgreSQL | `5432` |
| SQL Server | `1433` |

## 四、数据库、Schema 与用户

不同数据库对“数据库”和“Schema”的理解不完全一样。

| 数据库 | 常见理解 |
| --- | --- |
| MySQL | 一个服务下有多个数据库 |
| PostgreSQL | 一个数据库下可以有多个 Schema，默认 `public` |
| Oracle | 用户和 Schema 关系很近，通常一个用户对应一个 Schema |
| SQL Server | 一个服务下有多个数据库，数据库下有 Schema，常见 `dbo` |

学习时先记住：

- MySQL 常说“创建数据库”。
- Oracle 更常见的是“创建用户 / Schema”。
- PostgreSQL 和 SQL Server 也有 Schema 概念。

## 五、执行 SQL 的基本流程

1. 打开数据库工具。
2. 新建数据库连接。
3. 输入主机、端口、用户、密码等信息。
4. 测试连接。
5. 打开 SQL 编辑器。
6. 输入 SQL。
7. 执行 SQL。
8. 查看结果或错误信息。

## 六、常见错误

| 错误 | 原因 | 修正 |
| --- | --- | --- |
| 连接不上 | 服务未启动、端口错误、防火墙限制 | 检查服务和端口 |
| 登录失败 | 用户名或密码错误 | 确认账号密码 |
| 找不到数据库 | 数据库名、服务名或 Schema 错误 | 确认连接目标 |
| 中文乱码 | 客户端编码和数据库编码不一致 | 使用 UTF-8 或项目指定编码 |

## 八、本章总结

- 数据库工具用于连接数据库和执行 SQL。
- 连接数据库需要主机、端口、用户、密码和目标数据库信息。
- 四种数据库的数据库、Schema、用户概念有差异。
