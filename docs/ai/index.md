# AI 工具与业务应用开发

这套课程解决两个实际问题：第一，怎样使用 AI 工具提高需求分析、编码、测试、调查和文档工作的效率；第二，怎样调用大语言模型 API，为已有业务系统增加文本分类、信息提取、知识检索和受控业务操作能力。

课程不重新讲 Python 语法、FastAPI 基础、React 基础和 SQL 基础。进入开发者路线前，请先完成对应课程。AI 章节只说明新增的模型能力、业务边界和验证方法。

## 学完能做什么

完成主线后，你应能够：

- 判断任务是否适合使用生成式 AI，并定义可测量的成功标准。
- 使用 AI 工具完成一次有证据的需求分析、编码、测试、Review 和障碍调查。
- 在既有 FastAPI 项目中安全调用模型 API，处理结构化输出、超时、错误和成本。
- 实现带来源的企业知识库 RAG，并分别评价检索和回答质量。
- 为模型提供只读及写入工具，设置参数校验、权限、确认、幂等和审计边界。
- 通过日志、评估集、Docker、部署手顺和 Review 清单交付一个可维护的 AI 应用。

## 贯穿项目

开发者路线使用同一个“ServiceDesk AI 工单智能助手”：

1. 将用户描述整理为结构化工单。
2. 对工单进行分类、摘要和优先级建议。
3. 通过企业文档回答问题并返回引用来源。
4. 查询工单状态；写操作必须经过权限检查和人工确认。
5. 记录模型、提示版本、Token、耗时、错误与评价结果。

完整边界和固定验收样例见[贯穿项目规格](project_spec.md)。

## 学习入口

- 所有学员：从[教学路线](learning_path.md)的阶段一开始，完成第 1～16 章。
- AI 应用开发者：在第 1～16 章基础上，确认 Python、FastAPI、HTTP、SQL 和测试前置能力，再学习第 17～50 章。
- 已有 AI 接口经验：可以从第 20 章开始自测，但仍需完成第 23、40、43 和 50 章的安全与评价验收。

## 技术主线

- 后端：已有 FastAPI 项目；课程只增加 AI 相关模块。
- 模型接口：以 OpenAI Responses API 的当前官方用法作为一条可运行示例；核心设计保持供应商可替换。
- 结构化校验：Pydantic。
- 向量存储：PostgreSQL + pgvector。
- 前端：已有 React 页面；课程只讲 AI 交互状态和 SSE 接入。
- 交付：pytest、Docker 和环境变量。

模型、SDK 和服务端行为可能变化。学习时应以课程锁定依赖与官方文档为准，不把示例中的模型名称、价格或额度当作永久事实。
