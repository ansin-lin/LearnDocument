# 第 34 章 Agent 基础

> 本章成果：区分普通 Chat、RAG、Tool Calling、固定 Workflow 和 Agent，并为业务场景选择最小方案。

Chat 生成回复；RAG 补充知识；Tool Calling 允许模型请求程序功能；Workflow 由程序预先规定步骤；Agent 让模型在边界内动态选择下一步。Agent 不是独立产品名，也不等于自动拥有工具和权限。

## 1. 五种方案的控制权

普通代码由程序决定全部步骤；Chat 只产生内容；RAG 增加检索；Tool Calling 允许模型选择某个函数；Agent 可根据结果多轮选择。自主性越高，测试、成本、权限和停止控制越重要。

## 2. Agent 的基本组成

包括目标、当前状态、模型、工具、执行循环、记忆、停止条件和人工介入点。宿主负责真正执行和安全边界，模型只做受限决策。

固定、可预测、强合规流程优先普通代码或 Workflow。只有步骤确实依赖中间结果、难以预先列举，而且错误可控时才考虑 Agent。

## 3. 选择判断

先问步骤能否预先写清、是否需要外部动作、错误影响、能否评价、是否有预算与人工兜底。固定月报和密码重置通常用 Workflow；开放式障害调查才可能受益于 Agent。

## 4. 常见误解

Agent 不是“更聪明的聊天框”，也不是给模型全部工具后让它自行负责。它仍是由程序管理状态、权限、执行、预算和停止条件的受控系统。

## 5. 普通 Chat、Workflow 与 Agent 的区别

普通 Chat 主要生成一次回答；固定 Workflow 按程序预先写好的步骤执行；Agent 则由模型根据当前状态在允许的动作中选择下一步。Agent 的灵活性更高，但路径更难预测，因此需要更严格的权限、停止条件和审计。

能用固定规则稳定完成的流程，优先使用 Workflow。例如“创建工单后发送固定通知”不需要 Agent；“根据多种证据选择调查工具，并在资料不足时询问用户”才可能需要动态决策。

## 6. Agent 的五个组成部分

1. **目标**：完成什么业务结果；
2. **状态**：当前已知事实、步骤和剩余任务；
3. **工具**：允许读取或修改哪些外部系统；
4. **策略**：模型如何选择下一步；
5. **护栏与停止条件**：什么必须拒绝、确认或结束。

“给模型一段长 Prompt”并不自动形成可靠 Agent。程序必须管理状态、执行工具和限制循环。

## 7. 决定是否使用 Agent 的问题

先问：步骤能否预先确定？错误代价多大？是否涉及外部写操作？每一步能否验证？人工确认是否可接受？如果目标含糊、工具权限过大且结果无法检查，就不适合直接自动化。

本章练习要求把工单处理分别设计成“单次 LLM”“固定 Workflow”“Agent”三版，并说明控制权、成本、失败方式和适用边界。

Agent 不必然比单次调用准确；多轮可能累积错误；提供工具不等于提供权限；“自主”不表示可以无限运行。

实践：为“密码重置”“复杂障害调查”“月末固定报表”选择方案，比较正确性、可测试性、权限、成本和维护难度。
