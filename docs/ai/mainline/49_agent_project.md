# 第 49 章 综合项目⑤：Agent 自动业务处理

> 项目成果：让 Agent 调查工单、检索手册并提出状态更新；只有授权用户确认后才执行写入。

Agent 可用 `get_ticket`、`search_knowledge` 和 `update_ticket_status`。最后一个工具要求当前用户权限、允许的状态迁移、`expected_version`、一次性 `confirmation_id` 和幂等键。

## 开始状态和目标

前四个项目的 Chat、RAG、结构化校验、权限和日志已通过验收。Agent 的目标限定为“调查指定工单并提出下一步”，不能自行扩大到批量处理或其他用户资源。

## 执行流程

1. 读取目标与当前登录用户，建立运行 ID 和预算。
2. 查询工单并检查归属；需要时检索有权手册。
3. 生成带证据的处理建议和拟执行动作。
4. 写操作进入 `WAITING_CONFIRMATION`，展示参数和影响。
5. 用户确认后，服务端重新检查权限、状态、版本和确认 ID。
6. 执行一次写入，记录结果并返回完成状态。

## 停止条件

达到最大步骤、工具次数、总时间、费用、连续错误或重复调用时停止。资料不足时请求最小信息；用户取消后禁止继续写入。重启恢复时从持久化状态判断已完成步骤。

## 必须验收

- 正常任务在步骤和预算上限内完成。
- 越权、非法状态、伪造确认和重复提交均被业务服务拒绝。
- 工具超时和部分失败不会导致未知状态写入。
- 每一步输入、工具、结果、确认和最终状态可审计。
- Agent 达到上限时停止并交还人工，不隐瞒未完成操作。

在隔离数据库执行写入测试并验证事务回滚。不得连接生产系统进行课程演示。

## 故障演练

制造工具超时、恶意结果、重复调用、越权编号、审批过期和服务重启，确认任务安全停止或从检查点恢复，并且没有重复副作用。

## 自动化范围

选择一个边界清晰的流程，例如“读取待处理工单，收集诊断信息，生成处理建议，经人工确认后更新状态”。首版不允许 Agent 自由访问数据库、任意 URL 或生产文件，也不自动关闭高风险工单。

## 状态与步骤

任务状态至少包含 `CREATED`、`COLLECTING`、`WAITING_APPROVAL`、`EXECUTING`、`COMPLETED`、`FAILED` 和 `CANCELLED`。每个转换有进入条件、允许工具、超时和恢复方式。聊天文字只能作为上下文，正式状态由程序保存。

## 分步成果

1. 用固定 Workflow 跑通流程并明确每步输入输出；
2. 把需要动态选择的调查步骤交给 Agent；
3. 为每个工具增加 Schema、权限、超时和结构化错误；
4. 加入最大轮数、预算、重复调用检测和人工确认；
5. 实现持久化检查点、幂等写入和中断恢复；
6. 用任务集比较自动化前后的成功率、耗时与人工介入。

## 风险验收

故意让工具超时、返回恶意指令、重复同一调用、提供越权工单、审批后修改参数、执行中重启服务。系统必须停止或恢复到可解释状态，不产生重复副作用。交付物包括状态图、工具契约、威胁模型、逐步 Trace、费用报告和人工接管说明。

覆盖查询成功后模型失败、确认过期、并发版本冲突、工具超时但实际已写入、重复回调和日志服务失败。重点验证不会产生重复或未知状态，而不是只看最终回复。
