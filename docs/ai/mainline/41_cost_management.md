# 第 41 章 AI 成本管理

> 本章成果：根据真实 Token、请求量和附加资源估算费用，并设置预算和降级策略。

费用可能来自输入、输出、缓存、Embedding、向量存储、工具和基础设施。价格会变化，应从供应商当前官方页面读取，不把讲义中的数字当常量。

## 1. 成本组成

区分模型输入/输出、推理模式、Embedding、文件检索、存储、网络和应用基础设施。失败与重试也会产生费用。以实际 usage 和账单口径为准。

```text
月费用估算 = 日请求数 × 工作日 × 单请求平均费用
```

单请求平均费用必须来自代表性测试，不只取一次短 Prompt。按业务功能记录输入/输出 Token、模型、缓存命中、延迟和失败重试。优化顺序通常是减少无关上下文、限制输出、选择合适模型、缓存稳定内容，再考虑更复杂架构。

## 2. 预算分层

设置单请求输出上限、Agent 工具/步骤上限、单用户日限额、功能月预算和组织告警。超过阈值时可拒绝、排队、切换已评估方案或转人工，不能静默降低到未验证模型。

## 3. 优化原则

先删除重复指令和无关历史，减少不必要工具调用；再比较模型、缓存、批量和检索参数。任何降本都要重跑评估，质量或安全退化不能算优化。

## 4. 成本报告

报告按功能、模型、租户和成功状态展示请求数、Token、外部工具费用和单位业务成本，并与预算和质量指标一起看。只有总金额无法定位浪费。

## 5. 一次请求的成本从哪里来

不只计算输入和输出 Token。完整成本还包括 Embedding、重排、工具 API、数据库和网络、失败重试、日志存储以及人工复核。长历史反复发送、过大的 RAG Context 和无上限 Agent 循环，都会让单个业务动作被放大成多次模型调用。

## 6. 建立业务单位成本

“本月花了多少钱”不能指导优化。应按功能、租户、模型和结果状态统计，并换算为每次有效摘要、每个已解决工单或每百次检索的成本。失败请求也要计入，因为它们同样消耗资源。

预算可分为单次请求上限、用户或租户日限额、功能月预算和全系统告警线。达到限制时使用更小模型、减少非必要上下文、排队或关闭低优先级功能，但不能悄悄降低关键业务正确性。

## 7. 优化顺序

先删除无价值调用和重复上下文，再缩短输入输出，然后基于评估结果选择更经济的模型，最后考虑对确定性结果做缓存。缓存键应包含任务输入、Prompt 版本、模型、权限范围和资料版本；不同用户权限的数据不能共享错误缓存。

## 8. 成本变化也要回归测试

每项优化同时比较质量、延迟和成本。例如把 Top-K 从 8 改为 3 可能省 Token，却降低召回。报告应包含基线、变更、评估集结果、节省比例和退化样本，不能只展示费用下降。

按功能、环境、模型和版本统计请求数、成功率、P50/P95 Token、重试和费用。平均值可能隐藏少量超长请求，因此要观察分布。

实践：用固定评估集计算 P50/P95 Token 与成本，模拟请求量增长三倍，设置单请求、单用户和月度预算阈值及超限后的明确行为。
