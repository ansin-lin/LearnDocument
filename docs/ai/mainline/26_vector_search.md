# 第 26 章 Vector Search

> 本章成果：实现 Cosine Similarity 与 Top-K 检索，并用命中率判断结果，而不是凭分数大小猜质量。

余弦相似度比较向量方向。Top-K 表示取分数最高的 K 个候选，不保证其中存在正确答案。阈值也不是跨模型、跨数据集通用常数，需要评估数据决定。

## 1. 距离与排序

余弦相似度关注方向，点积和欧氏距离也可用于向量检索，但数据库操作符和排序方向不同。必须按所用索引、模型建议和数据库文档核对，不能把“分数越大越相似”推广到所有距离字段。

## 2. Top-K、阈值与过滤

K 太小可能漏掉正确片段，太大增加噪声、Token 和延迟。阈值用于拒绝低相关结果，但应从标注问题集估计。权限、部门、版本等元数据应在可信检索层过滤，而不是交给模型事后删除。

## 3. 召回和精度

Recall@K 衡量标注相关块是否进入前 K；Precision@K 关注返回中有多少相关。RAG 常先保证合理召回，再用重排和上下文构造降低噪声。最终回答正确不能反推每次检索都正确。

## 4. 混合检索

向量检索擅长语义近似，关键词检索擅长编号、专有名词和精确短语。混合检索合并两类候选并统一重排，能减少只依赖一种方法的盲点。

## 5. Cosine Similarity 应怎样理解

余弦相似度比较两个向量方向是否接近，常用于语义排序。分数只在同一模型、同一处理流程和同一数据集上有可比意义，不能把 `0.8` 当作跨项目通用的“80% 正确”。阈值必须用本项目评估集确定。

## 6. Top-K 和阈值解决不同问题

Top-K 限制最多返回多少项；阈值拒绝过于不相关的项。K 太小可能漏掉正确文档，太大则把噪声塞进上下文并增加费用。合理流程通常是先做权限与 Metadata 过滤，再召回候选，必要时重排，最后选择进入 Context 的片段。

查询“VPN 无法连接”时，若 Top-1 是旧版手册、Top-2 才是当前手册，只调大 K 不能解决版本优先级，需要版本过滤或重排规则。

## 7. 召回率与精确率

- **召回率**关心应该找到的相关内容有多少被找到了；
- **精确率**关心找出的内容中有多少真正相关。

客服辅助通常不能漏掉关键流程，所以先保证合理召回，再通过过滤与重排减少噪声。评估时需要标注每个问题对应的相关文档，不能仅凭最终回答好不好反推检索。

## 8. 检索结果的验收

每条结果至少展示文档编号、标题、片段、来源位置、版本、相似度或排序分数以及权限范围。用同义词、精确编号、否定问题、旧版本、无答案和越权文档六类查询测试。若结果错误，要能区分是 Embedding、过滤、索引数据、K 值还是重排造成的。

编号、错误码和专有名词适合关键词检索，自然语言改写适合向量检索。混合检索组合两类信号，但增加参数和评价复杂度，应在向量基线不足时再引入。

检索流程：查询预处理 → 使用同一 embedding 模型生成向量 → 相似度排序 → 元数据与权限过滤 → 返回文本和来源。生产实现通常由向量数据库完成排序。

实践：准备 15 个文档块和 10 个问题，人工标注每题应命中的块。分别测试 K=1、3、5，记录 Recall@K、无关结果数量和耗时。不能只用模型最终回答判断检索好坏。
