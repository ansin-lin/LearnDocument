# 第 46 章 综合项目②：企业知识库 RAG

> 项目成果：在同一工程中交付带来源、拒答和权限过滤的企业知识库问答。

导入项目规格中的三份虚构手册，保留版本、部门、角色和段落定位。接口返回回答、引用和证据不足标志；页面可以打开对应来源。

## 开始状态

第 45 章 Chat 功能稳定，PostgreSQL 测试环境与 pgvector 已准备，三份虚构手册拥有固定 ID、版本、角色和人工标注问题。真实内部资料不进入练习。

## 实现步骤

1. 校验并解析文件，按结构切分，保存来源定位。
2. 批量生成 Embedding，以导入批次控制可见状态。
3. 实现权限过滤、Top-K 检索和空结果。
4. 构造带引用 ID 的 Context，生成回答并验证引用。
5. 在 Chat 页面显示来源、版本和证据不足状态。
6. 建立检索、生成、安全和性能四类评估。

## 评价方法

先计算 Recall@K，再检查引用是否支持每个声明。开发集用于调整 Chunk 与 K，独立评估集决定发布。无答案、冲突文档和无权限问题必须单独统计。

## 必须验收

- 固定问题集的 Recall@K 和声明支持率达到预设门槛。
- 无答案问题明确拒答。
- user-a 无法检索 user-b 或无权部门内容。
- 注入文本不能改变系统权限或触发工具。
- 文档更新、撤回和索引回退均有实际演练。

提交检索评估与生成评估两份结果，不能只展示最终聊天截图。

## 更新与恢复

文档更新使用新索引版本，验证后切换；失败时保留旧版本继续服务。删除文档要同步处理原文、Chunk、向量、缓存和派生结果。

## 项目边界

知识库只回答已批准文档中的内容，展示来源和版本；没有依据时拒答。第一版不追求支持所有文件类型，可先限定文本型 PDF 或准备好的 Markdown，以便把重点放在解析质量、检索、引用和权限上。

## 分步成果

1. 定义文档、Chunk、版本和权限数据；
2. 完成一份文档的解析、切块、向量化和可重复入库；
3. 实现有权限过滤的 Top-K 检索并显示原文片段；
4. 构造带来源编号的 Context，生成带引用回答；
5. 处理无答案、冲突版本和文档更新；
6. 建立固定问题集，评价检索与回答两层。

## 调试要求

页面或诊断接口应在授权条件下展示：查询改写、Metadata 过滤、候选结果、最终 Context、答案引用和索引版本。答案错误时，学员必须先判断正确片段是否被召回，不能直接修改 Prompt 碰运气。

## 最终验收证据

至少准备正常问法、同义问法、精确编号、无答案、旧版本、跨片段和越权七类问题。提交索引任务报告、抽样解析对照、Recall@K、引用正确率、拒答结果、权限测试、更新切换与回退记录，并说明当前不支持的文档类型和风险。

导入新版本但不立即替换；验证后切换当前版本。模拟解析失败和错误索引，确认可继续使用旧版。撤回文档时清理原文件、块、向量和缓存，并记录审计。
