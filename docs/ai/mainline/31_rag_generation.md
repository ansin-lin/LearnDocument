# 第 31 章 RAG 回答生成

> 本章成果：基于检索片段生成带引用的回答，并在证据不足时明确拒答。

Prompt 应明确：只使用提供的资料；每个事实附来源；资料冲突时说明冲突；没有足够证据时返回 `insufficient_evidence=true`。不能把“请勿幻觉”当作唯一保护。

## 1. Context 的格式

每个块包含服务端分配的引用 ID、文档名、版本、位置和正文。系统指令与文档正文使用明确边界。模型只返回引用 ID，应用再映射可展示来源，防止伪造 URL。

## 2. 回答策略

先判断材料能否支持问题，再生成简洁答案。部分有依据时区分已确认和未知；多个版本冲突时列出冲突而非自行融合。拒答应说明缺少哪类资料，并避免泄露无权限文档是否存在。

回答后的程序检查引用 ID 是否真实存在于本次检索结果，引用片段是否对当前用户可见。模型生成的不存在文档号必须拒绝或降级，不能直接展示为来源。

## 3. 声明级核对

将回答拆成可验证声明，逐条判断引用是否真正支持。引用存在、主题相关但没有证明具体数字，仍属于不支持。自动检查用于初筛，关键答案保留人工抽查。

## 4. 失败类型

区分“没有检索到正确资料”“正确资料未进入 Context”“模型忽略资料”“引用不支持结论”和“资料本身错误”。不同失败应由不同环节修复。

## 5. Prompt 中各部分的职责

生成阶段的指令应明确：只能依据提供的 Context、资料不足时必须说明、引用格式、回答语言和输出结构。用户问题与检索资料分别包裹，不能把资料中出现的“忽略上述规则”当作系统指令执行。

Context 片段使用稳定来源编号，例如 `[DOC-12#p3]`。模型输出引用后，程序还要检查编号确实存在于本次 Context 中，防止生成不存在的来源。

## 6. 忠实性、完整性和可读性

- **忠实性**：回答中的事实能在资料中找到依据；
- **完整性**：问题要求的关键部分没有遗漏；
- **可读性**：表达清楚，适合目标读者。

三者不能混为一个“感觉不错”的分数。回答流畅但引用不支持结论，忠实性仍然失败；逐字复制全部资料可能忠实，却不完整回答问题或难以阅读。

## 7. 无答案与冲突资料

若资料不足，应指出缺少什么，而不是补充模型常识。若两个有效片段相互冲突，应展示冲突的来源、版本和日期，并请求确认或按已定义的版本优先规则处理。模型不能自行决定哪份公司制度有效。

## 8. 声明级核对方法

把回答拆成能独立验证的声明，为每条声明标注支持它的来源。程序可先检查引用编号，人工或评估器再判断“该片段是否真的支持声明”。数字、期限、权限和否定结论应优先检查。

练习要求为同一问题准备“正确资料”“缺少关键资料”“互相冲突资料”三组 Context，观察回答并提交逐条核对表。

区分无检索结果、上下文过长、模型拒绝、生成截断、引用非法和声明无支持。不同失败对应不同修复，不应一律增加 Prompt 长度。

实践：测试有直接依据、只有部分依据、互相冲突、没有依据和无权限五类问题。人工标注每个关键声明能否被引用支持，并记录拒答是否恰当。
