# 第 45 章 综合项目①：AI Chat System

> 项目成果：在 ServiceDesk AI 中交付一个可取消、可追踪、能处理错误的客服对话功能。

## 实现范围

复用第 17～22 章已有工程，实现会话创建、发送消息、历史读取、流式显示、取消和删除。回答业务事实时调用只读工单工具，不允许模型凭历史猜状态。

## 开始状态

FastAPI 工单 API、认证、Fake LLMClient 和 React 基础页面已经可运行，原有测试通过。先保存基线提交、启动命令和测试结果；本项目不修改工单表的核心业务规则。

## 实现步骤

1. 定义会话、消息、完成状态和错误契约。
2. 实现会话归属、历史读取、长度限制与删除。
3. 接入普通生成，再增加 SSE；完成后才持久化助手消息。
4. 业务事实通过 `get_ticket` 查询，保留工具证据。
5. 页面处理加载、空内容、完成、失败、取消和重试。
6. 加入 trace、Token、超时和错误指标。

## 测试设计

自动测试使用 Fake Client，覆盖串话、重复提交、历史上限、首事件失败、中途断流和取消。真实模型只用虚构数据完成少量质量评价，并设置费用上限。

## 必须验收

- 两个用户的会话严格隔离。
- 历史达到上限时按设计截断或摘要。
- 正常、超时、限流、取消和流中断都有明确 UI 状态。
- 前端和日志不出现 API Key。
- 每次请求可关联模型用量和 `trace_id`。

提交代码、接口说明、自动测试、5 条真实模型评估结果和已知限制。真实模型不可用时可用替身完成工程测试，但必须明确未完成外部质量验证。

## 故障演练与交付

演练模型超时、流式中断、并发发送、服务重启和数据库保存失败。交付运行说明、状态图、测试证据、Trace 与已知限制，使其他学员可以独立复现。

## 关键设计说明

本项目的 Chat 是一个受控业务界面，不是无限制聊天机器人。服务端保存可信历史，浏览器只发送本轮消息；AI Service 隔离供应商接口；消息状态至少区分等待、流式生成、完成、失败和取消。对话涉及的工单事实仍从业务数据库读取，不能只相信历史文本。

## 分步成果

1. **单轮版本**：提交一条消息并返回非流式结果，完成认证、输入长度和错误映射；
2. **持久化版本**：保存会话和消息，刷新后可恢复且不能访问他人会话；
3. **多轮版本**：服务端构造受控历史，长会话有裁剪策略；
4. **流式版本**：显示增量、完成、断线与取消状态；
5. **运营版本**：记录模型版本、Token、延迟和追踪编号。

每一步完成后保留可运行状态和测试，不要一次生成全部代码再统一排错。

## 新人容易遗漏的情况

重复点击发送会产生两条消息；第二个请求可能先返回；流式中断会留下半个答案；模型拒绝或返回空内容不应保存为正常完成；浏览器伪造 assistant 消息不能进入可信历史；服务端重启后正在生成的消息要转为可解释状态。
