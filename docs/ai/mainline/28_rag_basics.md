# 第 28 章 RAG 基础

> 本章成果：解释 RAG 为什么存在，并把“检索错”和“生成错”分开定位。

RAG（Retrieval-Augmented Generation）先从外部知识库检索相关内容，再将内容作为上下文交给模型生成回答。它用于补充内部、最新或可引用资料，不会自动消除幻觉。

## 1. 为什么需要 RAG

模型训练知识不包含全部内部资料，也难以随着制度更新立即变化。RAG 允许应用在运行时选择当前、获准、可定位的片段。与把整份文档放入 Prompt 相比，检索可以降低无关内容，但会引入切分和召回问题。

```text
问题 → 查询处理 → 权限过滤与检索 → 候选片段
     → Context 构造 → 模型回答 → 引用校验 → 用户
```

若正确片段没有进入 Top-K，属于检索问题；片段正确但回答曲解内容，属于生成问题；文档本身过期，属于知识治理问题。评价必须分层。

## 2. RAG 不是什么

RAG 不是重新训练模型，不保证每个问题有答案，也不能自动解决权限和数据质量。知识库有错误时，回答可能有证据却仍然业务错误。因此要管理权威来源、版本和负责人。

## 3. 四个验收层

文档处理检查文本是否正确；检索检查相关块是否命中；生成检查声明是否被上下文支持；业务检查答案是否可用且权限正确。每层保存独立输入输出，才能定位失败。

## 4. 最小闭环

最小闭环是“文档切块并入库 → 问题检索 → 将片段加入 Context → 基于片段回答 → 显示来源”。每一步保存可观察结果，才能定位错误来自检索还是生成。

## 5. RAG 的两条独立链路

**离线索引链路**负责读取文档、解析、清洗、切块、生成向量并保存；**在线回答链路**负责接收问题、校验身份、检索有权限的片段、构造 Context、生成回答和附上引用。文档更新影响索引链路，用户提问走在线链路。

如果把二者混在一个请求中，每次提问都重新解析全部文档，系统会又慢又贵，也难以定位错误。

## 6. 为什么需要 RAG

模型训练知识可能没有企业内部资料，也可能不是最新版本。RAG 在请求时把可控资料提供给模型，使回答能够基于当前文档并给出来源。它适合知识经常更新、需要权限控制或必须引用依据的场景。

RAG 不是让模型“真正记住”文档，也不保证一定正确。检索可能漏掉资料，资料本身可能过期，模型也可能错误解释。因此仍需拒答策略、引用核对和评估。

## 7. 一次失败可能在哪一层

问题可能来自解析丢字、Chunk 切错、Embedding 表示不佳、权限过滤过严、检索排序错误、Context 被截断，或模型没有遵守资料。调试时先看正确片段是否进入候选，再看是否进入最终 Context，最后看回答是否忠实。

## 8. 最小项目验收

使用三份短文档构建索引，准备有唯一答案、跨片段答案、无答案、旧版本和无权限五类问题。页面必须显示答案和来源；无依据时明确拒答；更新文档后能确认新版本生效。学员要保存每一步的输入输出，能够指出错误发生在哪一层。

先用三份短文档和人工标注问题完成“切分—检索—上下文—回答—引用”，不要一开始加入 OCR、重排、多查询和 Agent。基线稳定后再逐项优化。

实践：为五个失败回答判断失败层，并写出下一步证据。验收要求：不能把所有问题都归因于 Prompt，也不能用 RAG 绕过文档权限。
