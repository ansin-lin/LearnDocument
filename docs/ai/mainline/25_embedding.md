# 第 25 章 Embedding

> 本章成果：把文本转换为向量，使用固定样例观察语义相似度，并说明其限制。

Embedding 将文本映射为数值向量，常用于检索、聚类和相似匹配。向量维度和计算方式由模型决定；不同模型生成的向量不能未经验证混在同一索引中。

## 1. 从关键词到语义表示

关键词检索依赖字面匹配；Embedding 试图把整体含义映射到向量空间，因此“无法登录”和“账号进不去”可能接近。向量中的单个数字通常没有可直接命名的业务含义，重点是整体距离关系。

## 2. 输入怎样影响向量

大小写、空白、模板前缀、语言、切分和模型版本都会影响结果。入库文档和查询必须使用兼容模型及一致预处理。更换模型或维度时建立新索引并重新生成，记录 `embedding_model` 和版本。

## 3. 相似不等于正确

高相似只说明在当前表示和度量下接近，不代表文档最新、有权限或支持最终答案。权限过滤、版本选择和事实验证由检索与业务层完成。

## 4. 批量与成本

对文档分批生成向量，限制单批大小并记录成功、失败和模型版本。只处理新增或内容哈希变化的 Chunk，避免每次更新都重算全部文档。

## 5. 向量到底表示什么

Embedding 模型把文本映射为一组数值。语义或用法相近的文本通常在向量空间中更接近，因此“无法登录系统”和“账号认证失败”即使关键词不同，也可能被检索到一起。单个维度通常不能解释为某个固定主题，不能把向量当作人工设计的标签表。

向量只反映模型从输入中编码出的相似性，不会自动验证事实、时间和权限。“怎样重置密码”和“不要重置任何密码”可能共享很多语义特征，因此检索后仍要由业务规则和生成阶段判断。

## 6. 文本怎样准备

索引文档与查询必须使用兼容的 Embedding 模型和相同的预处理约定。保留能区分含义的标题、产品名和章节路径；去掉重复页眉页脚和无意义空白；不要把互不相关的多段内容强行合成一个向量。

对于工单知识库，可将“标题 + 适用系统 + 正文片段”作为嵌入文本，同时把部门、权限、版本和原文位置保存为普通 Metadata。

## 7. 模型变更意味着重建索引

不同模型生成的向量空间和维度可能不同。升级 Embedding 模型时，不能把新查询向量与旧文档向量直接混用。应记录模型标识与处理版本，建立新索引，离线评估后切换，并保留回滚路径。

## 8. 最小验证实验

准备五组同义问法、五组容易混淆的反例和五组业务专有词，比较相似度排序。不要只看一个“看起来成功”的查询。记录输入文本、模型版本、前 K 个结果和人工相关性判断，为下一章向量检索提供基线。

文档入库可分批生成并记录失败项；不要失败后静默留下半套索引。对输入长度、批量大小、速率限制和费用设置边界，并避免重复计算未变化内容。

语义相近不代表业务等价。例如“重置本人密码”和“重置管理员密码”可能语义接近，但权限完全不同。Embedding 不能承担授权、真假判断或最终匹配决策。

实践：为登录、报表、权限三组短句生成向量，比较同类、近义但权限不同、完全无关文本的相似度。记录模型、预处理和样例，避免只展示一个成功结果。

验收：能够解释相似度只是排序信号，并指出至少一个高相似但不应返回的业务例子。
