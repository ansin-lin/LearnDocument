# 第 47 章 综合项目③：AI 文档分析系统

> 项目成果：上传虚构需求文档，提取结构化需求、疑问和证据位置，并由人工确认后保存。

处理链：文件校验 → 文本解析 → 分段 → 结构化提取 → Schema 校验 → 证据定位 → 人工确认 → 保存。扫描件解析失败、超长文档和不支持格式必须明确返回。

## 开始状态与输出

复用第 46 章的安全文件处理与来源定位。新增 `RequirementExtraction`，包含功能、参与者、输入输出、业务规则、异常、QA 和每项证据位置。提取结果处于 `DRAFT`，未经确认不得成为正式规格。

## 实现步骤

1. 校验类型、大小、权限并创建处理任务。
2. 解析文本并输出质量报告，异常页进入人工检查。
3. 按章节分批提取，再合并重复项和冲突。
4. 执行 Schema、证据和业务校验。
5. 页面并排显示原文、提取结果和引用位置。
6. 由授权人员修订、确认并生成版本。

## 失败处理

区分上传失败、解析失败、部分页面失败、模型拒绝、输出截断、引用不存在和保存冲突。允许从安全检查点重试，不重复创建正式版本。

## 必须验收

- 每个提取字段能定位原文；无依据内容不得自动保存。
- 文档中的注入指令只作为正文。
- 文件类型、大小、权限和恶意内容有服务端检查。
- 修改确认后的结果保留操作者和版本。
- 固定样例计算字段准确率和证据正确率。

删除测试要同时覆盖原文件、派生文本、向量、缓存和访问日志中的合规保留边界。

## 交付证据

交付文件契约、处理状态、结果 Schema、人工确认记录、评估集和删除报告。抽查未被提取的原文，防止只评价模型已经输出的部分。

## 结构化分析目标

系统接收需求书或设计书，提取文档基本信息、功能列表、角色、业务规则、异常条件、数据项和疑问点。每个结论保留原文位置与证据，不能只输出一篇无法追溯的总结。

## 分步成果

1. 限制文件类型、大小并完成安全上传；
2. 解析正文、标题、表格和页码，标记 OCR 或失败状态；
3. 定义分析结果 Schema 和字段解释；
4. 分段分析后合并，处理重复和冲突；
5. 验证引用位置，导出可复核的分析报告；
6. 对失败文件支持重试、删除和审计。

## 新人需要理解的难点

长文档不能简单截取开头；表格拆散会改变字段关系；分段分别分析可能遗漏跨章节规则；多个片段对同一字段给出不同值时不能静默覆盖；模型提出的疑问不等于原文缺陷，需要人工确认。

## 评价方法

准备人工标注的字段和疑问点，分别计算字段提取准确性、关键规则召回、引用有效率和无依据结论数。对数字、日期、否定、权限和状态转换做重点抽查。最终交付包含失败样本及原因，不只展示成功报告。

提交文件契约、处理状态图、结构化 Schema、人工确认记录、固定评估集和删除报告。随机抽查未被提取的段落，防止只评价模型已经输出的内容。

## 最终验收

另一名学员应能上传合法文件、看到每个处理阶段、对照原文确认结果、修正待确认字段、导出带来源报告并删除全部派生数据。对超大文件、损坏文件、扫描件和含恶意指令的文档，系统必须给出受控结果，不能卡死或执行文档中的命令。
