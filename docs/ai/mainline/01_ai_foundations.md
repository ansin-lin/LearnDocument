# 第 1 章 AI 基础认识

> 本章成果：能够区分 AI、机器学习、深度学习、生成式 AI 和 LLM，说明“模型、AI 产品、Agent”不是同一个东西，并为常见业务问题选择合适的实现方式。

## 1. 先从普通程序开始理解

普通程序通常由开发者写出明确规则。例如计算加班费时，程序读取工时、判断是否超过标准时间，再按确定公式计算。只要输入、规则和程序版本相同，结果就应相同。

AI 系统处理的是过去很难完全写成固定规则的任务，例如识别图片、理解自然语言、预测风险或生成文本。AI 不是“会思考的人”，也不是某一个产品名称，而是一类让计算机表现出感知、预测、决策或生成能力的技术与系统。

## 2. 五个核心概念

### 2.1 人工智能（AI）

AI 是范围最大的概念。它既包括人工编写规则的专家系统，也包括从数据中学习的模型。地图寻路、垃圾邮件识别、语音识别和工单摘要都可能属于 AI 应用，但实现方法不同。

### 2.2 机器学习（ML）

机器学习是实现 AI 的一种方法。开发者不逐条写出“满足什么条件就是垃圾邮件”，而是准备带标签的数据，让算法学习输入特征与结果之间的关系。训练完成后得到模型，再用新数据做预测。

典型任务包括分类、回归、聚类和异常检测。机器学习不等于生成式 AI：预测客户是否流失通常是机器学习，但不需要生成一段文章。

### 2.3 深度学习（DL）

深度学习是机器学习的一类方法，核心是多层神经网络。它能从大量数据中学习复杂表示，广泛用于图像、语音和自然语言任务。这里的“深”主要指网络层次，不代表模型一定更正确或更懂业务。

### 2.4 生成式 AI

生成式 AI 按输入生成新的内容，例如文本、代码、图片、音频或视频。它描述的是应用能力，不是单一算法。因此文本生成模型和图像生成模型都属于生成式 AI，但图像模型不一定是 LLM。

### 2.5 大语言模型（LLM）

LLM 是面向语言理解和生成的大规模模型。它可以续写、摘要、翻译、分类、提取信息和生成代码。LLM 输出的是根据当前输入和模型参数生成的结果，不是从业务数据库中自动查出的事实。

```text
人工智能 AI
├─ 人工规则系统
└─ 机器学习 ML
   └─ 深度学习 DL
      └─ 许多现代 LLM

生成式 AI：从“是否生成新内容”描述系统，和上面的技术层级不是同一分类角度。
```

## 3. 模型、AI 产品与 Agent

| 对象 | 是什么 | 工单场景中的职责 |
| --- | --- | --- |
| 模型 | 接收输入并产生预测或生成结果的核心能力 | 根据文字生成分类建议 |
| AI 产品 | 把模型、界面、账号、数据和功能组合起来的软件 | 在聊天页面上传文档并提问 |
| Agent | 在宿主允许范围内，根据中间结果选择下一步或工具 | 先查工单，再检索手册，最后提出建议 |

同一个模型可以被多个产品使用。产品的文件读取和按钮不是模型天然拥有的能力；Agent 能否修改数据取决于宿主实际提供的工具和权限。

## 4. 训练和使用模型不是一回事

训练是用大量数据调整模型参数的过程，通常需要专门的数据、计算资源和评估。推理是把新输入交给已经训练好的模型并得到输出。日常聊天、调用 API、编写 Prompt 和提供项目规则通常属于推理，不是在重新训练模型。

RAG 是在推理时检索外部资料并提供给模型；微调会用准备好的样例进一步调整模型行为。两者目的、成本和数据处理方式不同。

## 5. 确定性与概率性

权限判断、金额计算、库存扣减和状态流转需要确定性。LLM 生成具有概率性：输入、模型版本或采样配置变化，都可能影响结果。

```text
用户自然语言
→ LLM 理解意图、提取候选字段
→ 程序校验类型、范围和权限
→ 数据库执行确定性查询或事务
→ LLM 将可信结果整理成自然语言
```

## 6. 怎样判断要不要使用 LLM

依次回答：输入是否主要是非结构化内容；是否已有简单稳定的规则；错误会造成什么影响；是否允许人工确认；能否准备代表性样例评价；模型效果是否值得延迟、费用和维护成本。

| 场景 | 推荐方案 | 判断依据 |
| --- | --- | --- |
| 按公式计算加班费 | 普通程序 | 规则确定，结果必须精确 |
| 从邮件提取问题类型 | LLM + Schema 校验 | 表达多样，输出字段明确 |
| 根据历史数据预测流失 | 传统机器学习 | 有标签数据和预测目标 |
| 查询本人剩余假期 | 普通 API/SQL | 数据库已有权威结果 |
| 用自然语言查询假期 | LLM + 受控工具 | 模型理解意图，程序负责权限和查询 |

## 7. 完整案例：智能工单分类

用户输入：“昨天升级后一直进不去员工门户，重置密码也没用。”LLM 可以建议 `ACCOUNT` 类别、生成摘要并指出缺少账号和错误信息。但它不能确认用户身份、读取真实日志或决定最高优先级，除非系统提供相应数据和规则。

核对时检查：分类是否来自允许枚举；摘要是否忠实原文；缺失信息是否真的缺失；优先级是否有 SLA 依据；结果是否经过人工确认。这样才能区分“语言处理得不错”和“业务决定正确”。

## 8. 练习与参考判断

为以下任务选择普通程序、机器学习、LLM 或组合方案，并写出模型职责、程序职责、错误风险和验证方法：自动计算报销金额；识别发票图片；总结障碍日志；查询工单状态；预测下月工单量。

参考判断：报销金额由规则程序计算；图片识别可用视觉模型并由程序校验字段；日志摘要可由 LLM 辅助但要链接原日志；状态查询由 API/SQL 返回事实；工单量预测更接近时间序列或机器学习。答案可以不同，但必须说明输入特征、正确性要求和核对证据。

## 9. 新人核对卡

看到一个 AI 功能时，先问四件事：输入是什么，输出是事实、预测还是生成内容，错误后果是什么，谁来验证。能生成流畅文字不代表具备业务权限；能调用工具不代表模型自己完成了数据库操作；接入 LLM API 也不等于训练了一个新模型。

本章达标表现：学员能用自己的话画出 AI、ML、DL、生成式 AI 与 LLM 的包含和区别，并能为一个真实需求选择规则、传统模型、LLM 或组合方案，而不是对所有问题都回答“用大模型”。
