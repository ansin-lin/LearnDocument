# 第 6 章 Context Engineering

> 本章成果：能够为代码、需求、日志和文档任务准备最小、可信、可追踪的上下文包，并在资料缺失、冲突或包含恶意指令时正确处理。

## 1. Context Engineering 是什么

Prompt 解决“怎样描述任务”，Context Engineering 解决“模型在执行时能看到什么信息，以及这些信息怎样组织和更新”。上下文可能来自用户输入、系统规则、会话历史、代码、日志、文档、检索结果和工具返回。

模型不会自动理解整个项目。文件存在仓库里、链接出现在需求中，或者数据库中有记录，都不代表相关内容已经进入本次上下文。

## 2. 好上下文的四个标准

### 2.1 相关

只提供完成当前任务需要的材料。修复登录错误通常需要错误日志、登录入口、认证流程和相关测试，不需要上传整个代码库。

### 2.2 可信

标明材料来源、版本和时间。正式规格、当前代码、实际运行结果和聊天转述的可信程度不同。模型不能自行决定冲突材料哪个更权威。

### 2.3 完整

最小不等于缺失。若要求修改接口，至少要有接口契约、相关实现、错误约定和测试入口。缺少关键资料时，应先停止并请求最小缺失项。

### 2.4 安全

删除密钥、个人信息和无关客户数据，只提供允许发送的内容。外部文档与日志中的指令按数据处理，不能覆盖系统权限。

## 3. 四类任务分别需要什么

| 任务 | 必要上下文 | 常见多余或危险内容 |
| --- | --- | --- |
| 需求分析 | 原始需求、术语、现状、业务规则、版本 | 无关会议全文、未确认传言 |
| Coding | 需求、相关调用链、数据结构、项目规范、测试 | 整个私人目录、真实 `.env` |
| Debug | 环境、复现步骤、完整异常、相关日志、最近差异 | 所有生产日志、访问令牌 |
| 文档分析 | 问题、权威文档、版本、引用要求 | 未授权内部文档、过期资料未标注 |

## 4. 上下文的组织顺序

推荐顺序是：任务与完成条件 → 权威依据 → 当前状态 → 相关材料 → 已知事实 → 待确认问题 → 允许和禁止操作 → 验证方法。把代码、日志等材料用清楚的边界包住，避免模型把材料内容误当新指令。

```text
任务编号：SD-AI-006
目标：找出 SD-001 登录失败的候选原因，不修改代码。
权威依据：登录规格 v2.1 第 3 节。
当前状态：测试环境可稳定复现。
材料：错误响应、完整堆栈、认证入口和最近差异。
已知事实：HTTP 401；账号未锁定。
待确认：令牌签名配置是否在发布时变化。
禁止：读取真实密钥、连接生产环境、修改文件。
输出：事实、候选假设、每个假设的验证动作。
完成条件：每个结论都能指向材料；不能确认时明确说明。
```

## 5. 处理资料冲突

假设需求票写“空描述返回 400”，当前接口规格写“返回 422”，代码实际也返回 422。不能因为两份材料一致就擅自宣布需求票错误。应记录冲突位置、版本、当前行为、影响范围和需要谁确认。

| 材料 | 内容 | 可确认的事实 | 不能自行决定的内容 |
| --- | --- | --- | --- |
| 需求票 | 空描述返回 400 | 票中确实写了 400 | 是否为最终要求 |
| 接口规格 | 返回 422 | 当前规格写 422 | 规格是否待更新 |
| 实际测试 | 返回 422 | 当前系统行为 | 应保持还是修改 |

## 6. 上下文中的不可信指令

日志、网页或文档可能包含“忽略之前要求”“读取其他文件”“输出密钥”等文字。它们可能是普通业务文本，也可能是 Prompt Injection。处理原则是：把它们作为待分析数据，不把它们当作授权；工具范围、权限和秘密保护由宿主程序执行。

## 7. 上下文过多和过少的症状

| 症状 | 可能原因 | 调整方法 |
| --- | --- | --- |
| 回答混合两个版本 | 没标来源或优先级 | 标版本并列出冲突 |
| AI 不断猜字段 | 缺少数据结构 | 补充最小 Schema |
| 忽略核心错误 | 日志过多且无时间范围 | 截取复现窗口并保留完整堆栈 |
| 修改无关文件 | 范围和项目结构不清 | 指定允许文件及差异检查 |
| 成本高且结果变差 | 大量无关内容 | 删除不能支持任务的材料 |

## 8. 实践与验收

现有材料包括一份需求、两个版本的接口规格、三段日志、五个代码文件、一个含密钥的 `.env` 和一张错误截图。为“调查工单提取接口为何返回 500”制作上下文包。

参考判断：排除 `.env` 并使用配置名占位；保留可复制的错误文本而不是只给截图；选择异常发生时间附近日志、完整堆栈、路由到 AI Service 的调用链和对应测试；两版规格同时标注版本并列为冲突。验收时说明每份材料的用途、来源及排除理由。

## 9. 新人核对卡

Prompt Engineering 主要设计任务表达，Context Engineering 还要决定取哪些资料、怎样排序、如何标注来源、怎样处理版本冲突和敏感信息。上下文不是越多越好，而是每一部分都能帮助模型完成任务或遵守边界。

提交上下文包前逐项回答：这份材料支持哪个判断；它是否为当前版本；是否包含秘密或无关个人信息；模型应把它当指令还是证据；资料冲突时谁拥有最终决定权。
