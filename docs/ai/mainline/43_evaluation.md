# 第 43 章 AI 应用评价

> 本章成果：建立独立评估集、指标和发布门槛，让 Prompt、模型和 RAG 变更可以回归。

先定义业务成功，再选择指标。结构化提取可计算字段准确率、完整率和非法结构率；RAG 分别计算 Recall@K、引用正确率、声明支持率和适当拒答率；Agent 还要看任务完成率、工具错误、越权阻止和平均步骤。

## 1. 评估集

样例包含输入、参考答案或判断规则、标签和来源，覆盖正常、边界、模糊、无答案、注入、越权和外部失败。开发集用于改进，独立评估集用于发布判断。

自动评分适合确定字段和大规模初筛；模型评分需要清晰 Rubric、样例和人工抽查；高风险结论保留专家评审。开发样例与评估集分离，避免针对答案调 Prompt。

## 2. 指标定义

每个指标写清分子、分母、忽略条件和阈值。例如字段准确率按字段还是整条记录计算，会产生不同结论。拒答既要避免乱答，也不能过度拒绝。

## 3. 评分方法

确定字段使用程序比较；语义质量使用 Rubric；模型评分器需验证与人工一致性，并保存评分理由。安全用例通常采用硬门槛，不用平均分抵消越权失败。

## 4. 回归与报告

模型、Prompt、Schema、Embedding、Chunk 和工具变化都要运行同一评估集。报告展示总体指标、严重失败、退化样本、版本和是否达到发布门槛。

## 5. 评估集怎样建立

从真实但已脱敏的业务问题、历史故障和设计边界中抽样，覆盖常见、困难、无答案、权限、安全和多语言场景。每条样本包含输入、允许使用的资料、预期关键点、禁止出现的内容和评分理由。训练或调试时频繁查看的样本不能代表最终盲测集。

## 6. 不同层使用不同指标

| 层 | 示例指标 |
| --- | --- |
| Structured Output | Schema 通过率、业务规则通过率 |
| Retrieval | Recall@K、相关结果比例、权限泄漏数 |
| Generation | 忠实性、关键点覆盖、引用正确率、拒答正确率 |
| Agent | 任务成功率、平均轮数、错误工具调用、副作用错误 |
| 系统 | 延迟、可用性、成本、人工介入率 |

不能用一个总分掩盖严重安全失败。权限泄漏、错误写操作等应设为零容忍门槛。

## 7. 评分方法的局限

规则评分稳定，适合格式、枚举和引用编号；人工评分适合业务含义，但要有评分 Rubric 和多人校准；模型评分适合扩大覆盖，却可能有偏差，必须用人工样本验证。三者组合比完全依赖“AI 给 AI 打分”可靠。

## 8. 回归判定

Prompt、模型、Embedding、Chunk、工具或业务代码变化都可能影响结果。每次变更记录版本，运行同一评估集，展示总体指标与具体退化样本。平均质量提高但高风险用例退化时，应阻止发布或缩小范围。

学员最终要能回答：评估代表哪些用户场景、评分依据是什么、结果能否复现、失败集中在哪类、上线阈值为何合理。

冻结代码、Prompt、模型、文档和参数版本，报告总体、分类和失败样例。改善平均分但显著增加成本或延迟时，需要产品权衡。

实践：为项目建立版本化评估集和报告，设置必须通过的安全用例与质量阈值。任一 Prompt、模型、Chunk、Top-K 或工具描述改变后重跑，并显示相对基线的改善和退化。
