# 第 20 章 LLM API 基础

> 本章成果：完成一次最小模型调用，并能解释 Model、Instructions、Input、Response 和 Usage。

## 1. 最小调用

以下是 Responses API 的核心形态，具体模型使用项目配置中已验证、当前可用的模型，不在讲义固定“最新”名称。

```python
response = client.responses.create(
    model=settings.ai_model,
    instructions="只根据输入生成不超过80字的工单摘要。",
    input=user_text,
    max_output_tokens=200,
)
summary = response.output_text
```

`instructions` 定义本次行为，`input` 是用户数据，`max_output_tokens` 是输出上限。SDK 支持 `output_text` 时优先使用它，不要假定输出数组第一项永远是文本。记录响应状态、请求 ID 和实际 usage。

## 2. 请求中各部分的职责

`model` 选择已配置模型；`instructions` 放服务端控制的任务规则；`input` 放本次用户内容；输出上限控制风险。用户数据不能拼成更高优先级指令。若使用多轮状态，要明确由应用重放历史还是使用 API 提供的会话标识。

## 3. 读取响应

先检查请求是否成功和响应是否完成，再读取文本或结构化项。响应可能包含消息、工具调用、拒绝或不完整状态，不能假设数组第一项固定。Usage 用于观测和成本，不代表回答正确。

## 4. 错误分类与重试

认证和参数错误需要修正配置；限流与临时服务错误可按策略有限退避；超时结果是否已在服务端完成需要按接口语义处理；业务校验失败通常不应原样重试。所有重试共享总耗时和次数上限。

## 5. 版本与模型选择

模型能力、字段和限制会变化，不在业务代码中永久假定“最新模型”。将模型与 Prompt 版本集中配置，并用固定评估集比较质量、延迟、成本和功能支持后再切换。

## 6. 一次 API 调用的完整生命周期

1. 服务端从受控配置读取凭据和模型；
2. 根据业务任务构造开发者指令与用户输入；
3. 设置超时、输出格式和必要工具；
4. 发送请求并记录追踪编号和开始时间；
5. 根据响应状态读取文本、结构化结果或工具请求；
6. 校验结果，记录用量、延迟与错误类别；
7. 只把业务需要的字段返回前端。

“HTTP 请求成功”不一定等于“任务成功”。响应可能已完成但内容不符合业务规则，也可能处于未完成、拒绝或需要工具结果的状态。读取响应时应先判断状态和内容类型，再取结果，不要假设数组中的第一个元素永远是最终文本。

## 7. 哪些错误可以重试

| 情况 | 默认处理 |
| --- | --- |
| 参数或 Schema 错误 | 修正请求，不自动重试 |
| API Key 无效或无权限 | 停止并告警，不重试 |
| 限流 | 按服务提示和退避策略有限重试 |
| 短暂网络或服务错误 | 在总时间预算内有限重试 |
| 内容被拒绝 | 向业务层返回可识别状态，不改写后盲目重试 |
| 输出业务校验失败 | 可做一次受控修复或转人工，避免无限循环 |

## 8. 模型选择不是只看“最强”

要同时看任务能力、结构化输出或工具支持、延迟、上下文需求、稳定性、数据政策和成本。建立一组固定样例比较候选模型，再决定默认模型与降级模型。模型名称和参数可能随服务变化，应集中配置并记录版本，不要散落在代码中。

本章检查点：学员能解释凭据为什么只能保存在服务端，能正确区分指令与业务输入，能按响应状态处理结果，并为每类错误说明是否重试及原因。

不要在讲义或代码中永久假定“最新模型”。根据质量、延迟、成本、上下文和功能支持选择，并用同一评估集验证变更。官方 Responses API 能生成文本或 JSON，并支持自定义及内置工具；实际字段以[官方 API 参考](https://developers.openai.com/api/reference/resources/responses/methods/create)为准。

请求必须设置项目级超时。只对临时性错误有限重试，并采用退避；认证、参数错误和业务校验失败不应盲目重试。参阅[官方 Responses API](https://developers.openai.com/api/reference/resources/responses/methods/create)。

实践：用虚构工单执行一次真实调用；没有可用 Key 时使用记录好的脱敏替身响应。提交成功与超时两种测试，不提交 Key 或完整用户正文。
