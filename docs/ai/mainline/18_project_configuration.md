# 第 18 章 AI 项目环境与配置

> 本章成果：在已有 FastAPI 工程中配置模型 SDK、环境变量和可替换模型设置，不重新学习 Python 或 FastAPI。

## 1. 开始状态

你已经有可运行、可测试的 FastAPI 工单项目。新增 `app/ai/`、配置项和开发依赖；不修改已有数据库契约。

建议配置名：`OPENAI_API_KEY`、`AI_MODEL`、`AI_TIMEOUT_SECONDS`、`AI_MAX_OUTPUT_TOKENS`。Key 必填且只存在于服务端运行环境；模型名不硬编码在业务函数中。`.env.example` 只放占位符，真实 `.env` 不提交 Git。

## 2. 配置分层

将通用默认值、环境差异和秘密分开。模型、超时、输出上限和功能开关可由普通配置管理；Key 由环境变量或秘密管理服务注入。开发、测试、预发布、生产使用不同凭据和限额。

配置对象在启动时验证类型与范围。错误消息可以指出缺少 `OPENAI_API_KEY`，但绝不打印值。测试通过依赖注入使用 Fake Client，不修改机器全局环境。

## 3. 依赖和版本

记录 Python 与 SDK 的已验证版本，并锁定直接依赖。升级前阅读变更说明，运行客户端契约测试、业务测试和评估集。模型名也属于部署配置，切换模型不是无风险文本修改。

安装并锁定当前验证过的 OpenAI Python SDK 版本。先阅读[官方 SDK 与 API 文档](https://developers.openai.com/api/docs)，再根据项目依赖文件重建环境。

## 4. 验证与排错

启动时检查必填配置和数值范围；运行时根据认证、网络、超时、限流和模型能力分类错误。排错日志只显示配置项名称和安全状态，不输出真实凭据。

## 5. 配置项的含义要明确

| 配置 | 作用 | 错误配置的表现 |
| --- | --- | --- |
| API Key | 证明服务端有权调用供应商 | 认证失败，或误用生产账户产生费用 |
| Model | 选择所需能力和成本等级 | 功能不支持、质量变化或成本超预算 |
| Timeout | 限制单次等待时间 | 太短导致频繁失败，太长拖住请求资源 |
| Retry | 处理可恢复的短暂失败 | 无限制重试造成重复操作和费用放大 |
| Base URL | 指定服务端点 | 请求发送到错误环境或代理 |

模型支持的参数和能力可能不同，配置层不能假设所有模型都支持同一组选项。启动时应校验必填项，但日志中只能显示“已配置”，不能打印密钥值。

## 6. 环境隔离

开发、测试和生产环境应使用不同凭据、额度、数据库和日志策略。`.env` 适合本地开发，不应提交到版本库；部署环境应通过平台的秘密管理功能注入。示例文件只保留变量名和无敏感默认值。

配置的优先级也要固定，例如“部署环境变量高于本地默认值”。如果同一变量可从多个地方读取却没有规则，调查时很难确认程序实际使用了哪个值。

## 7. 最小启动检查

应用启动后应验证：关键配置存在、数值范围合理、供应商客户端能创建、健康检查可访问。不要用一次昂贵的真实生成请求作为每次健康检查；外部依赖的连通性可以放在单独的就绪检查或诊断命令中。

本章成果是可复制的配置说明：新学员仅凭示例配置和步骤，就能启动测试环境，并能区分“配置缺失”“认证失败”“网络失败”和“模型不支持”四类问题。

启动时验证必要配置，但错误信息不得打印 Key。测试环境注入假客户端，不要求真实网络。检查 Git 差异确认秘密未出现，并执行原有测试证明项目基线未被破坏。

实践产物：配置清单、`.env.example`、依赖锁定记录和一条“缺少 Key 时安全失败”的测试。
