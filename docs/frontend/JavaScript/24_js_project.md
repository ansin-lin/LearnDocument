# 第 24 章 JavaScript 新人综合练习

本章是 JavaScript 阶段的最终综合练习说明。练习使用 `training` 文件夹中的 JavaScript 任务：

[JavaScript 阶段练习任务](../training/03_javascript_task.md)

本章不重新发明项目需求，而是说明学员应如何把前 23 章知识整合到最终成果中。

## 1. 最终成果

学员需要在请假申请系统中补齐 JavaScript 行为，让已有 HTML 和 CSS 页面具备基本交互能力。

最终至少包括：

- 登录页面基础校验。
- 注册页面基础校验。
- 首页登录状态显示。
- 申请页面表单校验。
- 确认页面数据展示。
- 完成页面跳转。
- 申请列表页面数据展示。
- 本地存储保存登录状态和申请记录。

## 2. 必须使用的核心知识

| 知识 | 在项目中的用途 |
| --- | --- |
| 变量与数据类型 | 保存表单值、状态和配置 |
| 条件判断 | 表单校验、登录判断、页面跳转判断 |
| 数组 | 保存申请列表 |
| 对象 | 表示用户、申请记录、状态映射 |
| 函数 | 封装校验、格式化、存储、渲染 |
| DOM 查询 | 找到输入框、按钮、提示区域、列表区域 |
| DOM 修改 | 显示错误、渲染确认信息、渲染列表 |
| 事件 | 处理点击、输入、表单提交 |
| JSON | 对象和字符串之间转换 |
| localStorage | 保存登录状态和申请列表 |
| sessionStorage | 页面间传递临时申请数据 |
| Date | 计算请假天数、格式化日期 |
| 正则 | 校验员工编号、邮箱等格式 |
| 调试 | 阅读错误、定位问题、验证变量 |

## 3. 可选使用的知识

| 知识 | 可选用途 |
| --- | --- |
| Set | 去重请假类型或日期 |
| Map | 保存状态代码和显示文字 |
| 解构 | 简化对象属性读取 |
| 展开语法 | 新增或更新申请数组 |
| 模块化 | 拆分格式化、校验、存储代码 |
| async/await | 为后续接口请求改造预留结构 |
| fetch | 如果教师提供测试接口 URL，可读取初始数据 |
| Axios | 如果项目具有接口和构建环境，可使用统一请求实例 |

可选内容不作为零基础第一轮验收的硬性要求，但可以作为优秀作业或进阶任务。

## 4. 推荐实现顺序

### 4.1 先确认页面和脚本连接

每个需要 JS 的页面都要正确引入脚本。

```html
<script src="js/app.js" defer></script>
```

如果使用模块：

```html
<script type="module" src="js/app.js"></script>
```

先在控制台输出：

```js
console.log("JavaScript loaded");
```

确认脚本确实执行。

### 4.2 登录与注册

先完成最小逻辑：

- 输入不能为空。
- 校验通过后保存登录用户。
- 登录成功跳转首页。
- 未登录访问业务页时跳转登录页。

### 4.3 申请表单

完成：

- 获取表单元素。
- 绑定 `submit` 事件。
- 阻止默认提交。
- 校验字段。
- 整理申请对象。
- 保存到 `sessionStorage`。
- 跳转确认页。

### 4.4 确认与完成

确认页：

- 读取 `sessionStorage`。
- 显示申请信息。
- 点击确认后保存到 `localStorage` 申请列表。
- 跳转完成页。

完成页：

- 显示成功提示。
- 延迟跳转首页。

### 4.5 申请列表

完成：

- 从 `localStorage` 读取申请数组。
- 没有数据时显示空状态。
- 有数据时循环创建 DOM。
- 显示日期、类型、天数、状态。

## 5. 验收标准

学员提交前必须自测：

1. 所有页面能正常打开。
2. JS 文件路径正确。
3. 表单校验能阻止错误输入。
4. 校验错误能显示在页面上。
5. 校验通过后能跳转确认页。
6. 确认页能显示申请数据。
7. 完成页能跳转首页。
8. 申请列表能显示已提交记录。
9. 刷新页面后申请记录仍然存在。
10. 控制台没有未处理错误。

## 6. 提交物

学员需要提交：

- 完整项目文件夹。
- 简短说明文档。
- 自测结果截图或文字记录。
- 已知问题说明。

说明文档至少包括：

- 实现了哪些功能。
- 使用了哪些本课程知识。
- 如何运行项目。
- 如何验证功能。

## 7. Review 重点

教师或 Review 人员重点检查：

- 代码是否能运行。
- JS 是否能和 HTML、CSS 正确配合。
- 表单校验是否清楚。
- 数据对象结构是否稳定。
- 本地存储读写是否有空值处理。
- 函数职责是否清楚。
- 是否有大量重复代码。
- 是否把样式大量写在 JS 中。
- 控制台是否有错误。

## 8. 进阶改修任务

基础功能完成后，可以追加以下任务：

1. 增加申请删除功能。
2. 增加状态筛选功能。
3. 增加按日期排序功能。
4. 使用 `Set` 生成不重复的请假类型筛选项。
5. 使用模块化拆分 JS 文件。
6. 使用 `fetch()` 从教师提供的测试接口 URL 加载初始申请数据。
7. 在具有后端接口和构建环境时，使用 Axios 实例封装申请查询与提交。

这些任务适合作为第二轮练习，不建议和第一轮基础验收混在一起。
