# JavaScript 递进练习：有給休暇申請システム

## 1. 任务目标

继续使用已经完成 HTML 和 CSS 的七页面项目，为有給休暇申請系统实现以下前端功能：

- 登录画面的模拟登录；
- 注册画面的输入校验；
- 首页员工信息与申请汇总；
- 休假申请的输入、确认和提交；
- 申请一览、条件筛选与申请取消；
- 登录状态、申请草稿和申请记录的浏览器存储；
- 异常提示、自测记录和改修影响调查。

本练习没有后端和数据库。登录只使用固定的研修账号模拟成功与失败，不是真实身份认证；注册内容不会保存为真实账号。

---

## 2. 开始状态

开始前应已完成 HTML、CSS 两个阶段，并确认七个页面能够正常显示：

paid-leave-system/

本阶段为每个页面分别新增一个 JavaScript 文件。不要把七个页面的全部处理写入同一个 `app.js`。

## 4. 实现范围与禁止事项

### 4.1 本阶段实现

- DOM 查询与页面内容更新；
- 表单事件和输入校验；
- 页面跳转；
- JSON 转换；
- `localStorage` 和 `sessionStorage`；
- 日期计算与受付番号生成；
- 数组查找、筛选、汇总和状态更新；
- 加载、空数据、成功和失败状态；
- 浏览器开发者工具调试。

### 4.2 本阶段不实现

- Web Crypto、密码摘要或加密；
- 真实用户注册和身份认证；
- Cookie 或服务端 Session；
- 后端 API、Fetch、Axios；
- Vue、React、jQuery；
- 浏览器中保存密码；
- 管理员审批功能。

> 不得把密码写入 `localStorage`、`sessionStorage`、URL、DOM 属性或控制台。登录页的密码只用于本次模拟判定，页面跳转后不保存。

## 5. 共通处理规格

### 5.1 登录状态

登录成功后，在 `sessionStorage` 中保存：

| 键 | 内容 | 生命周期 |
| --- | --- | --- |
| `paidLeaveCurrentUser` | 当前研修用户对象的 JSON | 当前标签页会话 |

保存对象：

```js
{
  employeeNumber: "EMP-00001",
  name: "山田 太郎",
  department: "development"
}
```

五个业务页面打开时必须读取该对象：

- 数据存在且格式正确：继续初始化页面；
- 数据不存在：跳转 `login.html`；
- JSON 损坏或字段不足：删除该键，显示或记录必要信息后跳转登录页。

登录页和注册页不执行业务页面的登录检查。

### 5.2 申请相关存储

| 存储位置 | 键 | 内容 |
| --- | --- | --- |
| `localStorage` | `paidLeaveApplications` | 已提交申请数组 |
| `sessionStorage` | `paidLeaveDraft` | 尚未提交的申请草稿 |
| `sessionStorage` | `paidLeaveLastReceipt` | 最后提交的受付番号 |

读取 JSON 和写入存储时使用 `try...catch`。

- 读取失败时不能直接覆盖原始数据；
- 保存失败时不能显示“保存成功”；
- 页面应显示使用者能够理解的日文错误消息；
- Console 可以记录排错信息，但不得输出密码或完整个人资料。

### 5.3 固定映射

页面显示文字使用映射对象取得，不在多个条件判断中反复手写。

部门映射：

| 保存值 | 页面显示 |
| --- | --- |
| `development` | システム開発部 |
| `quality` | 品質管理部 |
| `sales` | 営業部 |
| `general-affairs` | 総務部 |
| `human-resources` | 人事部 |

申请状态映射：

| 保存值 | 页面显示 |
| --- | --- |
| `pending` | 申請中 |
| `approved` | 承認済 |
| `returned` | 差戻し |
| `cancelled` | 取消済 |

休假类型映射：

| 保存值 | 页面显示 |
| --- | --- |
| `paid` | 有給休暇 |
| `half-am` | 半日休暇（午前） |
| `half-pm` | 半日休暇（午後） |
| `special` | 特別休暇 |

### 5.4 DOM 和错误处理

- 页面元素使用稳定的 `id` 或 `data-*` 属性查询；
- 查询结果可能不存在时先判断，不对 `null` 直接调用方法；
- 普通文字使用 `textContent` 显示；
- 不使用 `innerHTML` 拼接用户输入；
- 字段错误显示在对应控件附近；
- 错误字段设置 `aria-invalid="true"`；
- 校验失败后聚焦第一个错误字段；
- 处理过程中可以临时禁用提交按钮，结束后恢复；
- 不使用连续多个 `alert()` 代替字段错误信息。

## 6. AUTH-001：登录画面

### 6.1 目标文件

```text
login.html
js/login.js
```

### 6.2 固定研修账号

```text
アカウント：training.user
パスワード：training123
```

该账号只用于前端流程练习。账号和密码写在任务规格中，因此不是秘密，也不能用于真实系统。

### 6.3 处理流程

1. 取得账号和密码并去除账号前后空格；
2. 账号统一转换为小写；
3. 检查必填和长度；
4. 与固定研修账号严格比较；
5. 登录成功时把固定研修用户对象保存到 `paidLeaveCurrentUser`；
6. 跳转到 `index.html`；
7. 登录失败时显示统一消息；
8. 不区分账号错误还是密码错误；
9. 无论成功或失败，都不保存密码。

统一失败消息：

```text
アカウントまたはパスワードが正しくありません
```

### 6.4 异常处理

- 连续点击登录按钮时不能重复执行；
- `sessionStorage` 写入失败时停留当前页并显示错误；
- 不在 Console 输出输入密码；
- 已存在有效登录状态时，可以显示“ホームへ”入口，但不自动循环跳转。

## 7. AUTH-002：注册画面

### 7.1 目标文件

```text
register.html
js/register.js
```

### 7.2 处理边界

本画面只练习客户端输入校验，不保存账号、密码和员工资料，也不生成可登录账号。

页面必须明确显示：

```text
研修用の入力確認です。登録内容は保存されません。
```

### 7.3 校验规则

| 项目 | 校验 |
| --- | --- |
| アカウント | 必填；去除前后空格；`^[a-z0-9._-]{4,20}$` |
| パスワード | 必填；长度 8～32 |
| パスワード（確認） | 必填；必须与密码一致 |
| 氏名 | 必填；去除前后空格；长度 2～40 |
| 所属 | 必须选择有效选项 |

提交成功后：

1. 临时禁用提交按钮，防止重复处理；
2. 显示“入力内容を確認しました”；
3. 显示账号、姓名和所属名称；
4. 不显示密码；
5. 清空密码和确认密码；
6. 提供返回登录页的操作；
7. 不写入浏览器存储。

## 8. HOME-001：首页

### 8.1 目标文件

```text
index.html

```

### 8.2 初始处理

1. 检查登录状态；
2. 显示员工编号、姓名和所属；
3. 读取申请数组；
4. 只统计当前员工的申请；
5. 显示汇总结果；

### 8.3 汇总规则

| 项目 | 规则 |
| --- | --- |
| 有給残日数 | 初始 12 日，只扣除 `approved` 的有給和半日休假 |
| 申請中件数 | 当前用户 `pending` 的件数 |
| 当月承認済日数 | 当前月且状态为 `approved` 的申请日数合计 |

### 8.4 退出处理

- 删除 `paidLeaveCurrentUser`；
- 删除 `paidLeaveDraft`；
- 删除 `paidLeaveLastReceipt`；
- 不删除 `paidLeaveApplications`；
- 跳转到 `login.html`。

## 9. LEAVE-001：休假申请输入

### 9.1 目标文件

```text
apply.html
js/apply.js
```

### 9.2 初始处理

1. 检查登录状态；
2. 显示当前员工信息；
3. 如果存在属于当前员工的草稿，则恢复表单；
4. 如果草稿属于其他员工，则删除无效草稿；
5. 为表单绑定 `submit` 事件。

### 9.3 输入校验

| 项目 | 校验 |
| --- | --- |
| 休暇種別 | 必须选择有效类型 |
| 開始日 | 必填；不能早于今天 |
| 終了日 | 必填；不能早于开始日 |
| 半日休暇 | 开始日和结束日必须相同 |
| 申請理由 | 必填；去除空格后不为空；最多 200 字符 |
| 引継ぎ状況 | 必须选择 |
| 連絡事項 | 最多 300 字符 |
| 特別休暇 | 連絡事項中必须填写具体制度名称 |
| 申請日数 | 不能超过当前有給残日数 |

### 9.4 申请日数

- `half-am`、`half-pm` 固定为 `0.5` 日；
- 其他类型按开始日至结束日的自然日数计算，包含首尾日期；
- 本练习不排除周末和日本节假日；
- 日期计算使用第 14 章讲解的日期拆分和 UTC 时间戳方式。

校验成功后创建草稿：

```js
{
  ownerEmployeeNumber: "EMP-00001",
  leaveType: "paid",
  startDate: "2026-09-01",
  endDate: "2026-09-02",
  leaveDays: 2,
  reason: "私用のため",
  handoverStatus: "done",
  note: ""
}
```

把草稿保存到 `paidLeaveDraft`，然后跳转 `confirm.html`。

## 10. LEAVE-002：申请内容确认

### 10.1 目标文件

```text
confirm.html
js/confirm.js
```

### 10.2 初始处理

1. 检查登录状态；
2. 读取申请草稿；
3. 确认草稿属于当前员工；
4. 使用映射显示全部申请内容；
5. 没有有效草稿时显示错误和返回申请页的操作。

### 10.3 修正处理

点击“修正する”时：

- 保留 `paidLeaveDraft`；
- 返回 `apply.html`；
- 申请页恢复原输入。

### 10.4 提交处理

点击“申請する”时：

1. 立即禁用按钮；
2. 再次确认草稿有效；
3. 读取已有申请数组；
4. 生成受付番号；
5. 创建正式申请记录；
6. 保存申请数组；
7. 保存最后受付番号；
8. 删除申请草稿；
9. 跳转 `complete.html`。

正式记录：

```js
{
  id: "REQ-20260831-001",
  ownerEmployeeNumber: "EMP-00001",
  leaveType: "paid",
  startDate: "2026-09-01",
  endDate: "2026-09-02",
  leaveDays: 2,
  reason: "私用のため",
  handoverStatus: "done",
  note: "",
  status: "pending",
  submittedAt: "2026-08-31T02:00:00.000Z"
}
```

`submittedAt` 使用 `new Date().toISOString()` 保存。结果采用 UTC 的 `Z` 格式。

### 10.5 受付番号

格式：

```text
REQ-YYYYMMDD-NNN
```

规则：

- 日期部分使用提交当天；
- 当天第一条从 `001` 开始；
- 读取已有同日前缀编号；
- 取得最大序号后加一；
- 不使用数组长度直接生成；
- 保存失败时不能删除草稿或跳转完成页。

## 12. LEAVE-004：申请一览

### 12.1 目标文件

```text
applications.html
js/applications.js
```

### 12.2 初始处理

1. 检查登录状态；
2. 读取当前员工申请；
3. 显示申请列表；
4. 绑定状态筛选、关键字检索、条件清除和取消事件。

### 12.3 筛选与检索

状态选项：

```text
すべて / 申請中 / 承認済 / 差戻し / 取消済
```

关键字匹配范围：

- 受付番号；
- 申请理由。

状态和关键字同时输入时，必须同时满足两个条件。

显示结果：

- 有数据：显示记录和当前件数；
- 没有数据：显示“該当する申請はありません”；
- 读取失败：显示错误，不显示伪造空数据。

### 12.4 取消

只有 `pending` 记录显示“取消”按钮。

处理顺序：

1. 显示包含受付番号的确认对话框；
2. 用户取消对话框时不修改数据；
3. 再次根据受付番号查找记录；
4. 再次确认记录属于当前员工且状态为 `pending`；
5. 把状态更新为 `cancelled`；
6. 保存完整申请数组；
7. 保存成功后重新筛选和渲染；
8. 不从数组中删除记录。

## 17. 日本项目式改修任务

### 17.1 变更规格

> 申請一覧画面に「開始日」と「終了日」の検索条件を追加してください。両方が入力された場合は、指定期間と重なる申請を表示してください。既存の状態検索とキーワード検索はそのまま利用できること。

### 17.2 影响调查

修改前记录：

- 受影响的 HTML 文件；
- 受影响的 JavaScript 文件；
- 现有筛选条件的组合方式；
- 日期未输入、只输入一侧、两侧输入和日期逆转时的处理；
- 需要追加的测试。

### 17.3 实现要求

- 只修改 `applications.html`、`js/applications.js` 和必要的 CSS；
- 开始日和结束日具有明确标签；
- 结束日早于开始日时显示错误；
- 日期条件与状态、关键字条件同时生效；
- 点击“条件をクリア”时清除全部条件；
- 不修改原始申请数组；
- 没有结果时继续显示空状态。

### 17.4 追加测试

| 编号 | 测试内容 | 预期结果 |
| --- | --- | --- |
| CHG-01 | 日期条件为空 | 结果与改修前一致 |
| CHG-02 | 只输入开始日 | 显示结束日不早于该日的申请 |
| CHG-03 | 只输入结束日 | 显示开始日不晚于该日的申请 |
| CHG-04 | 输入完整期间 | 显示与指定期间重叠的申请 |
| CHG-05 | 结束日早于开始日 | 显示错误，不执行筛选 |
| CHG-06 | 日期、状态和关键字组合 | 只显示满足全部条件的申请 |
| CHG-07 | 清除条件 | 所有条件恢复默认值 |
