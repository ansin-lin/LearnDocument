# JavaScript 递进练习：有給休暇申請システム

## 1. 任务定位

继续使用已经完成 HTML 结构和 CSS 样式的五页面项目，实现申请输入、确认、保存、列表筛选、取消和首页汇总功能。

本阶段使用浏览器原生 JavaScript，不使用 Vue、React、jQuery、后端服务器和外部 API。数据只保存在当前浏览器中，因此本项目是前端业务流程练习，不是真实的审批系统。

## 2. 前置状态与最终目录

开始前确认五个页面能够互相跳转，并且共用一个 CSS 文件。将项目扩展为：

```text
paid-leave-system/
├─ index.html
├─ apply.html
├─ confirm.html
├─ complete.html
├─ applications.html
├─ css/
│  └─ style.css
└─ js/
   └─ app.js
```

五个页面共用一个 `js/app.js`，使用 `defer` 加载。脚本必须先判断当前页面上是否存在目标元素，再注册相应事件，不能因为某一页缺少元素而中断整个脚本。

## 3. 实现边界

- 使用 DOM、事件、数组、对象、函数、条件判断和浏览器存储完成任务。
- 不使用 `innerHTML` 插入员工输入内容；使用 `textContent` 和 DOM 方法创建节点。
- 不在浏览器中保存密码、令牌或其他秘密。
- 不实现登录、真正的审批权限、邮件发送和服务器持久化。
- HTML 原生验证继续保留；JavaScript 增加业务规则，但不能删除 `required`、类型和长度限制。
- 用户能够观察到加载成功、空数据、提交成功、校验失败和存储失败状态。

## 4. 数据规格

每条申请使用以下对象结构：

```js
{
  id: "REQ-20260818-001",
  leaveType: "paid",
  startDate: "2026-08-24",
  endDate: "2026-08-25",
  leaveDays: 2,
  reason: "私用のため",
  handoverStatus: "done",
  note: "緊急連絡はメールで確認します。",
  status: "pending",
  submittedAt: "2026-08-18T10:30:00+09:00"
}
```

代码内部使用以下稳定值，页面显示对应的日文：

| 字段 | 保存值 | 页面显示 |
| --- | --- | --- |
| `leaveType` | `paid` | 有給休暇 |
| `leaveType` | `half-am` | 半日休暇（午前） |
| `leaveType` | `half-pm` | 半日休暇（午後） |
| `leaveType` | `special` | 特別休暇 |
| `status` | `pending` | 申請中 |
| `status` | `approved` | 承認済 |
| `status` | `returned` | 差戻し |
| `status` | `cancelled` | 取消済 |

申请数组保存在 `localStorage` 的 `paidLeaveApplications` 键中。输入页与确认页之间的临时草稿保存在 `sessionStorage` 的 `paidLeaveDraft` 键中。

## 5. 共通 JavaScript 任务

### 5.1 页面识别与初始化

- 在各页面的 `body` 或主要区域添加稳定的页面标识，例如 `data-page="apply"`。
- 根据页面标识只执行当前页面需要的初始化函数。
- 使用多个职责单一的函数，不把所有逻辑写进一个事件监听器。
- 需要查询的元素使用稳定的 `id` 或 `data-*` 属性。

### 5.2 存储处理

- 第一次打开系统时写入 HTML 阶段使用的三条测试申请。
- 读取数据时使用 `try...catch` 处理无效 JSON 或存储不可用。
- 写入失败时在页面显示错误信息，不能只写入控制台。
- 取消记录时修改状态，不从数组中物理删除记录。
- 提供开发用“测试数据重置”函数，但不要在普通页面上放置容易误触的重置按钮。

### 5.3 共通显示

- 日期以 `YYYY/MM/DD` 形式显示，存储时保持 `YYYY-MM-DD`。
- 日文名称通过映射对象取得，不能在多个函数中重复编写相同判断。
- 页面提示区域使用 `role="status"` 或 `aria-live="polite"`，并保持可见文字。
- 所有用户输入都通过 `textContent` 显示，避免把输入解释为 HTML。

## 6. 各画面功能任务

### 6.1 HOME-001：ホーム

- 从本地申请数据计算并显示以下汇总：
  - 有給残日数
  - 申請中件数
  - 当月承認済日数
- 有給残日数以 12 日为练习初始值，只扣除 `approved` 的有給休暇和半日休暇。
- `pending`、`returned` 和 `cancelled` 不扣除剩余天数。
- 没有数据时三个汇总仍显示明确的 `0` 或初始值，不能留空。

### 6.2 LEAVE-001：休暇申請

提交表单前执行以下校验：

1. 必填项目已经输入。
2. 开始日不能早于今天。
3. 结束日不能早于开始日。
4. 半日休暇的开始日和结束日必须相同。
5. 申请日数不能超过当前有給残日数。
6. `leaveType === "special"` 时，連絡事項必须包含具体制度名称，不能只输入空格。

错误处理要求：

- 在对应字段附近显示日文错误信息。
- 为错误控件设置 `aria-invalid="true"`，修正后恢复。
- 第一次失败时聚焦第一个错误控件。
- 不使用连续多个 `alert` 展示字段错误。
- 表单有效时，将草稿写入 `sessionStorage`，然后跳转到 `confirm.html`。
- 从确认页返回时恢复原输入，不要求员工重新填写。

申请日数采用简化规则：

- 半日休暇固定为 `0.5` 日。
- 其他类型按开始日至结束日的自然日数计算，包含首尾日期。
- 本练习暂不排除周末和日本节假日，必须在页面帮助文字中说明。

### 6.3 LEAVE-002：申請内容確認

- 从 `sessionStorage` 读取草稿并显示全部输入内容。
- 页面不再显示 HTML 阶段的固定测试数据。
- 不使用 `innerHTML` 拼接确认内容。
- “修正する”返回申请页，并保留草稿。
- “申請する”只能处理一次，点击后立即进入处理中状态并暂时禁用按钮。
- 生成 `REQ-YYYYMMDD-NNN` 格式的受付番号；同一天的序号从 `001` 开始递增。
- 新记录的状态固定为 `pending`，并写入提交时间。
- 保存成功后清除草稿、保存最后受付番号，然后跳转 `complete.html`。
- 没有草稿时显示“申請内容が見つかりません”，并提供返回申请页的操作。

### 6.4 LEAVE-003：申請完了

- 从 `sessionStorage` 读取最后提交的受付番号并显示。
- 刷新页面时不能重复新增申请。
- 没有受付番号时不显示伪造编号，应提示从申请页重新操作。
- 提供返回首页和打开申请一览的操作。

### 6.5 LEAVE-004：申請一覧

动态生成申请列表，并实现：

- 按状态筛选：すべて、申請中、承認済、差戻し、取消済。
- 按受付番号或申请理由进行关键字检索。
- 同时应用状态和关键字条件。
- 显示当前结果件数。
- 没有匹配数据时显示“該当する申請はありません”。
- `pending` 状态显示“取消”按钮；其他状态不显示可执行的取消按钮。
- 取消前显示包含受付番号的确认对话框。
- 确认后把状态改为 `cancelled`，重新保存并刷新列表。
- 点击“条件をクリア”后恢复全部记录。

为支持上述功能，可以在 `applications.html` 增加状态下拉框、关键字输入框、清除按钮、结果件数和消息区域。新增控件必须具有可关联标签。

## 8. 调试要求

- 使用 Elements 确认错误控件的 `aria-invalid` 是否正确变化。
- 使用断点观察表单数据如何变成申请对象。
- 使用 Application 面板检查 `localStorage` 和 `sessionStorage`。
- 使用控制台确认没有未处理异常。
- 修改一条测试数据状态，确认首页汇总和一览状态同步变化。
- 记录至少一个自己发现并修复的问题，包括症状、原因、修改位置和复测结果。

## 9. 日本项目式改修任务

收到以下变更规格：

> 申請中の休暇のみ取消可能とする。取消時はデータを削除せず、取消済に更新すること。取消後も監査確認のため一覧に表示すること。

提交改修前完成以下工作：

1. 调查首页汇总、一览筛选、取消按钮和本地数据保存受到的影响。
2. 确认 `pending` 以外的记录没有可执行取消操作。
3. 取消时只修改 `status`，不使用 `splice` 删除记录。
4. 确认 `取消済` 筛选能够找到该记录。
5. 刷新浏览器后再次确认状态仍然保留。
6. 记录自测证据和未解决问题。
