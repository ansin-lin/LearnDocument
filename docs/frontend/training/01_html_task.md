# HTML 递进练习：有給休暇申請システム

## 1. 任务目标

你将为日本企业内部使用的“有給休暇申請システム”制作七个 HTML 页面。本阶段只完成内容结构、表单、表格和页面之间的链接，不编写 CSS 和 JavaScript。

页面文字使用日文，任务说明使用中文。完成后，即使页面保持浏览器默认外观，使用者也能理解登录、注册、休假申请和申请查询的基本流程。

## 2. 开始状态与目录

新建以下目录和文件：

```text
paid-leave-system/
├─ login.html
├─ register.html
├─ index.html
├─ apply.html
├─ confirm.html
├─ complete.html
└─ applications.html
```

本阶段不得创建或使用 CSS、JavaScript、前端框架和组件库。

## 3. 项目背景

系统供公司员工注册培训账号、登录系统、提交带薪休假申请并查看处理状态。HTML 阶段使用以下固定测试员工：

| 项目 | 显示值 |
| --- | --- |
| 社員番号 | EMP-00001 |
| 氏名 | 山田 太郎 |
| 所属 | システム開発部 |
| 有給残日数 | 12日 |

系统使用以下申请状态：

| 状态 | 含义 |
| --- | --- |
| 申請中 | 等待审批 |
| 承認済 | 已批准 |
| 差戻し | 被退回，需要修改 |
| 取消済 | 已取消 |

| AUTH-001 | `login.html` | ログイン | 输入账号和密码 |

## 5. 共通 HTML 规格

七个页面都必须满足以下要求：

- 使用完整 HTML 文档结构，声明 `lang="ja"`、UTF-8 和适合移动设备的 `viewport`。
- 每页具有不同且能说明用途的 `title` 和 `meta description`。
- 每页只有一个 `h1`，后续标题层级连续。
- 页面跳转使用 `a`，执行表单操作使用 `button`。
- 所有表单控件都有可关联的 `label`、唯一 `id` 和含义清楚的 `name`。
- 必填项目同时显示“必須”文字并使用 `required`，不能只显示星号。
- 站内链接使用相对路径，不出现空链接和无法打开的路径。
- 不使用表格进行页面布局，不使用 `div` 代替标题、按钮、列表或表单控件。

登录页和注册页属于公开页面，只显示系统名称及登录、注册入口。其余五页使用 `header`、`nav`、`main`、`footer`，导航包含“ホーム”“休暇申請”“申請一覧”“ログアウト”。HTML 阶段的“ログアウト”链接暂时返回 `login.html`。

## 6. 认证画面任务

### 6.1 AUTH-001：ログイン

在 `login.html` 创建登录表单：

| 项目 | 控件 | 要求 |
| --- | --- | --- |
| アカウント | `input type="text"` | 必填；`autocomplete="username"`；长度 4～20 |
| パスワード | `input type="password"` | 必填；`autocomplete="current-password"`；长度 8～32 |

还必须完成：

- 表单使用 `action="index.html"` 和 `method="post"`，避免密码出现在地址栏中；HTML 阶段只检查结构和原生验证，不把页面跳转当作登录成功。
- 提交按钮文字为“ログイン”。
- 提供“アカウントをお持ちでない方”及前往 `register.html` 的链接。
- 显示“研修用システムのため、実際に使用しているパスワードは入力しないでください”。
- HTML 阶段只验证字段是否填写，不声称已经完成身份认证。

### 6.2 AUTH-002：アカウント登録

在 `register.html` 创建注册表单：

| 项目 | 控件 | 业务要求 |
| --- | --- | --- |
| アカウント | 文本框 | 必填；长度 4～20；提示只使用半角英数字、`.`、`_`、`-` |
| パスワード | 密码框 | 必填；长度 8～32；`autocomplete="new-password"` |
| パスワード（確認） | 密码框 | 必填；长度 8～32；与密码一致的判断留到 JavaScript 阶段 |
| 氏名 | 文本框 | 必填；长度 2～40；`autocomplete="name"` |
| 所属 | 下拉框 | 必填；系统开发部、品质管理部、营业部、总务部 |

要求如下：

- 表单使用 `action="login.html"` 和 `method="post"`，不得使用 GET 提交密码；HTML 阶段不声称资料已经保存。
- 所属选项的 `value` 使用稳定英文值：`development`、`quality`、`sales`、`general-affairs`。
- 页面显示只读说明“社員番号は登録完了時に自動採番されます”，不让使用者输入社员番号。
- 提交按钮文字为“登録する”，并提供返回登录页的链接。
- 显示“没有后端和数据库，注册与自动编号将在 JavaScript 阶段实现”的日文说明。

## 7. 休假业务画面任务

### 7.1 HOME-001：ホーム

在 `index.html` 中：

- 使用定义列表显示社員番号、氏名和所属。
- 显示“有給残日数：12日”。
- 创建“休暇を申請する”和“申請一覧を確認する”两个入口。
- 使用列表显示“原则上提前三个营业日申请”和“紧急情况联系直属上司”。
- 显示固定基准日 `2026年8月20日`，不得描述为自动取得。

### 7.2 LEAVE-001：休暇申請

在 `apply.html` 中创建表单。HTML 阶段提交到 `confirm.html`，页面需说明确认页暂时显示固定测试数据。

| 项目 | 控件 | 要求 |
| --- | --- | --- |
| 休暇種別 | `select` | 必填；有給休暇、半日休暇（午前）、半日休暇（午後）、特別休暇 |
| 開始日 | 日期框 | 必填 |
| 終了日 | 日期框 | 必填 |
| 申請理由 | `textarea` | 必填；最多 200 字符 |
| 引継ぎ状況 | 同组单选框 | 必填；対応済、対応不要；默认不选择 |
| 連絡事項 | `textarea` | 选填；最多 300 字符 |

使用 `fieldset` 和 `legend` 对单选框分组。选项值使用 `paid`、`half-am`、`half-pm`、`special` 等稳定英文值。

### 7.3 LEAVE-002：申請内容確認

在 `confirm.html` 使用定义列表或表格显示固定测试数据：有給休暇、2026年8月24日至25日、2日、私用、引继完成。明确标注“画面確認用のサンプルデータ”。提供“修正する”和“申請する”两个操作，分别前往 `apply.html` 和 `complete.html`。

### 7.4 LEAVE-003：申請完了

在 `complete.html`：

- 显示“申請が完了しました”。
- 显示固定测试受付番号 `REQ-20260820-001`。
- 说明 HTML 阶段没有把申请保存到服务器或浏览器。
- 提供返回首页和申请一览的链接。

### 7.5 LEAVE-004：申請一覧

在 `applications.html` 使用带有 `caption`、`thead`、`tbody` 和列标题的表格显示三条测试数据：

| 受付番号 | 休暇種別 | 休暇期間 | 申請日数 | 状態 |
| --- | --- | --- | --- | --- |
| REQ-20260710-001 | 有給休暇 | 2026/07/24 | 1日 | 承認済 |
| REQ-20260801-001 | 半日休暇（午後） | 2026/08/07 | 0.5日 | 承認済 |
| REQ-20260812-002 | 有給休暇 | 2026/08/22～2026/08/23 | 2日 | 申請中 |

状态文字必须直接显示。页面说明筛选、登录用户数据分离和取消功能将在 JavaScript 阶段实现。

## 8. 实现顺序

1. 创建七个 HTML 文件和不同的页面标题。
2. 完成登录页与注册页的表单。
3. 完成五个业务页面的共通导航。
4. 完成首页、申请表、确认页和完成页。
5. 完成申请一览表。
6. 逐页执行链接、表单、键盘和 HTML 结构检查。

- [ ] 七个 HTML 文件都存在并能直接打开。
- [ ] 登录和注册表单不会用 GET 提交密码。

- [ ] 注册包含账号、密码、确认密码、姓名和所属，不允许输入社员番号。
- [ ] 所有标签、`id`、`name` 和选项值对应正确。
- [ ] 空表单会被浏览器原生验证阻止。
- [ ] 五个业务页面可以通过导航互相访问并返回登录页。
- [ ] 申请表、确认信息和一览数据保持一致。
