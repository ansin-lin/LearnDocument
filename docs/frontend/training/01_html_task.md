# HTML 递进练习：有給休暇申請システム

## 1. 任务定位

你将为日本企业内部使用的“有給休暇申請システム”制作五个 HTML 页面。本阶段只完成页面结构、业务内容和画面迁移，不编写 CSS 和 JavaScript。

页面使用日文，任务说明使用中文。完成本阶段后，即使页面保持浏览器默认样式，使用者也应能够理解每个页面的用途、通过导航访问所有页面，并使用浏览器自带的表单验证完成一次申请操作。

## 2. 开始状态

新建以下目录和文件：

```text
paid-leave-system/
├─ index.html
├─ apply.html
├─ confirm.html
├─ complete.html
└─ applications.html
```

本阶段不得创建或使用 CSS、JavaScript、前端框架和组件库。

系统供公司员工提交带薪休假申请。当前使用者固定为以下测试员工：

| 氏名 | 山田 太郎 |

| 取消済 | 已取消 |

## 4. 共通画面规格

五个页面都必须满足以下要求：

- 使用完整的 HTML 文档结构，并声明 `lang="ja"` 和 UTF-8。
- 设置适合移动设备的 `viewport`。
- 每页具有不同且能说明用途的 `title` 和 `meta description`。
- 页面主体按 `header`、`nav`、`main`、`footer` 的顺序组织。
- 每页只有一个 `h1`，后续标题层级连续。
- 共通导航包含“ホーム”“休暇申請”“申請一覧”。
- 当前页面不能只通过颜色或装饰来表示；可以使用文本说明或 `aria-current="page"`。
- 站内链接全部使用相对路径，并且不能出现无法打开的链接。
- 页面中的按钮使用 `button`，页面跳转使用 `a`，不能用普通文本或 `div` 代替。
- 不添加没有实际用途的 ARIA 属性，优先使用原生语义元素。

## 6. 各画面任务

### 6.1 HOME-001：ホーム

在 `index.html` 中完成以下内容：

- 显示系统名称“有給休暇申請システム”。
- 使用定义列表展示社員番号、氏名和所属。
- 显示“有給残日数：12日”，数字部分使用适合强调的语义标签。
- 创建“休暇を申請する”和“申請一覧を確認する”两个入口。
- 创建“お知らせ”区域，使用列表显示以下内容：
  - 休暇申请原则上需要在休假日前三个营业日提交。
  - 紧急情况请联系直属上司。
- 显示基准日期，但不得写成“系统自动取得”；HTML 阶段直接使用指定日期 `2026年8月18日`。

### 6.2 LEAVE-001：休暇申請

在 `apply.html` 中创建表单。表单使用 `method="get"`，提交目标为 `confirm.html`。

| 表单项目 | HTML 要求 | 业务要求 |
| --- | --- | --- |
| 休暇種別 | `select` | 必填；选项为有給休暇、半日休暇（午前）、半日休暇（午後）、特別休暇 |
| 開始日 | `input type="date"` | 必填 |
| 終了日 | `input type="date"` | 必填 |
| 申請理由 | `textarea` | 必填；最多 200 字符 |
| 引継ぎ状況 | 同组单选框 | 必填；选项为対応済、対応不要 |
| 連絡事項 | `textarea` | 选填；最多 300 字符 |

表单还必须满足：

- 每个控件都有唯一的 `id`、稳定的 `name` 和可关联的 `label`。
- 选项的 `value` 使用稳定的英文值，例如 `paid`、`special`，不能使用 `value="1"` 这类含义不明的值。
- 单选框使用 `fieldset` 和 `legend` 分组，默认不选择。
- 必填项同时具有文字提示和 `required`，不能只用星号表示。
- “入力内容を確認する”使用提交按钮。
- “戻る”使用返回首页的链接，不能伪装成提交按钮。
- 在表单附近说明：本阶段只使用 HTML，确认页暂时显示固定测试数据，动态传值将在 JavaScript 阶段完成。

| 项目 | 测试数据显示值 |
| --- | --- |
| 休暇種別 | 有給休暇 |
| 開始日 | 2026年8月24日 |
| 終了日 | 2026年8月25日 |
| 申請日数 | 2日 |
| 申請理由 | 私用のため |
| 引継ぎ状況 | 対応済 |
| 連絡事項 | 緊急連絡はメールで確認します。 |

要求如下：

- 使用定义列表或表格表达“项目—值”的对应关系。
- 明确显示“現在は画面確認用のサンプルデータです”。
- 提供“修正する”链接，返回 `apply.html`。
- 使用一个表单和提交按钮前往 `complete.html`，按钮文字为“申請する”。
- 不使用 JavaScript 模拟数据传递，也不声称输入内容已经保存。

### 6.4 LEAVE-003：申請完了

在 `complete.html` 中完成以下内容：

- 主标题为“申請が完了しました”。
- 显示固定测试受付番号 `REQ-20260818-001`。
- 说明当前 HTML 练习没有把申请保存到服务器。
- 提供返回首页和打开申请一览的链接。
- 不自动跳转页面。

### 6.5 LEAVE-004：申請一覧

在 `applications.html` 中使用表格显示以下三条测试数据：

| 受付番号 | 休暇種別 | 休暇期間 | 申請日数 | 状態 |
| --- | --- | --- | --- | --- |
| REQ-20260710-001 | 有給休暇 | 2026/07/24 | 1日 | 承認済 |
| REQ-20260801-001 | 半日休暇（午後） | 2026/08/07 | 0.5日 | 承認済 |
| REQ-20260812-002 | 有給休暇 | 2026/08/22～2026/08/23 | 2日 | 申請中 |

要求如下：

- 表格必须具有 `caption`、`thead` 和 `tbody`。
- 列标题使用 `th scope="col"`。
- 状态文字必须直接出现在页面中，不能只通过图标表达。
- 表格下方说明：筛选和取消操作将在 JavaScript 阶段实现。
- 提供“新規申請”链接，前往 `apply.html`。

## 7. 实现顺序

1. 创建五个文件并写入不同的文档标题。
2. 完成五个页面共通的页眉、导航和页脚。
3. 完成首页的员工信息和入口。
4. 完成申请表，并核对所有 `label`、`id`、`name` 和 `value`。
5. 完成确认页和完成页的静态迁移。
6. 完成申请一览表。
7. 使用键盘和浏览器逐页检查。

## 8. 验收测试

### 8.1 页面与导航

- [ ] 五个 HTML 文件都能直接打开。
- [ ] 从每个页面都能访问首页、申请页和一览页。
- [ ] 页面不存在错误路径和空链接。
- [ ] 每页只有一个明确的 `h1`。

### 8.2 表单

- [ ] 空表单不能提交。
- [ ] 点击标签可以聚焦或选择对应控件。
- [ ] 引継ぎ状況一次只能选择一个，并且默认不选择。
- [ ] 申請理由超过 200 字符时不能继续输入。
- [ ] 正确填写后可以打开确认页。

### 8.3 语义与可用性

- [ ] 只用键盘可以完成导航和表单填写。
- [ ] 表格的标题、列标题和数据关系明确。
- [ ] HTML 检查工具没有未处理的结构错误。
- [ ] 页面没有使用 CSS 或 JavaScript。
