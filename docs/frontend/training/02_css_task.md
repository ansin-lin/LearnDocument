# CSS 递进练习：有給休暇申請システム

## 1. 任务定位

继续使用 HTML 阶段完成的五个页面，为系统建立统一、清晰、适合日本企业内部业务系统的视觉样式。本阶段只处理表现层，不实现数据保存、状态筛选和动态画面迁移。

完成后，五个页面应具有一致的页眉、导航、表单、表格和按钮样式，并能在电脑和手机宽度下正常阅读与操作。

## 2. 前置状态

开始前确认 HTML 阶段的五个页面已经通过验收：

```text
paid-leave-system/
├─ index.html
├─ apply.html
├─ confirm.html
├─ complete.html
└─ applications.html
```

在不删除原有语义结构和业务内容的前提下，将目录扩展为：

```text
paid-leave-system/
├─ index.html
├─ apply.html
├─ confirm.html
├─ complete.html
├─ applications.html
└─ css/
   └─ style.css
```

五个页面共用一个 `css/style.css`。每个页面都在 `head` 中使用正确的相对路径加载该文件。

## 3. 修改边界

- 可以为选择样式添加必要的 `class`，但不能把语义元素全部改成 `div`。
- 不允许使用行内样式、`style` 标签、CSS 框架或组件库。
- 不允许添加 JavaScript 或依赖 JavaScript 才能显示的内容。
- 不修改申请字段、测试数据、状态名称和页面迁移关系。
- 不使用 `!important` 作为默认解决办法。
- 所有尺寸和间距都应能够说明用途，避免为了对齐截图堆叠无规律的魔法数。

## 4. 设计基准

界面采用稳重、易读的公司内部系统风格：

| 用途 | 建议值 |
| --- | --- |
| 主色 | 深蓝色，例如 `#1f4e79` |
| 页面背景 | 浅灰色，例如 `#f4f6f8` |
| 内容背景 | 白色 |
| 正文颜色 | 接近黑色，不使用纯浅灰正文 |
| 错误或必填提示 | 深红色，并同时保留文字 |
| 成功提示 | 深绿色，并同时保留文字 |
| 最大内容宽度 | 约 960～1100px |
| 最小支持宽度 | 360px |

在 `:root` 中定义颜色、间距、圆角等重复使用的自定义属性。项目必须保持足够的文字与背景对比度。

## 5. 共通样式任务

### 5.1 基础与盒模型

- 全局设置 `box-sizing: border-box`。
- 清楚设置页面的字体、行高、背景和正文颜色。
- 限制正文最大宽度，并让内容在页面中水平居中。
- 区分外边距和内边距的用途，不依赖空段落制造间距。
- 页面内容较少时，页脚也不能覆盖正文。

### 5.2 页眉和导航

- 页眉在五个页面中保持相同高度、颜色和内容宽度。
- 使用 Flexbox 排列系统名称与导航。
- 导航链接具有默认、悬停、键盘焦点和当前页面状态。
- 当前页面状态不能只依赖颜色，还应保留 HTML 中的 `aria-current="page"`。
- 窄屏下允许导航换行，不能让文字被截断或重叠。

### 5.3 共通组件

为以下元素建立可复用的类，而不是按页面复制样式：

- 页面标题区域
- 白色内容面板
- 主要按钮
- 次要按钮或返回链接
- 必填标记和帮助文字
- 状态标签
- 成功完成区域

相同职责的按钮应保持相同外观，不要为每个页面建立独立按钮样式。

## 6. 各画面样式任务

### 6.1 HOME-001：ホーム

- 员工信息与剩余天数组成一个清晰的信息面板。
- 宽屏时可以左右排列，窄屏时改为上下排列。
- “休暇を申請する”和“申請一覧を確認する”显示为两个大小一致的入口卡片。
- 入口卡片可以使用 Grid；在 360px 宽度下变为单列。
- “お知らせ”保持列表语义，并与操作入口形成明显层次。

### 6.2 LEAVE-001：休暇申請

- 表单标签显示在控件上方。
- 文本框、日期框、下拉框和文本域具有统一的边框、圆角和内边距。
- “開始日”和“終了日”宽屏时使用两列 Grid，窄屏时使用一列。
- 单选框与标签保持足够点击空间，不能只缩小成难以点击的圆点。
- 帮助文字、必填提示和普通正文具有不同但清晰的视觉层级。
- 提交与返回操作在宽屏时靠右排列，在窄屏时改为适合触控的整行按钮。

### 6.3 LEAVE-002：申請内容確認

- “项目—值”区域使用两列结构展示。
- 项目名称区域具有统一背景，值区域允许长文本自然换行。
- 360px 宽度下改为上下排列，不能出现横向页面滚动。
- “サンプルデータ”提示应明显，但不能伪装成错误信息。

### 6.4 LEAVE-003：申請完了

- 完成内容居中显示在独立面板中。
- 受付番号使用单独区域强调，并允许长编号换行。
- 成功状态同时使用图形和文字，不能只显示一个绿色图标。
- 返回首页和申请一览的操作层级清楚。

### 6.5 LEAVE-004：申請一覧

- 表头与数据行具有清楚的边界和对齐关系。
- 状态显示为标签，并为 `申請中`、`承認済`、`差戻し`、`取消済` 设置不同样式。
- 每个状态标签必须保留状态文字，颜色不是唯一信息来源。
- 小屏幕下将表格放入可横向滚动的容器，不能压缩到内容重叠。
- 键盘焦点和长受付番号不能被容器裁切。

## 7. 响应式与可访问性要求

至少检查以下三种视口：

| 检查宽度 | 目标 |
| --- | --- |
| 360px | 手机竖屏，表单和导航仍可操作 |
| 768px | 平板宽度，布局没有异常空白 |
| 1280px | 电脑宽度，内容不过度拉伸 |

还必须完成以下检查：

- 浏览器缩放到 200% 后，正文和操作不会重叠。
- 所有链接、按钮和表单控件具有明显的 `:focus-visible` 状态。
- 鼠标悬停不是显示重要信息的唯一方式。
- 长姓名、长申请理由和长受付番号能够换行或安全滚动。
- 不使用固定高度裁切可能增长的正文。
- 如果添加动画，应在 `prefers-reduced-motion` 下停止或减弱动画。

## 8. 实现顺序

1. 在五个页面加载同一个样式文件。
2. 完成全局盒模型、字体、颜色和内容宽度。
3. 完成共通页眉、导航、面板和按钮。
4. 完成首页和表单布局。
5. 完成确认、完成和一览页面。
6. 添加响应式规则。
7. 检查键盘焦点、长文本、缩放和不同屏幕宽度。

## 9. 验收测试

### 9.1 文件与加载

- [ ] 五个页面都正确加载 `css/style.css`。
- [ ] 删除 CSS 引用后，HTML 内容仍然按合理顺序阅读。
- [ ] 项目没有行内样式、CSS 框架和 JavaScript。

### 9.2 一致性

- [ ] 页眉、导航、面板和按钮在五页中保持一致。
- [ ] 相同状态在不同位置使用相同颜色和文字规则。
- [ ] 表单控件的高度、边框和字体一致。

### 9.3 布局

- [ ] 360px、768px 和 1280px 下均可操作。
- [ ] 页面没有意外的整体横向滚动。
- [ ] 申请一览表在窄屏下可以单独横向滚动。
- [ ] 200% 缩放后没有文字或按钮重叠。

### 9.4 操作状态

- [ ] 键盘焦点清楚可见。
- [ ] 悬停状态不会引起明显布局跳动。
- [ ] 当前页面、必填、状态和完成结果不只通过颜色表达。

## 10. 日本项目式改修任务

收到 Review 指摘：

> 申請一覧はノートPCで確認することが多い。画面全体を横スクロールさせず、一覧部分だけをスクロール可能にしてください。また、受付番号と状態は常に確認できること。

完成以下工作：

1. 确认主要影响文件为 `applications.html` 和 `css/style.css`。
2. 为表格添加具有明确职责的滚动容器。
3. 在 768px 和 360px 下验证页面主体没有横向滚动。
4. 确认表格滚动时受付番号和状态文字仍能通过操作查看。
5. 记录修改前症状、修改位置、测试宽度和结果。
