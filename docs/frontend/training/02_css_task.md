# CSS 递进练习：有給休暇申請システム

## 1. 任务目标

继续使用 HTML 阶段完成的七个页面，为系统建立统一、易读、适合日本企业内部业务系统的视觉样式。本阶段只处理表现层，不实现注册、登录、数据保存和动态画面迁移。

完成后，公开认证页面与登录后的业务页面应具有清楚的视觉区别，同时保持同一套颜色、字体、表单和按钮规则。

## 2. 前置状态与目录

开始前确认已有以下文件：

├─ register.html
├─ index.html

├─ complete.html

新增一个共用样式文件：

七个页面都使用正确相对路径加载 `css/style.css`。

## 3. 修改边界

- 可以添加必要的 `class`，但不能破坏 HTML 的语义结构和表单关联。
- 不使用行内样式、`style` 标签、CSS 框架、组件库和 JavaScript。
- 不修改字段名称、选项值、测试数据和页面迁移关系。
- 不使用 `!important` 作为默认修复方法。
- 不通过 CSS 隐藏必填说明、安全说明或错误信息占位区域。

## 4. 共通设计基准

在 `:root` 中定义重复使用的颜色、间距、圆角和阴影：

| 用途 | 建议值 |
| --- | --- |
| 主色 | 深蓝，例如 `#1f4e79` |
| 页面背景 | 浅灰，例如 `#f4f6f8` |
| 内容背景 | 白色 |
| 正文 | 接近黑色 |
| 错误或必填 | 深红，并保留文字 |
| 成功 | 深绿，并保留文字 |
| 最大内容宽度 | 960～1100px |
| 最小支持宽度 | 360px |

全局设置 `box-sizing: border-box`，明确字体、行高、背景、正文颜色和内容最大宽度。不要用空段落制造间距，也不要使用固定高度裁切可能增长的内容。

## 5. 公开认证页面样式

### 5.1 登录页

- 登录区域在电脑宽度下显示为居中的单列卡片，宽度约 400～480px。
- 系统名称、页面标题、说明、表单和注册链接层次清楚。
- 账号和密码控件占满卡片可用宽度。
- “ログイン”是主要按钮，注册链接是次要操作。
- 安全提示保持可读，不能使用过浅文字。

### 5.2 注册页

- 注册表单使用与登录页一致的认证卡片风格，但允许更宽。
- 字段较多时保持稳定的垂直节奏。
- 所属下拉框、密码帮助文字和社员番号说明清楚分组。
- “登録する”和“ログインへ戻る”具有明确的主次关系。
- 360px 下所有控件和按钮均不超出屏幕。

### 5.3 认证页面共通要求

- 认证页不显示登录后导航，避免混淆当前状态。
- 登录与注册卡片使用同一组类，不复制两套近似样式。
- 键盘焦点必须明显，密码控件不能因浏览器自动填充而出现不可读文字。
- 错误消息区域预留自然增长空间，但不使用固定高度留出大块空白。

## 6. 登录后业务页面样式

### 6.1 页眉与导航

- 使用 Flexbox 排列系统名称、导航和登录用户区域。
- 登录用户区域预留“山田 太郎 / EMP-00001”和“ログアウト”位置。
- 窄屏下允许合理换行，不截断姓名或社员番号。
- 当前页面具有可见状态，同时保留 `aria-current="page"`。

### 6.2 首页

- 员工资料、有給残日数和申请件数组成信息面板。
- 操作入口使用两列 Grid，360px 下变为一列。
- 长姓名和长所属名称可以换行。

### 6.3 申请与确认

- 标签显示在控件上方；文本框、日期框、下拉框和文本域样式一致。
- 开始日与结束日在宽屏下两列、窄屏下一列。
- 单选项具有足够点击空间。
- 确认页“项目—值”宽屏下两列、窄屏下上下排列。
- 主要提交、返回和修正操作具有一致样式。

### 6.4 完成与一览

- 完成信息居中显示，受付番号单独强调并允许换行。
- 申请状态显示为带文字的状态标签，颜色不是唯一信息来源。
- 一览表放入独立横向滚动容器，不能让整个页面横向滚动。
- 长受付番号、长日期范围和操作按钮不能互相覆盖。

## 7. 共通组件要求

建立并复用以下样式，不为每个页面复制近似规则：

- 页面容器与内容面板
- 认证卡片
- 页面标题区域
- 表单组、帮助文字和错误文字
- 主要按钮、次要按钮和危险操作按钮
- 员工信息与数字汇总卡片
- 申请状态标签
- 成功提示和普通通知
- 表格滚动容器

## 8. 响应式与可访问性检查

| 检查宽度 | 合格结果 |
| --- | --- |
| 360px | 登录、注册和申请表可完整操作 |
| 768px | 导航、用户信息和表格没有重叠 |
| 1280px | 内容不过度拉伸，阅读宽度合理 |

还必须确认：

- 浏览器缩放至 200% 时，文字、表单和按钮不重叠。
- 链接、按钮和控件具有明显的 `:focus-visible`。
- 鼠标悬停不是获取重要信息的唯一方式。
- 自动填充后的账号和密码仍清晰可读。
- 长姓名、长所属和长申请理由能换行或安全滚动。
- 动画在 `prefers-reduced-motion` 下停止或减弱。

## 9. 实现顺序

1. 七个页面加载同一个 CSS 文件。
2. 完成盒模型、字体、颜色和内容宽度。
3. 完成登录与注册的认证卡片。
4. 完成业务页眉、导航、面板和按钮。
5. 完成首页、申请、确认、完成和一览页面。
6. 添加响应式规则并执行缩放、键盘和长文本测试。

## 11. 日本项目式改修任务

Review 指摘：

> 登録画面の項目数が多く、スマートフォンで登録ボタンを見失いやすい。項目の順序は変更せず、入力のまとまりと主要操作が分かるように修正してください。

调查 `register.html` 和 `css/style.css`，通过分组、间距和按钮层级改善页面。不得使用固定在屏幕上的按钮遮挡输入框。完成后在 360px、键盘操作和 200% 缩放下复测。
