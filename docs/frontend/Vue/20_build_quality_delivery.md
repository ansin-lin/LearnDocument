# 第 20 章 构建、质量与项目交付

## 本章目标

- 【必须掌握】完成Lint、类型检查、单元测试、构建和预览。
- 【必须掌握】判断何时依赖类型推断、何时显式标注Vue与业务类型，并避免滥用类型逃生写法。
- 【必须掌握】检查Git差异并提交可复现的README与自测证据。
- 【会使用、能看懂】根据失败命令、浏览器工具和日志定位问题。

## 前置知识

需要已完成WorkHub主要功能，并掌握npm脚本、Git和第19章测试基础。

## 1. 什么叫可以交付

“我的页面能打开”不足以证明项目可交付。团队成员还需要能够重建依赖、运行检查、理解变更并复现验证结果。

```text
开发完成 → 自测 → Lint → Type Check → Unit Test
→ Build → Preview → Review → 修正 → 回归测试
```

## 2. Vue + TypeScript项目规范与常见类型问题

TypeScript已经贯穿本课程，不需要在交付前重新迁移。这里统一整理Review时最常遇到的判断：

| 场景 | 推荐写法或判断 |
| --- | --- |
| 初始值已明确 | `const loading = ref(false)`，优先类型推断 |
| 空数组无法推断元素 | `ref<Task[]>([])` |
| 尚未取得对象 | `ref<Task | null>(null)` |
| 表单对象需要固定结构 | `reactive<TaskForm>({...})` |
| 组件输入与输出 | `defineProps<T>()`、`defineEmits<T>()` |
| 输入组件值 | `defineModel<string>()` |
| Template Ref | 指定`HTMLInputElement`等DOM类型并处理`null` |
| Router参数 | 先按外部字符串处理，再转换和验证 |
| API响应 | 先接收`unknown`，运行时检查后返回业务类型 |
| 只导入类型 | 使用`import type`表达不会产生运行时代码 |

`any`会关闭检查，`as`只是告诉编译器“相信我”，非空断言`!`也不能让运行时值自动存在。三者只在边界已被其他逻辑证明且理由明确时谨慎使用，不能用来让报错暂时消失。

公共业务类型集中在`src/types/`，不要在组件、Store和测试中分别维护近似的`Task`。Pinia的state用明确元素类型，action参数和返回值表达业务契约；Props、Emits和组件v-model也应使用同一公共类型。

`vue-tsc`会检查`.ts`和`.vue`模板之间的类型关系，生产Build负责生成可部署资源。两者目的不同，因此必须分别执行`npm run type-check`和`npm run build`。TypeScript只在开发期检查源码，不能代替第17章对服务器真实响应的运行时验证。

## 3. 交付前命令

在包含`package.json`的项目目录执行，脚本名称以仓库实际配置为准：

```bash
npm run lint
npm run type-check
npm run test:unit
npm run build
npm run preview
```

| 命令 | 验证内容 | 成功证据 |
| --- | --- | --- |
| `lint` | 代码规则与常见错误 | 命令退出且无错误 |
| `type-check` | `.ts`和`.vue`中的类型关系 | `vue-tsc`退出且无类型错误 |
| `test:unit` | 自动化行为测试 | 全部用例通过 |
| `build` | 生产构建 | 生成`dist`且无错误 |
| `preview` | 本地预览构建结果 | 主要页面、刷新和路由正常 |

某个项目没有对应脚本时，应先查看README和`package.json`，不要凭空假设命令存在。

## 4. Review前检查

```bash
git status
git diff
```

确认只包含任务范围内的文件；删除临时`console.log`、测试账号、临时URL和无关格式化。不提交真实密钥、令牌、`.env`中的秘密或`node_modules`。锁文件是否提交遵守仓库规则，不能随意删除。

Review说明至少写明：改了什么、为什么改、影响哪些页面、如何验证、仍有哪些限制。收到指摘后修正，并对相关功能执行回归测试。

## 5. 浏览器调查

- Console：检查未处理异常、Vue警告和失败导入。
- Network：检查请求URL、方法、状态、请求体、响应和耗时。
- Elements：检查最终DOM、属性、焦点和显示状态。
- Vue DevTools：检查组件、Props、事件和Pinia状态。

截图不能替代错误文字和复现步骤。报告问题时记录操作顺序、预期结果、实际结果及相关日志。

## 6. 安全与无障碍底线

- 前端环境变量会进入浏览器资源，不能保存真正的秘密。
- 前端校验、隐藏按钮和Router Guard不能代替后端校验与权限控制。
- 表单控件具有可关联label，按钮可通过键盘操作，错误信息可以理解。
- 异步操作显示加载状态，失败后提供可恢复方式，避免永久loading。
- 不必要的动画应尊重减少动态效果偏好。

## 7. README与交付物

README至少包含项目说明、环境要求、安装与启动方法、目录结构、主要功能、API说明、测试方法和已知限制。不要写入真实内部地址或账号。

交付物包括源码、锁文件、README、自测结果和必要截图。`dist`是否提交由项目发布方式决定。
