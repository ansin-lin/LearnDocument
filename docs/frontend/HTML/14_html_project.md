# HTML 新人综合练习：公司技术交流会报名网站

本章是一次独立练习。请根据下面的任务要求完成一个只使用 HTML 的多页面网站，并完成自测记录。

完成前不要查看第十五章参考答案。第十五章只用于你提交自测结果后的核对，不作为本章的复制来源。

## 1. 任务背景

公司计划举办一次面向项目开发新人的技术交流会，需要一个简单的报名网站。你负责用 HTML 制作页面结构，让浏览器能够正确显示活动信息、日程、报名表和提交完成提示。

本练习不要求制作漂亮外观。页面保持浏览器默认样式，不添加 CSS，不添加 JavaScript。

## 2. 你需要提交的成果

请在 `html-event-site/` 目录中整理并提交以下文件：

```text
html-event-site/
├─ index.html
├─ schedule.html
├─ register.html
├─ success.html
└─ images/
   ├─ meeting-room.jpg
   └─ favicon.ico
```

必须完成的文件：

- `index.html`：活动首页
- `schedule.html`：活动日程页
- `register.html`：活动报名页
- `success.html`：报名完成页
- `images/meeting-room.jpg`：会场图片

`favicon.ico` 是选做文件。如果你没有准备图标文件，请删除页面中的图标 `link`，不要保留指向不存在文件的路径。

会场图片请使用自己有权使用的图片，并命名为 `meeting-room.jpg`。

## 3. 通用制作要求

四个 HTML 页面都必须满足以下要求：

- 使用完整 HTML 文档骨架
- 声明 `lang="zh-CN"`
- 使用 UTF-8 字符编码
- 设置 `viewport`
- 每个页面有不同的 `title`
- 每个页面有符合当前页面内容的 `description`
- 页面正文按照 `header`、`nav`、`main`、`footer` 的顺序组织
- 导航能够到达首页、日程页和报名页
- 每页只有一个页面主标题 `h1`
- 链接文字要能说明点击后的目标
- 不使用 CSS
- 不使用 JavaScript

## 4. 页面制作要求

### 4.1 首页 `index.html`

请在首页完成以下内容：

- 显示活动名称和活动介绍
- 显示活动时间、地点和报名截止日期
- 显示会场图片
- 为会场图片编写合适的替代文本
- 使用无序列表展示分享主题
- 使用有序列表展示报名步骤
- 显示参加提示
- 显示负责人邮箱

### 4.2 日程页 `schedule.html`

请在日程页使用表格展示活动安排。表格必须包含：

- 时间
- 主题
- 讲师

表格结构必须满足以下要求：

- 使用 `caption` 说明表格内容
- 列标题使用 `th scope="col"`
- 最后一项“全体提问与交流”需要横跨“主题”和“讲师”两列
- 表格只用于展示日程数据，不用于页面布局

### 4.3 报名页 `register.html`

请在报名页制作报名表。表单必须满足以下要求：

- 提交后打开 `success.html`
- 姓名为必填，长度为 2 到 40 个字符
- 员工编号为必填，长度为 4 到 10 个字符
- 邮箱为必填，并使用 `type="email"`
- 部门为必填
- 参加方式使用同一组单选框
- 希望主题使用复选框
- 问题输入使用 `textarea`
- 所有控件都有可以关联的 `label`
- `label`、`id`、`name`、`value` 和控件用途保持一致

### 4.4 完成页 `success.html`

请在完成页完成以下内容：

- 明确显示“报名完成”
- 提醒使用者：本地 HTML 示例不会真正保存报名数据
- 提供返回首页的链接
- 提供再次打开报名页的链接

## 5. 建议实施顺序

请按下面顺序完成，不要先写完某一个页面再回头猜公共结构：

1. 确认四个 HTML 文件位于同一级目录。
2. 确认 `images/meeting-room.jpg` 路径正确。
3. 为四个页面写入完整文档骨架。
4. 为四个页面设置不同的 `title` 和 `description`。
5. 完成所有页面共用的导航。
6. 完成首页正文。
7. 完成日程表。
8. 完成报名表和表单验证属性。
9. 完成报名完成页。
10. 逐页打开浏览器检查显示结果。
11. 执行导航、图片、表格、表单和键盘测试。
12. 使用 HTML 检查工具检查四个文件。

## 6. 自测要求

### 6.1 导航测试

请从每个页面依次点击：

1. 活动首页
2. 活动日程
3. 活动报名

合格条件：不出现找不到文件、跳错页面或链接文字含义不清的问题。

### 6.2 图片测试

请完成以下检查：

1. 首页会场图片可以正常显示。
2. 临时把 `src` 改成错误路径，确认替代文本能够说明图片内容或用途。
3. 恢复正确路径。
4. 图片没有明显变形。

合格条件：图片路径正确，失效时仍能通过替代文本理解图片含义。

### 6.3 表格测试

请完成以下检查：

1. 表格有可见标题。
2. 三个列标题与数据对应。
3. 14:30 的新增日程位置正确。
4. 最后一行没有多余空单元格。

合格条件：表格结构能准确表达时间、主题和讲师的关系。

### 6.4 表单测试

请完成以下检查：

1. 空表单不能直接提交。
2. 点击每个标签都能操作正确控件。
3. 单选框只能选择一个参加方式。
4. 复选框可以选择多个主题。
5. 错误邮箱不能提交。
6. 正确填写后打开完成页。
7. 地址栏中的参数名与表单控件的 `name` 一致。

合格条件：表单字段、标签、验证属性和提交目标都符合规格。

### 6.5 键盘测试

请只使用键盘完成以下操作：

1. 浏览三个导航链接。
2. 填写姓名、员工编号和邮箱。
3. 选择部门和参加方式。
4. 勾选希望主题。
5. 提交表单。

合格条件：链接和表单控件可以按照阅读顺序操作，不依赖鼠标才能完成报名流程。

## 7. HTML 验收标准

| 验收项 | 合格条件 |
| --- | --- |
| 文件 | 4 个 HTML 文件均存在并能打开 |
| 文档结构 | 每页有 `doctype`、`html`、`head`、`body` |
| 元数据 | 每页语言、编码、视口、标题和说明正确 |
| 标题 | 每页一个明确 `h1`，后续标题层级合理 |
| 导航 | 所有站内链接路径正确 |
| 图片 | `src` 正确，`alt` 符合图片用途 |
| 列表 | 列表项正确嵌套在列表中 |
| 表格 | 只用于日程数据，表头与数据关系明确 |
| 表单 | 标签、`id`、`name`、`value` 和类型一致 |
| 验证 | 必填、长度和邮箱检查符合规格 |
| 语义 | 使用原生标签表达内容职责 |
| 键盘 | 链接和表单可以按阅读顺序操作 |
| 检查工具 | 没有未处理的 HTML 结构错误 |

## 8. SES 改修任务

完成基础页面后，请继续处理下面的变更规格。

收到的变更规格：

> 活动新增“上午场”和“下午场”。报名者必须选择其中一个，默认不选择。

请先判断影响范围，再修改文件。

本次改修要求：

1. 只修改 `register.html`。
2. 在报名表中添加一个新的 `fieldset`。
3. `legend` 写“参加场次（必填）”。
4. 两个单选框使用相同 `name="session"`。
5. 两个单选框的 `value` 分别为 `morning` 和 `afternoon`。
6. 两个选项都不写 `checked`。
7. 使用 `required` 保证必须选择一个场次。
8. 自测空表单、上午场和下午场三种提交情况。
9. 在交付记录中写明修改文件和测试结果。

不要修改日程页中不存在的业务内容。完成影响调查后，应能说明：本次变更只需要修改 `register.html`。
