# 第 6 章：Linux 网络、SSH 与远程服务器操作

完成本章后，你应能说明 IP、端口和服务的关系，读懂 `ping`、`curl`、`ss`、`ssh`、`scp` 的常用写法，并根据模拟证据初步判断访问故障。先学习[第 5 章](05_process_system.md)的进程与服务概念。查看本机网络信息和分析示例是基础学习；实际 SSH 登录、文件传输与密钥配置仅在有教师提供的独立练习主机时选做。以下命令以 Bash 为例，不要求在线环境提供 SSH 服务器、systemd 或运行中的 Java 应用。

## 6.1 网络基础：从浏览器到 Java 进程

**IP 地址**标识网络上的目标地址，**端口**区分同一主机上的服务，**TCP**负责建立可靠连接，**HTTP**是浏览器与 Web 应用交换请求/响应的协议；**DNS**把域名解析为地址。详细 HTTP 基础见[Web 基础课程](../../web_basics/01_http_rest_cookie_cors.md)。

```text
浏览器／React ── HTTP 到测试主机:8080 ──> Linux 上监听的 Spring Boot 进程
                                              │
                                              └── 项目中可能再访问数据库
```

这是定位问题用的简化图，省略了常见的反向代理、TLS、负载均衡等组件。第 7～8 章的练习 API **没有数据库**。进程存在、端口监听、HTTP 有响应和业务接口成功是不同的检查结果。

## 6.2 查看 Linux 网络信息

在已获准使用的 Linux 终端运行：

```bash
ip addr
ip route
```

`ip addr` 列出网络接口及地址；先找实际使用的网卡和 `inet` IPv4 地址，不把 `127.0.0.1` 当作别的机器可访问的地址。`ip route` 显示系统如何把数据发往目标网络；`default via ...` 通常是默认下一跳。两条命令只读，输出因虚拟机网络配置而异；查不到目标地址时先核对所在主机和虚拟机网络方式，不自行修改路由。

## 6.3 网络连通性与 HTTP 请求

只对教师给出的练习主机或本机执行。若在线环境没有运行第 7 章的应用，第二条只需读懂写法与可能的响应：

```bash
ping -c 3 127.0.0.1
curl -i --connect-timeout 3 --max-time 10 http://127.0.0.1:8080/health
```

`ping` 发出 ICMP 探测，`-c 3` 只发三次；能收到回应说明这条探测有响应，但**不代表 8080 端口或 HTTP 服务正常**。有些环境会阻止 ICMP，因此 ping 不通也不能单独证明服务器宕机。第二条只有本机确实启动了第 7 章练习应用时才会返回 HTTP；`-i` 显示响应头与正文，两个超时选项防止请求无期限等待。连接拒绝表示该地址/端口当前没有成功建立连接；收到 `404` 或 `500` 则说明已有 HTTP 响应，调查方向不同。

## 6.4 检查端口监听

```bash
ss -lnt
ss -lntp
```

`ss` 查看套接字信息；`-l` 只看监听、`-n` 用数字显示地址/端口、`-t` 只看 TCP、`-p` 尝试显示进程信息（受当前用户权限限制）。模拟输出 `LISTEN ... 127.0.0.1:8080 ...` 表示只在本机地址监听；外部浏览器不能直接连接这个地址。看到 `0.0.0.0:8080` 表示应用在所有 IPv4 本地接口监听，**仍须核对防火墙、访问控制及实际入口**。端口被别的进程占用时，要先确认归属，不能直接结束它。

## 6.5 SSH 基础

浏览器通过 HTTP 请求 Web 接口；开发者通过 SSH 登录获准使用的主机，在远端执行命令。两者用途不同：能打开网页不表示有 SSH 登录权限，能 SSH 登录也不表示 Web 接口正常。SSH 为远程命令连接提供加密与服务器身份校验；常见默认端口是 TCP 22，但项目可能使用其他端口。登录前需要确认远程用户名、主机地址、SSH 端口、认证方式以及自己是否获准访问。认证可以是密码或公钥；服务器的**主机密钥指纹**用于确认连接的服务器身份，不等于你的登录私钥。第一次连接出现指纹提示时，应按教师/项目提供的可信指纹核对，不能机械输入 `yes`。私钥只留在自己的受控设备，不上传到练习服务器、Git 或聊天记录。主机密钥核对可参照 [OpenSSH 手册](https://man.openbsd.org/ssh.1)。

## 6.6 登录已知练习主机

先读懂最小写法，下面的 `192.0.2.10` 是**文档示例地址**，不是可供登录的服务器，不能原样执行：

```bash
ssh labuser@192.0.2.10
ssh -p 2222 labuser@192.0.2.10
```

`ssh` 发起远程登录；`labuser` 是远程用户名；`@` 后是远程主机地址。未写 `-p` 时通常使用默认 SSH 端口 22；`-p 2222` 指定使用远程端口 2222，实际端口以教师或项目提供的信息为准。两行是不同连接方式，只按目标服务器的配置选择一条。

**选做：连接教师提供的练习主机。**取得实际地址、账号和可信主机指纹后，在**开发机的 Bash 终端**设置目标并登录：

```bash
LAB_HOST='教师提供的主机地址'
ssh -o ConnectTimeout=5 "labuser@$LAB_HOST"
```

`LAB_HOST` 右侧必须替换为实际练习地址；`ssh user@host` 中左边是远端用户名，右边是主机。`ConnectTimeout=5` 限制连接等待秒数。登录成功后提示符会变成远端环境；运行 `whoami`、`hostname`、`pwd` 确认身份和位置，再用 `exit` 退出。`Permission denied` 多指认证未通过，`Connection refused` 表示目标地址/端口拒绝连接，超时则要核对地址、路由或访问控制；三者不能混为一谈。

## 6.7 传输练习文件

`ssh` 用于登录远程主机执行命令；`scp` 用于本机与远程主机之间复制文件；`sftp` 用于进入交互式传输会话。三者都依赖 SSH 连接和认证。下面的 `scp` 以“从开发机上传一个文件”为例，冒号左边是远程主机，右边是远程路径；实际执行仍需教师提供主机。

**选做：传输自己的练习文件。**仅在教师给出的练习账号上操作。先在**开发机 Bash**的个人练习目录准备一个小文件：

```bash
mkdir -p "$HOME/learndoc-linux-lab/output"
cd "$HOME/learndoc-linux-lab/output"
printf 'ssh transfer lab\n' > ssh-note.txt
scp ssh-note.txt "labuser@$LAB_HOST:/home/labuser/ssh-note.txt"
```

`printf` 只创建或覆盖自己练习目录中的 `ssh-note.txt`；`scp 源 目标` 不会删除本地源文件。上传后可 SSH 登录并用 `ls -l ~/ssh-note.txt` 核对远端文件；不要覆盖远端已有项目文件。若项目使用 `sftp`，可输入 `sftp "labuser@$LAB_HOST"` 进入会话，再用会话内的 `put ssh-note.txt` 上传、`bye` 退出；这些命令不在普通 Bash 中输入。本章不要求完成 SFTP 的上传、下载与文件核对全过程。

## 6.8 公钥与私钥

公钥可以按项目流程交给服务器管理员放入授权列表；私钥用于证明“我是对应公钥的持有者”，不能分享。需要生成或登记密钥时遵循项目给出的算法、存储位置与轮换规则；本章不要求在共享主机创建账号或修改 `authorized_keys`。SSH/SCP 遇到认证失败，先核对账号、密钥和授权范围，不关闭主机身份校验。

## 6.9 网络访问控制

Linux 防火墙和云平台**安全组**都可能限制入口流量，但位于不同管理层；学员先识别其存在，不在本章修改策略。若应用仅绑定 `127.0.0.1`，即使放开防火墙也不能让外部直接访问；若绑定了可达地址，还要核对主机防火墙、云安全组、网络路径与反向代理。开放 8080 或 22 并非排障的默认动作。云安全组的入站/出站职责可参照 [AWS 官方说明](https://docs.aws.amazon.com/vpc/latest/userguide/vpc-security-groups.html)。

## 6.10 练习：分层解释“访问不了”

读取以下**模拟证据**：`pgrep -af java` 找到目标进程；`ss -lnt` 显示 `127.0.0.1:8080`；服务器上 `curl -i http://127.0.0.1:8080/health` 返回 `200`，开发机浏览器却无法直接访问 `服务器IP:8080`。请记录三个已确认事实、一个最可能的访问边界，并列出下一步需要向负责人核对的入口方式。参考判断：进程存在、本机端口监听、本机健康请求成功；应用只绑定回环地址是外部直连失败的重要线索，仍需确认项目是否要求经代理或 SSH 隧道访问，不能直接修改绑定地址或防火墙。
