# 选学专题：用户级定时任务

cron 是按时间启动命令的调度程序，crontab 是某个用户保存的任务表。脚本写“做什么”，cron 条目写“何时、由谁启动”。本专题先读懂既有任务；完成 Shell 基础后，且确认是**独立练习环境、允许修改自己的定时任务、cron 正在运行**时，才选做编辑实验。不管理 cron 服务，也不修改其他用户或系统级任务。

## 只读查看任务

```bash
crontab -l
```

`crontab [选项]` 操作**当前用户**的任务表；`-l` 是 list，只列出而不修改。每行前五列是执行时间，后面是执行命令。若显示“no crontab for ...”，表示当前没有任务；其他错误（例如命令不存在或权限不足）不能当作“没有任务”。查看项目批处理前还要确认任务由哪个账号执行；当前用户的 `crontab -l` 看不到别人的任务。

以下备份与编辑步骤只供完成 Shell 基础后的独立练习环境选做：

在允许编辑的独立练习环境中，先创建目录，再单独保存备份并检查状态：

```bash
mkdir -p "$HOME/learndoc-linux-lab/output"
crontab -l > "$HOME/learndoc-linux-lab/output/crontab.backup"
printf 'backup_status=%s\n' "$?"
```

只有原本已有任务且 `backup_status=0` 时，备份才可用于恢复。原本没有任务时，空文件只是练习记录，**不要把它当成可恢复备份**。发生其他错误应停止，保留错误信息并找负责人确认。`crontab -e` 打开当前用户的任务表编辑器；保存会改变实际定时任务，因此仅在上述前提满足时运行。不要使用 `crontab -r` 删除全部任务。

恢复已有备份前必须先阅读内容：

```bash
cat "$HOME/learndoc-linux-lab/output/crontab.backup"
```

如确需恢复，应由教师或负责人先核对备份与当前条目；`crontab <备份文件>` 会**整体替换**当前用户的任务表，不作为日常练习命令。

## 时间格式

下面是 **crontab 条目中的时间字段**，不是可直接在终端执行的 Shell 命令。cron 决定何时启动；条目末尾的脚本或命令决定执行什么。

```text
分钟 小时 日 月 星期 命令
```

```text
*/5 * * * *  每 5 分钟
0 2 * * *    每天 02:00
0 9 * * 1    每周一 09:00
0 3 1 * *    每月 1 日 03:00
```

日期、星期同时受限时的组合行为容易误解，复杂生产计划应按项目手顺确认，不凭记忆配置。
`*` 表示该时间字段的每个取值；`*/5` 在分钟字段表示每 5 分钟一次。读任务时先看前五列，再看后面的脚本路径和输出重定向，不要只凭脚本名判断执行频率。
命令通常在对应用户的环境中运行，但 cron 的工作目录、`PATH` 和其他环境变量可能不同于交互式终端；相对路径可能找错文件。还要核对服务器时区、任务预定时间、标准输出 stdout 和错误输出 stderr 的保存位置；没有这些证据不能单凭日志空白断言任务未启动。

### 日本项目中的ジョブ和ジョブネット

「ジョブ」是一项作业，「ジョブネット」是多项作业的依赖与执行顺序。读障害票时要区分「実行予定（计划时间）」「実行履歴（实际记录）」「正常終了（正常结束）」「異常終了（异常结束）」及「再実行（重新执行）」。一个前置作业失败可能让后续作业未执行。项目可能使用专用调度平台，不一定使用 cron；PG 先查看作业手顺、执行账号、输入输出与状态，不自行重新执行。重跑可能造成重复写入或发送。

## 创建安全练习脚本

先完成 Shell 基础后再执行本节。创建 `~/learndoc-linux-lab/cron_demo.sh`：

```bash
cat > "$HOME/learndoc-linux-lab/cron_demo.sh" <<'EOF'
#!/usr/bin/env bash
printf '%s cron demo\n' "$(date '+%Y-%m-%dT%H:%M:%S')" \
  >> "$HOME/learndoc-linux-lab/output/cron-demo.log"
EOF
chmod u+x "$HOME/learndoc-linux-lab/cron_demo.sh"
```

先手动验证：

```bash
"$HOME/learndoc-linux-lab/cron_demo.sh"
tail -n 1 "$HOME/learndoc-linux-lab/output/cron-demo.log"
```

手动运行成功后，才在 `crontab -e` 中添加：

```text
*/5 * * * * /usr/bin/env bash "$HOME/learndoc-linux-lab/cron_demo.sh" >> "$HOME/learndoc-linux-lab/output/cron-run.log" 2>&1
```

cron 通常会设置 `HOME`，但它的 `PATH` 等执行环境比交互式终端更少。实际项目应按作业手顺确认执行用户、解释器、环境变量和绝对路径；排错时不能只以“手动执行成功”为依据。
条目中的 `/usr/bin/env bash` 选择 Bash 运行脚本；`>>` 追加正常输出，`2>&1` 把错误输出也送到同一文件。若只是阅读项目中的现有条目，不需要新增或修改它。

## 验证与排错

```bash
crontab -l
tail -n 20 "$HOME/learndoc-linux-lab/output/cron-run.log"
tail -n 20 "$HOME/learndoc-linux-lab/output/cron-demo.log"
```

常见原因：绝对路径错误、脚本手动执行就失败、环境变量不同、输出未重定向、服务器时区与预期不同。先验证脚本，再调查调度。

## 清理练习任务

使用 `crontab -e` 只删除本专题添加的一行，然后运行 `crontab -l` 确认其他任务仍保留。不要用删除全部任务的命令代替编辑。

## 本专题任务

1. 必做：在允许读取的练习环境运行 `crontab -l`，说明一条任务的时间和命令；没有任务时记录实际提示，不为完成练习而创建任务。
2. 选做（仅独立练习环境）：确认备份状态，手动运行脚本并查看日志，再添加一条练习任务。
3. 选做完成后只删除自己添加的任务行，保存修改前后 `crontab -l` 结果，确认其他行未变化。
