# 第 3 章：用户、用户组与文件权限

本章沿用第 2 章的 `~/learndoc-linux-lab`。学完后，你应能读懂“谁可以读、改、执行这个文件”，并在自己的练习文件上排查权限问题。项目服务器上的权限变更应先确认授权和手顺。

## 3.1 Linux 用户

Linux 用**用户**区分操作身份。你登录练习环境时通常是普通用户；`root` 是拥有系统管理能力的特殊用户，不是第 2 章所说的根目录 `/`。先确认自己是谁：

```bash
whoami
```

输出是当前用户名，例如 `student`。不同用户对同一个文件可能有不同操作权限；能够看到文件名，不表示一定能读取或修改内容。以下练习都使用普通用户，不切换为 `root`。

## 3.2 用户与用户组

**用户组**把若干用户归在一起，便于给一组人授予相同的访问能力。一个用户有主组，也可能加入附加组。查看自己的身份：

```bash
id
groups
```

`id` 显示用户 ID（UID）、主组 ID（GID）及所属组；`groups` 只列出组名。输出因环境不同而不同。判断某文件能否访问时，需要把这里的用户名、组名与文件的所有者信息对照；仅在 `groups` 中看到某组，不代表对所有文件都有权限。

## 3.3 文件所有者

进入练习目录，查看第 2 章创建的配置文件：

```bash
cd "$HOME/learndoc-linux-lab"
ls -l -- input/app.conf
```

`ls -l` 的一行可能类似下面这样；用户名、组名和时间以你的环境为准：

```text
-rw-r--r-- 1 student student 11 Sep 1 09:00 input/app.conf
```

第一个 `student` 是文件的 **owner（所有者）**，第二个是所属 **group（组）**。权限还会为 **others（既不是所有者、也不属于所属组的其他用户）** 单独规定。这里的 `11` 是文件字节数，不是权限。查看目录自身的所有者时，使用 `ls -ld -- 目录路径`，否则 `ls -l 目录` 显示的是目录里的内容。

## 3.4 文件权限

`r`、`w`、`x` 对普通文件和目录的作用不同：

| 权限 | 普通文件 | 目录 |
|---|---|---|
| `r` | 读取文件内容 | 列出目录中的名称 |
| `w` | 修改文件内容 | 在目录中创建、删除或改名目录项（还需 `x`） |
| `x` | 允许把文件作为程序直接执行 | 允许进入或经过目录，并访问已知名称的项目 |

例如，文件有 `r` 但没有 `w` 时，可能可以查看却不能改写。目录即使有 `r`，若缺少 `x`，也可能列得出名称却无法进入；访问文件还要能经过路径上的各级目录。删除一个文件主要看**父目录**的 `w` 和 `x`，不只看文件自身的 `w`。权限排查不能只盯着目标文件一行。

## 3.5 权限表示方法

`ls -l` 最左侧先有一个文件类型字符，后面九位才是权限。普通文件类型为 `-`，目录为 `d`：

```text
- | rwx | r-x | r--
│    │     │     └─ others：可读
│    │     └─────── group：可读、可执行
│    └───────────── owner：可读、可写、可执行
└────────────────── 普通文件
```

因此 `rwxr-xr--` 是九位权限本身，完整的普通文件显示为 `-rwxr-xr--`。数字写法把每组三位中的 `r=4`、`w=2`、`x=1` 相加：

| 单组权限 | 计算 | 数字 |
|---|---|---|
| `rwx` | 4+2+1 | `7` |
| `rw-` | 4+2 | `6` |
| `r-x` | 4+1 | `5` |
| `r--` | 4 | `4` |

| 数字 | 展开为 | 含义示例 |
|---|---|---|
| `755` | `rwxr-xr-x` | 所有者可读写执行，组与其他人可读执行 |
| `644` | `rw-r--r--` | 所有者可读写，组与其他人只读 |
| `600` | `rw-------` | 仅所有者可读写 |

例如 `755` 的第一位 `7=4+2+1`，后两位 `5=4+1`。数字本身不代表“安全”：配置若含敏感信息，`644` 可能让无关用户读到内容；项目权限应由具体需求决定。

## 3.6 修改文件权限

只复制并修改自己的练习副本，不碰原始配置：

```bash
cp -- input/app.conf output/permission-demo.conf
chmod 600 output/permission-demo.conf
ls -l -- output/permission-demo.conf
```

`chmod 权限 文件` 修改权限，不改变文件内容。这里 `600` 应让输出以 `-rw-------` 开头，表示仅所有者能读写。若用符号写法，`chmod u+x 文件` 中 `u` 指所有者，`+x` 指**增加**执行权限，不改变组与其他用户的权限。不要用 `chmod 777` 作为权限错误的通用解决办法，那会把读写执行都开放给所有人。

## 3.7 修改所属用户及组

`chown` 用于改变文件所有者，也可以同时指定所属组；`chgrp` 只改变所属组。以下是**识别命令格式，不在本章执行**的示意：

```text
chown 用户名:组名 文件路径
chgrp 组名 文件路径
```

例如 `chown appuser:appgroup app.log` 表示把所有者设为 `appuser`、组设为 `appgroup`，不是修改权限位。项目文件的所属关系由有授权的负责人按手顺处理。

## 3.8 sudo

`sudo` 是按系统策略**以其他用户身份执行一条命令**的工具，默认目标通常是 `root`；它不是永久把普通用户变成管理员，也不表示每个人都有使用资格。命令前出现 `sudo` 时，应先确认目标主机、执行目的、权限和作业手顺。本章不运行 `sudo`，更不为了绕过 `Permission denied` 自动加上它。

权限报错时，先记录当前用户和目标状态：

```bash
whoami
id
ls -l -- input/app.conf
ls -ld -- input
```

如果报错涉及更深的路径，还要逐级核对父目录的 `x` 权限，再说明需要的访问能力，不直接扩大权限。

## 3.9 用户管理基础

阅读运维手顺时可能看到 `useradd`（创建用户）和 `passwd`（设置或修改用户密码）。本课程只要求识别用途，**不执行账号管理练习**；调查权限问题时先提供当前身份及文件权限信息。

## 3.10 项目权限案例

**读取失败。** 假设 `cat input/app.conf` 提示 `Permission denied`，先在自己的练习目录查看身份、文件和所在目录，而不是立即修改权限：

```bash
whoami
ls -l -- input/app.conf
ls -ld -- input
```

`ls -l` 用于查看文件所有者和读权限，`ls -ld` 查看目录本身；若路径更深，还要逐级检查父目录是否允许经过（`x`）。文件显示可读而 `cat` 仍失败时，不能只凭这一行推断原因。这里是**假设报错**，正常练习文件通常可以读取，不要求故意制造权限故障。

**写入失败。** 假设应用无法写入日志，先区分是修改**已有文件**，还是在 `logs` 目录**创建新文件**：前者要看文件写权限及父目录的进入权限；后者要看目录的 `w`、`x`。再核对**实际运行应用的用户**和所属组；只看开发者自己的 `whoami` 不足以判断应用能否写日志。已有文件权限、目标目录权限与运行身份是三条不同线索，不能用 `chmod 777` 一次“解决”。

再用自己的练习目录模拟“脚本无法直接执行”。下面的脚本只打印一行文字，不接触项目资源：

```bash
printf '#!/bin/sh\nprintf "started\\n"\n' > output/start.sh
chmod 600 output/start.sh
ls -l -- output/start.sh
./output/start.sh
```

第一行 `#!/bin/sh` 告诉系统用 Shell 解释文件；`printf` 创建脚本，`>` 只覆盖自己的练习文件。`600` 没有 `x`，所以 `./output/start.sh` 预期出现 `Permission denied`。这次失败是练习预期结果，不要在真实项目对照执行。确认路径确实是自己的脚本后，增加**所有者**的执行权限并重试：

```bash
chmod u+x output/start.sh
ls -l -- output/start.sh
./output/start.sh
```

此时应看到权限中的所有者一组出现 `x`，终端打印 `started`。若仍报 `Permission denied`，还要检查父目录的 `x`、挂载是否禁止执行等条件，不能直接扩大为 `777`。**普通文件的 `x` 是允许直接执行，目录的 `x` 是允许进入或经过**；二者不要混淆。练习结束可保留 `output/start.sh`，后续课程不会依赖它。

课堂检查：① `-rwxr-xr--` 中哪一组属于文件所有者？② 为什么能看到文件名却可能无法读取内容？③ 脚本有读取权限却不能用 `./` 启动时，先检查什么？④ `sudo` 是否等于永久成为 `root`？参考：第一组三位 `rwx`；文件或父目录权限可能不足；文件及父目录的 `x`、实际运行身份；不是。
