# 第 2 章：变量、参数与环境变量

## 本章学习目标与前置知识

沿用第 1 章的 Bash 练习环境，学会保存业务日期与文件路径、接收位置参数、正确引用含空格的值。先会保存和运行脚本；本章尚不要求判断日期是否合法。

## 为什么日本项目需要

日次処理的処理対象日（业务日期）通常由调度系统作为参数传入，而输入文件路径、环境名也会因环境而异。把它们写死在脚本中，改修和测试都容易出错。

## 概念、语法与最小示例

变量名保存值，赋值时等号两边不留空格；读取时写 `$name`。双引号 `"$name"` 会展开变量且保持为一个参数，单引号 `'$name'` 不展开；不加引号可能把空格拆成多个参数。`$0` 是脚本名，`$1`、`$2` 是前两个参数，`$#` 是参数个数，`"$@"` 保留所有参数的各自边界。

以下是**完整可执行脚本** `show_sales_args.sh`：

```bash
#!/usr/bin/env bash
# 读取第一个位置参数；未传入时使用空字符串。
business_date="${1:-}"
# 读取第二个位置参数；引号保证路径是一个值。
input_file="${2:-}"
# 输出实际收到的参数个数。
printf 'count=%s\n' "$#"
# 同时展示日期和文件路径；尖括号便于看出空值。
printf 'date=<%s> file=<%s>\n' "$business_date" "$input_file"
```

`${1:-}` 表示没有第 1 个值时先用空串，避免空参数造成混淆；`$#` 报告参数个数，最后的 `printf` 显示两个值。执行流程是“调用方传参 → Bash 依位置赋值 → 输出观察值”，没有访问文件。

```bash
# 用单引号把含空格的路径作为一个参数传给脚本。
bash show_sales_args.sh 20260901 'input/sales data.csv'
# 不传参数，再观察脚本如何显示空值。
bash show_sales_args.sh
```

**示例输出**：第一次是 `count=2` 和 `date=<20260901> file=<input/sales data.csv>`；第二次是 `count=0` 和两个空尖括号。传入时用引号、脚本内也用引号，才能把含空格路径保留为一个文件名。第 3 章再拒绝参数不足。

环境变量通过 `export` 传给后续启动的程序，普通变量默认只属于当前 Bash。下面是**可在终端逐行执行的命令**：

```bash
# 设置环境名，并传给随后启动的子进程。
export APP_ENV='test'
# 显示刚设置的环境名。
printf 'env=%s\n' "$APP_ENV"
# 显示查找可执行命令的目录列表。
printf 'PATH=%s\n' "$PATH"
# 查看当前环境能否找到 Java 命令，不安装或修改 Java。
command -v java
```

`PATH` 列出查找命令的目录；`command -v java` 找到 Java 时显示路径，找不到通常无输出且状态非 0。此检查只读，不要求学员安装 Java 或修改服务器。`JAVA_HOME` 是有些项目用于定位 JDK 的变量，是否设置取决于项目手顺。

命令替换 `$(...)` 取命令的标准输出。例如**局部片段** `today="$(date +%Y%m%d)"` 将当前日期保存到变量；它不是业务日期的默认规则，日次 Batch 必须优先使用明确传入的业务日期。

## 常见错误与项目关联

`name = value` 会被当作命令；`$input_file` 未引用时可能按空格拆开；`date` 当前日期不一定等于处理对象日期（补跑尤其如此）。后续真实销售取込処理会用业务日期定位 `sales_YYYYMMDD.csv`，但不会根据文件名猜测参数正确。

## 本章练习与完成标准

将 `show_sales_args.sh` 的第二参数改成自己创建的含空格路径并验证仍完整输出；增加一行输出 `APP_ENV`，分别在 `export APP_ENV=test` 前后运行并记录差异。能解释变量、环境变量、双/单引号、`$1`、`$#` 与 `PATH`，即完成本章。
