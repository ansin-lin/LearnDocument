# 05 错误处理、日志与清理

项目脚本不能只在成功时运行。调用方需要通过退出状态判断结果，调查人员需要从错误信息理解失败原因，临时文件也不能留在现场。

## 5.1 设计退出状态

为脚本预先定义状态，比在各处随意写数字更容易交接：

| 状态 | 含义 | 调用方处理示例 |
|---:|---|---|
| 0 | 成功并找到记录 | 继续后续处理 |
| 1 | 正常执行，但没有匹配记录 | 确认 ID 或调查范围 |
| 2 | 参数或格式错误 | 修正调用方式 |
| 3 | 输入文件错误或搜索失败 | 确认路径、权限和命令错误 |
| 4 | 无法创建或保存输出 | 确认输出目录和磁盘状态 |

非 0 不一定等于系统故障。例如 `grep` 返回 1 表示“没有匹配行”，返回大于 1 才表示实际错误。
**退出状态**是命令结束时交给调用者的数字，不是屏幕上的错误文字。脚本必须同时给人可读的信息和机器可判断的状态；本例的状态表只适用于本课程脚本，不代表所有 Linux 命令都使用这些数字。

先不写分支，观察一条命令的状态：

```bash
grep 'ERROR' input/app.log
status=$?
printf 'grep_status=%s\n' "$status"
```

样例日志有 ERROR，状态应为 0；把搜索词改为 `FATAL` 时，正常搜索但无匹配，状态应为 1。`$?` 只保存上一条命令的状态，因此要紧接 `grep` 赋值，不能先运行 `printf` 再读取。随后再用下面的 `if` 处理不同分支；只有 `else` 不够，因为无匹配和读取文件失败都可能走进去。

```bash
if grep -n 'ERROR' input/app.log > output/result.txt; then
  printf 'matched\n'
else
  grep_status=$?
  if [[ $grep_status -eq 1 ]]; then
    printf 'no match\n' >&2
    exit 1
  fi
  printf 'grep failed: status=%s\n' "$grep_status" >&2
  exit 3
fi
```

`if grep ...; then` 在找到 ERROR 行时进入成功分支；否则立即用 `$?` 保存 `grep` 的状态。`-n` 保留原始行号。这里的 `> output/result.txt` 会先创建或清空文件，即使没有匹配也一样；它只用于说明状态分支，不能直接作为最终写文件方案。最终脚本先写临时文件，成功后才发布结果。

## 5.2 `set` 选项不是完整错误处理

```bash
set -u
set -o pipefail
```

- `set -u`：读取未定义变量时失败，能较早发现拼写错误。
- `pipefail`：管道中任一命令失败时，整条管道返回非 0。

`set -e` 的行为会受条件、管道和命令替换等上下文影响。本课程的最终脚本不把它当作完整方案，而是对关键命令显式判断并输出业务上可理解的错误。
`set -u` 和 `set -o pipefail` 是脚本设置，不会替代参数校验、错误消息或清理。前者防止误用未赋值变量；后者让管道中较早失败的命令不被最后一条命令的成功掩盖。
例如 `if grep ...; then` 本来就是在检查状态，`grep` 无匹配不应在判断前直接结束整个脚本。不要以为添加 `set -e` 就完成了异常处理；关键命令仍须区分“无匹配”和“执行错误”。

## 5.3 临时文件与 `trap`

先写临时文件，成功后再移动到正式文件，可以避免失败时留下半份结果。

```bash
tmp_file=""

cleanup() {
  if [[ -n "$tmp_file" && -f "$tmp_file" ]]; then
    rm -- "$tmp_file"
  fi
}

trap cleanup EXIT

tmp_file="$(mktemp 'output/.check-log.XXXXXX')" || {
  printf 'ERROR: cannot create temporary file\n' >&2
  exit 4
}
```

`mktemp` 创建名称不冲突的临时文件；`trap ... EXIT` 让脚本在正常结束或错误退出时执行清理。`rm -- "$tmp_file"` 中的 `--` 表示后续内容都是路径，即使文件名以 `-` 开头也不会被当作选项。

临时文件必须创建在已确认的输出目录内，不要把未经校验的输入直接拼进删除路径。
`tmp_file=""` 先声明变量，供 `cleanup` 安全读取；`mktemp` 中的 `XXXXXX` 会被替换成随机字符。`trap cleanup EXIT` 使脚本退出时调用清理函数。练习前先确认 `output` 目录存在；若没有，运行 `mkdir -p output`。清理只针对这个临时文件，不删除原日志或正式结果。
这一节先要求**读懂**：临时文件防止留下半份结果，`EXIT` 时自动清理；不要求从零设计复杂清理框架。第 06 章给出可运行的组合版本。

## 5.4 语法检查与执行跟踪

在自己的练习脚本上排错：

```bash
bash -n validate_input.sh
bash -x validate_input.sh input/app.log R001
```

`bash -n` 只检查语法，不运行处理；`bash -x` 会真正执行，并把展开后的命令写到 stderr，便于定位失败行。**跟踪可能显示参数和变量中的秘密**，因此仅在不含真实凭据的练习环境使用，不传播未经脱敏的跟踪日志。语法通过不代表业务结果正确。

## 5.5 可调查的消息

```bash
write_message() {
  local level="$1"
  local message="$2"
  printf '%s level=%s message=%s\n' \
    "$(date '+%Y-%m-%dT%H:%M:%S%z')" "$level" "$message" >&2
}
```

错误消息至少说明“发生了什么”和“涉及哪个对象”，但不得输出密码、令牌、个人信息或完整生产日志。stderr 可由作业平台或调用脚本单独收集。

## 5.6 可重复执行

可重复执行（idempotent，幂等）是指相同输入重复运行，不会不断追加重复数据或破坏原始文件。本课程脚本每次生成完整临时结果，再替换同名输出；不会修改输入日志。
