# 第 7 章：Job 调度与日本项目运用

## 本章学习目标与前置知识

前置：第 5～6 章能调用外部程序、解释日志与结束码。你将读懂调度关系，说明日次/月次、失败停止与再执行判断；不要求配置生产 JP1。

## 为什么日本项目需要

日次処理是每天运行的业务处理，月次処理是按月结算等处理。取込処理是导入数据，出力処理是生成文件或报表；本案例的销售日报便是后续出力处理。Shell 可能只占整个ジョブネット（Jobnet，作业网络）中的一环，先行ジョブ（前置作业）失败，後続ジョブ（后续作业）不能盲目继续。

## 概念、最小示例与执行流程

cron 是按时间启动命令的机制；`crontab -l` **只读**查看当前用户计划。五个时间字段依次为分钟、小时、月中日、月份、星期。下面是**配置片段，不是可在终端执行的命令**：

```text
# 配置片段：分、时、日、月、星期依次为 0、2、*、*、*；后面是调用命令。
0 2 * * * /bin/bash /project/bin/run_sales_import.sh 20260901
```

它表示每天 02:00 调用固定命令，但把业务日期写死只是讲解格式，**不能作为生产日次配置**。真实项目由调度系统传入处理对象日期，必要时与自然日不同。cron 的工作目录和环境变量往往不同于交互终端，脚本须使用明确路径并核对运行账号。

JP1/AJS 是日本项目常见的作业调度产品；Job 是一个执行单位，Jobnet 组织依赖与运行条件。这里仅按项目资料理解概念，不讲复杂操作画面和平台配置。**伪代码/流程图，非可执行脚本**：

```text
先行 Job：收取销售 CSV
      ↓ 文件到齐且结束码 0
Shell Job：接日期 → Java 取込 → 成功后归档
      ├─ 结束码 0 → 後続 Job：生成销售日报
      └─ 非 0 → 停止后续、通知担当者、保留调查资料
```

按**本案例的依赖和返回码约定**，先行失败时 Shell 不应开始；Shell 返回 10 时应标记異常終了并停止后续。真实 JP1/AJS 的判定条件和后续分支由 Jobnet 定义决定，不能以为所有非 0 都自动按本图处理。Shell 返回 0 才能被本案例视作正常終了，但业务是否完整还应结合 Java 的处理结果与项目规则。关于后续 Job 状态，可参看日立的 [JP1/AJS3 监视说明](https://itpfdoc.hitachi.co.jp/manuals/3021/30213D2130/AJSF0114.HTM)。

用个人练习脚本做**可执行的本地模拟**（先按第 5 章生成 JAR，且文件未归档）：

```bash
# 进入个人副本中的销售导入案例目录。
cd docs/tools/shell/sample/sales-import
# 运行参考脚本，等待它结束并取得业务日期的处理结果。
bash run_sales_import.sh 20260902
# 紧接脚本执行，保存它交给调用方的退出状态。
status=$?
# 模拟调度平台记录这一状态。
printf 'job_status=%s\n' "$status"
```

进入案例目录后，后三行依次执行 Shell、保存退出状态、模拟调度平台记录它。**示例输出**：成功时 `SUCCESS ...`、`job_status=0`；失败时 `ERROR ...`、非 0。若已运行过、输入被归档，重复执行会得到输入缺失，不能把它当作首次正常案例。代码中的 `status=$?` 必须紧跟脚本运行。

二重起動（重复启动）指同一业务日期的作业同时或重复运行，可能导致重复导入、文件争夺；本课脚本仅检查既有归档，**不具备并发互斥保证**。リラン／再実行（重跑）前应确认上次状态、Java 是否已产生业务副作用、输入与归档位置、担当者的手顺；异常后不自动重跑。Shell PG 负责提供准确返回码与日志，调度管理和生产批准由相应角色承担。

## 常见错误、练习与完成标准

误把 cron 定时日期当业务日期、忽略环境差异、在 Java 失败后返回 0、未调查就再执行，都会误导 Jobnet。请画出“收取 CSV → 导入 → 日报”的依赖关系，为返回码 0、3、10 写明后续应继续还是停止，以及需要确认的证据。能说清 cron、JP1/AJS、Job、Jobnet、先行/后续、日次/月次、二重起動与リラン，并展示一次本地状态记录，即完成。
