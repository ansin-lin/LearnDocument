# 07 教师参考：日志结果改修 Review

本页仅供授课和评审使用，不属于学员 01～07 章主线。学员先依据 [改修票](07_project_task.md) 独立提交脚本、测试结果与证据，再用本页核对。

## 评审顺序

1. 对照改修前的第 06 章脚本，确认只改了结果生成和必要的清理逻辑，没有删掉参数、文件、ID 校验及错误状态。
2. 正常输入 `input/app.log R001` 时，结果第一行应含本次执行时刻和源文件；后面两行应继续保留原日志行号 `1:`、`2:`。不要把示例时间硬编码。
3. 检查程序是不是**先确认搜索成功、再发布正式文件**。如果无匹配时产生仅有头行的新文件，判为不合格；既有旧结果也不能被当成本次证据。
4. 检查所有路径变量均带双引号；用 `input/app copy.log` 验证完整路径仍作为一个参数。
5. 核对返回状态：成功 0、无匹配 1、参数错误 2、输入错误 3、输出错误 4。错误文字应送往 stderr，不能只靠屏幕文字判断成功。
6. 连续运行成功案例两次，核对结果未重复追加；失败后检查没有 `.check-log.*` 临时文件。用输入文件前后摘要确认原始日志未改。

## 讨论指摘的方式

若学员把头行写到正式结果后才执行 `grep`，请先问“搜索返回 1 时留下什么文件”，让其追踪临时文件与发布时机。若日志行号消失，请让其回看原脚本的 `grep -n`，不要直接替学员重写整段代码。对于不同但满足规格的实现，按可观察结果、退出状态和清理证据评审，不要求与教师写法逐字相同。

生产环境的调度任务、日志和权限不能用于本练习；Linux 第 08 章与 Shell 第 07 章的 Web／Batch 模拟资料只供阅读和说明调查边界。
