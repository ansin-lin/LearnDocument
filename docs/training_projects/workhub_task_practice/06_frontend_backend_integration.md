# 前后端联调任务

联调目标是把 JavaScript 的数据源从 `localTaskRepository` 切换为 `apiTaskRepository`，页面和业务字段不重写。

## 开始条件

- 四个页面在本地数据模式下已经通过验收。
- 五个 API 可独立通过接口测试。
- 前后端使用[统一练习规格](00_practice_spec.md)中的字段、枚举和日期格式。

## 联调顺序

1. 配置 API 基础地址，开发环境明确允许的来源；生产或最终交付优先同源部署。
2. 接通列表接口，分别验证有数据、无数据、网络失败和服务器失败。
3. 接通详情接口，验证正常 id、无效 id 和不存在 id。
4. 接通新建接口，验证成功、前端校验失败和后端校验失败。
5. 接通编辑接口，验证成功更新和不存在任务。
6. 接通状态接口，只显示当前状态允许的操作，同时仍以后端校验为准。
7. 刷新页面确认结果来自数据库，不再依赖 localStorage。

## 前后端责任

| 问题 | 前端 | 后端 |
| --- | --- | --- |
| 必填和格式 | 尽早提示，改善操作体验 | 必须再次校验 |
| 状态迁移 | 隐藏或禁用无效操作 | 做最终业务判定 |
| 错误信息 | 显示可理解提示 | 返回稳定 code，不泄露内部信息 |
| 枚举显示 | code 转显示文字 | 只接收约定 code |

## 必做联调用例

| 编号 | 操作 | 预期结果 |
| --- | --- | --- |
| INT-01 | 无条件打开列表 | 按固定顺序显示分页结果 |
| INT-02 | 组合状态和关键字查询 | 表格和 total 同步变化 |
| INT-03 | 新建合法任务 | 返回成功，可在列表和详情查到 |
| INT-04 | 期限早于开始日 | 页面显示字段错误，数据库无新增 |
| INT-05 | 编辑后再次查看 | 编辑字段更新，其他字段保持不变 |
| INT-06 | `TODO -> IN_PROGRESS` | 状态更新并显示新操作 |
| INT-07 | `TODO -> DONE` | 操作被拒绝，原状态不变 |
| INT-08 | 使用不存在的任务 id | 返回 404，页面显示任务不存在 |
| INT-09 | 停止后端后查询 | 结束加载状态并显示失败提示 |

## 联调证据

保留一份简短记录：用例编号、执行日期、结果、截图或响应、发现的问题和修正结果。不要只提交“测试通过”四个字。
