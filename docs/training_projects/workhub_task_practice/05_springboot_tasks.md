# Spring Boot 学完后的综合练习

## 任务名称

将已经完成的 MyBatis 数据访问层封装成可测试的任务管理 REST API。

## 开始条件

- MyBatis 综合练习已经通过验收。
- 使用 Java 17、课程当前 Spring Boot 3.x、Maven、MyBatis 和 MySQL 8。
- 包名为 `com.example.workhubtask`，端口为 8080，基础路径为 `/api`。
- 接口和错误结构以[统一练习规格](00_practice_spec.md)为准。

## 要完成的接口

| 方法 | 路径 | 成功结果 |
| --- | --- | --- |
| GET | `/api/tasks` | 条件查询和分页，200 |
| GET | `/api/tasks/{id}` | 任务详情，200 |
| POST | `/api/tasks` | 新建任务，201 |
| PUT | `/api/tasks/{id}` | 编辑任务，200 |
| PUT | `/api/tasks/{id}/status` | 状态变更，200 |

另外实现 `GET /api/health`，用于确认应用启动状态。

## 具体要求

### 分层和模型

- 请求处理保持 Controller -> Service -> Mapper -> 数据库的调用方向。
- 使用构造器注入，不在 Controller 中访问 Mapper 或编写 SQL。
- 区分请求 DTO、响应 VO 和数据库实体。
- 列表响应不返回不需要的大字段，新建请求不能控制 id、taskCode、status 和时间字段。

### 校验和业务规则

- 使用 Jakarta Validation 检查必填、长度和分页范围。
- Service 检查期限不早于开始日、项目和负责人存在、状态迁移合法。
- 新建任务由后端生成 taskCode，状态固定为 TODO。
- 编辑和状态更新必须检查 Mapper 影响行数；更新 0 行时返回资源不存在错误。
- 查询无结果返回 200、空 items 和 total=0，不返回 404。

### 事务、异常和日志

- 写操作和必要的关联检查放在明确的 Service 事务边界中。
- 统一处理校验错误、资源不存在、非法状态和未知异常。
- 所有响应使用统一结构，内部异常和 SQL 不返回给前端。
- 日志保留接口和错误上下文，但不打印密码、令牌或其他敏感值。

### 配置和测试

- 分离开发、测试配置，敏感值使用环境变量占位。
- 为状态迁移 Service 编写单元测试，为五个 API 编写集成测试。
- 测试数据可重复准备，不污染开发数据库。
- README 写明数据库准备、环境变量、测试、打包、启动和健康检查方法。

## 必做接口测试

1. 无条件列表、组合查询、第二页和无结果。
2. 正常详情、非法 id 格式和不存在 id。
3. 正常新建，以及空标题、超长标题、逆序日期、无效项目。
4. 正常编辑，确认字段更新；不存在 id 返回 404。
5. TODO -> IN_PROGRESS 成功。
6. TODO -> DONE 返回 400/`TASK_STATUS_INVALID`。
7. 状态更新不存在 id 时返回 404/`RESOURCE_NOT_FOUND`。
8. 模拟未知异常，确认响应不包含堆栈和 SQL，日志能够定位问题。
9. 连续执行两次自动测试，结果一致。
10. 使用打包后的 jar 启动，健康检查和任务列表可访问。

## 限制

- 本练习不临时增加登录、权限、评论、附件和通知。
- 不直接公开 TaskEntity。
- 不使用空 catch 或把所有异常都返回 500。
- 不提交真实密码、账号或内部地址。
