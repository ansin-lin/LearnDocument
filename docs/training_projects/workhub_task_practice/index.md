# Company WorkHub 任务管理递进练习

这是一条与现有“有給休暇”练习并行的新主线。它不替代知识课程，也不替代结课综合项目；学员完成一门大课程后做一次阶段综合练习，并逐步组合成一个可运行的前后端小功能。

## 三套内容的关系

| 类型 | 用途 | 当前安排 |
| --- | --- | --- |
| 课堂示例 | 讲清单个知识点 | 保留各课程现有示例，不改正文 |
| 阶段综合练习 | 每个大知识点学完后集中完成 | 本主线：任务管理核心 |
| 结课综合项目 | 整合全部课程能力 | Company WorkHub 企业员工管理系统 |

现有三份“有給休暇”练习继续作为已经布置的练习保留。本主线用于后续批次或下一轮教学，两者不要混在同一次提交中。

## 最终成果

学员最终完成一个“任务管理核心”小系统，包含：

- 任务列表与条件查询
- 任务新建、详情和编辑
- 任务状态变更
- 前端加载中、空数据、成功和失败反馈
- Spring Boot、MyBatis、MySQL 与原生 HTML/CSS/JavaScript 联调
- 接口测试、关键业务测试和阶段验收证据

统一字段、状态、接口和业务规则见[统一练习规格](00_practice_spec.md)。练习范围来源于 Company WorkHub 的 SCR-013～SCR-017、API-TASK-001～API-TASK-005，但这里采用适合教学的简化契约；正式项目仍以正式设计书为准。

## 两种学习顺序

### 先学前端

1. HTML 完成页面骨架。
2. CSS 完成布局和状态样式。
3. JavaScript 先用本地模拟数据完成交互。
4. MyBatis 和 Spring Boot 完成真实接口。
5. 将数据源从本地模拟数据切换为 HTTP API。

### 先学后端

1. MyBatis 完成表、查询和更新。
2. Spring Boot 完成接口、校验和异常处理。
3. HTML/CSS 完成可访问的页面。
4. JavaScript 调用已经完成的接口。
5. 按同一份验收表进行联调。

两条路线最终使用相同的字段名、状态值、URL 和验收标准，因此可以在任意阶段汇合。

## 使用规则

- 每完成 HTML、CSS、JavaScript、MyBatis 或 Spring Boot 一门大课程，再布置该阶段综合练习。
- 后续综合练习必须在上一阶段成果上继续修改，不重复新建互不相关的小项目。
- 学员未学到的部分可使用给定数据或临时实现，不要求提前自学。
- 教师验收通过后保留稳定版本，再进入下一阶段。
- 最后将经验迁移到 Company WorkHub 正式综合项目，不直接复制教学版规格。
