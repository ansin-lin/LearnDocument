# 阶段验收与结课衔接

每个阶段只验收已经学过的能力。通过后保存稳定提交，再继续下一阶段。

## 每个阶段综合练习的完成定义

一个阶段综合练习只有同时满足以下条件才算完成：

1. 完成该阶段任务规定的全部功能，上一阶段成果仍可运行。
2. 逐条执行任务中的验收步骤，而不是只看代码。
3. 在对应的 `evidence/*-check.md` 中记录结果。
4. 保存阶段提交，例如 `feat: complete javascript task practice`。

记录格式：

```text
练习阶段：JavaScript 综合练习
完成日期：2026-04-10
修改文件：frontend/js/ 下的模块和四个 HTML 页面
验收结果：全部通过
证据：截图文件名、测试命令或响应摘要
发现问题：刷新后编号重复
修正结果：将 nextNumber 与任务数组一起持久化
```

如果存在未通过项，在“验收结果”中明确记录，修正并重新验证后再提交。不要伪造截图、测试输出或接口响应。

## 阶段验收表

| 阶段 | 必交成果 | 通过标准 |
| --- | --- | --- |
| 规格确认 | 字段、状态图、页面和 API 清单 | 能说清教学版与正式项目的边界 |
| HTML | 四页和列表截图 | 无样式时仍可阅读、填写、导航 |
| CSS | 样式表、桌面/窄屏截图 | 布局可用，焦点可见，状态不只靠颜色 |
| JavaScript | 本地数据版本、检查记录 | 查询、保存、编辑、状态和错误反馈可运行 |
| MyBatis | SQL、Mapper、XML、测试 | 条件查询、关联、写入和影响行数正确 |
| Spring Boot | 应用、接口测试、自动测试 | 五个 API 契约一致，异常状态正确 |
| 联调 | 运行说明、联调记录 | 页面全部切换真实 API，九个用例通过 |

## 最终演示脚本

1. 启动数据库和后端，说明使用的配置环境。
2. 打开列表，执行一次组合查询和一次无结果查询。
3. 新建任务并进入详情。
4. 编辑任务，展示修改前后的字段变化。
5. 完成一次合法状态迁移和一次非法迁移。
6. 演示网络错误或任务不存在的页面反馈。
7. 展示自动测试结果，并说明一个实际修复的问题。

## 评分建议

| 维度 | 比例 |
| --- | ---: |
| 业务规则和接口契约 | 25% |
| 前端结构、交互和可用性 | 20% |
| MyBatis 数据访问正确性 | 20% |
| Spring Boot 分层、校验和异常 | 20% |
| 测试、运行说明和证据 | 15% |

任何会造成数据覆盖、非法状态写入、敏感信息提交或项目无法运行的问题，必须修正后再通过。

## 进入综合项目时的扩展

本练习完成后，学员已经掌握任务管理的核心闭环。进入 Company WorkHub 正式综合项目时，再以正式基本设计和详细设计为准，扩展登录权限、任务看板、评论、附件、历史、进度、通知以及项目级业务规则。

迁移时先做差异表：正式字段、正式状态、正式数据库、正式 API、权限和画面规则分别与教学版比较。不得把本练习的简化约定当作正式项目需求。
