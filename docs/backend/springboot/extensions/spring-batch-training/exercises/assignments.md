# 学员任务书：勤怠日次集計・CSV連携バッチ

仅使用 [独立实验工程](../examples/attendance-batch/pom.xml) 和个人测试数据库。先完成 [01～06 章](../README.md)；提交自己的代码、测试与证据，不在共享库中运行故障注入。以下问题不附答案，教师评分依据保存在单独文件。

## 开始状态与交付物

开始状态：样例业务日期 `2026-10-19` 有 25 条虚构考勤，汇总表为空，调度默认关闭。按 [运行手册](../runbook.md)建库、配置环境变量并运行 `mvn test`。每位学员使用自己的数据库和输出目录，记录所用 Java/Maven 版本。

交付：修改后的源码与测试、`mvn test` 结果、成功/失败/恢复三个 JobExecution ID、各 Step 的读写与 Skip 件数、业务表查询结果、CSV 行数、脱敏日志和一页障害調査记录。不得提交数据库密码或真实个人信息。

## 第一组：基础知识与现场识读（20 分）

1. 在 [BatchConfig.java](../examples/attendance-batch/src/main/java/com/example/attendance/BatchConfig.java) 中标出 Job、四个 Step、JobRepository、事务管理器、Reader/Processor/Writer 与 Tasklet；画出执行顺序，并指明哪些步骤写业务表、哪些只写元数据。
2. 给定同一 `businessDate` 的两次 `FAILED`、一次 `COMPLETED` 执行，说明 JobInstance 与 JobExecution 的数量；指出再以同参数启动会怎样。另说明换日期与加入随机参数的差别。
3. 比较 `@Scheduled` 与 Spring Batch：分别负责什么、何时需要同时使用、为什么“到了 02:00”不足以证明数据交付成功。再为“Oracle 调度 + PL/SQL”和“Linux cron + Shell + Java”各画一条触发→启动→业务处理→结果核对的最小流程；只要求识读，不要求编写 Oracle 或 Shell 程序。
4. 对第 13 条处理异常，判断第一、第二、第三个 Chunk 的状态；说明 Skip、Retry、Restart 各适合什么故障，不允许把所有异常都配置为 Retry。

## 第二组：独立开发与改修（40 分）

5. 在自己的可重建副本中，为 `2026-10-19` 增加一条合法的虚构员工及考勤，`start_at=09:00`、`end_at=19:00`、`break_minutes=60`。修改样例 SQL 或独立的追加脚本，并加测试断言：源/汇总各 26 条、CSV 27 行、新员工实际工作 540 分钟、加班 60 分钟。先写预期，再运行，不把固定 25 的断言误认为改修失败。
6. 在 `validateStep` 中增加“日期不能晚于日本时间今天”的规则。给出针对未来日期的测试，同时保持历史日与空日可执行。明确这是本练习新增的业务规格，而非 Spring Batch 默认规则。
7. 增加一个只读查询或测试，按 `businessDate` 输出处理件数、异常件数与最终状态；不能仅凭 Scheduler 一行“触发成功”日志给出成功结论。
8. 让定时入口与手动入口继续共用 `BatchTrigger`。在测试环境验证业务日期为日本时间前日，并留下 JobExecution 与业务表两种证据；说明多实例部署时还需什么运行约束。

## 第三组：异常处理与自动化测试（25 分）

9. 在可重建副本中将第 13 条的休息时间改为超过总时长，执行该日期。记录失败前已提交件数、`summarizeStep` 状态与异常摘要；修正后用**相同标识参数**恢复，验证无重复和 CSV 完整。另设计 Writer 的一次暂时性数据库错误，证明仅指定异常可 Retry。
10. 制造 CSV 输出目录不可写或指向普通文件的故障，核对汇总 Step 已完成、CSV Step 失败；修复路径后同参数恢复。说明数据库事务为何不能撤销已经交付给外部的文件。
11. 至少增加两条自动化断言：数据库元数据中有对应执行记录；同日期 `COMPLETED` 后再运行被拒绝且业务表件数不变。测试应独立、可重复，不依赖真实 MySQL 账号。

## 第四组：既存项目调查与报告（15 分）

12. 假设运营反馈“`2026-10-20` 的 CSV 缺失，但汇总表已有 25 行”。只使用日志、`BATCH_JOB_EXECUTION`、`BATCH_STEP_EXECUTION`、业务表和文件系统调查。提交一份简短的日文风格报告，包含 `発生日時`、`対象ジョブ`、`業務日付`、`発生事象`、`エラーログ`、`調査内容`、`原因`、`対応方針`、`再実行可否`、`影響範囲`、`再発防止策`。事实未知时写“確認中”，不能编造。
