# 员工管理系统教学使用指南

> 本文件供课程编写者、教师和学员共同使用，规定贯穿项目如何逐章增长，避免每章重新创建无关示例。

## 一、教学原则

每个框架章节使用“双层示例”：

```text
最小示例
用于解释当前唯一的新知识点

贯穿项目示例
把已经学过的知识加入员工管理系统
```

最小示例不能引入多个陌生概念；贯穿项目可以组合已经讲过的知识。

## 二、统一规则

- 项目名称统一为 Employee Management System
- Python 练习目录使用 `employee_api`
- Java 后端练习目录可以使用 `employee-api`
- 前端练习目录可以使用 `employee-web`
- API 基础路径统一为 `/api/v1`
- JSON 字段统一使用 camelCase
- 业务代码和状态代码以共享规格为准
- 示例员工优先使用 `EMP0001`
- 示例部门优先使用 `D001`
- 示例中不得出现真实员工和公司信息

## 三、Python FastAPI 路线

| 章节 | 项目增量 |
| --- | --- |
| 环境准备 | 创建 `employee_api`、虚拟环境和依赖文件 |
| FastAPI 入门 | 创建应用、根接口、健康检查和文档 |
| 请求与响应 | 创建员工列表、详情和新增入口，建立基础配置与内存数据 |
| Pydantic | 定义员工请求模型、响应模型和字段校验，并重构新增功能 |
| 项目结构、路由与依赖 | 拆分员工、部门路由、Schema 和公共依赖 |
| SQL 基础 | 设计员工、部门、账号和日志表 |
| SQLAlchemy | 实现 ORM Model、Engine 和 Session |
| Service、Repository 与 CRUD | 替换内存数据，完成员工和部门数据库 CRUD |
| 事务与迁移 | 实现员工更新事务、乐观锁和数据库迁移 |
| 配置与异常 | 实现环境配置、统一错误和日志 |
| 认证授权 | 实现登录、当前用户和角色权限 |
| 前后端联调 | 与 Vue 或 React 页面连接 |
| 文件处理 | 实现 CSV 导入和 Excel 导出 |
| 测试 | 覆盖正常、异常、边界和权限 |
| 安全性能 | 增加密码安全、分页、N+1 调查和限流认识 |
| 部署 | 在 Linux 或容器中运行并验证健康检查 |
| 项目验收 | 对照要件完成测试、文档、部署说明和交付 |

## 四、Flask 路线

- 使用同一员工管理系统要件，不把 Flask 作为零散附录
- 从应用工厂、配置和健康检查开始
- 通过员工接口讲解路由、请求和响应
- 使用 Blueprint、Service 和 Repository 建立分层
- 使用 Flask-SQLAlchemy 与 Flask-Migrate 完成持久化
- 补全校验、异常、认证、测试和部署
- 明确区分 Flask 核心能力和第三方扩展能力

## 五、Django 路线

- 使用同一 Employee、Department 和 UserAccount 契约
- Django Model 字段与共享数据字典对应
- Django Admin 可以作为管理能力补充，不替代前后端分离主页面
- Django REST Framework API 保持 `/api/v1` 和统一 JSON 契约
- 不另建一套互不兼容的员工字段

## 六、Java、Spring Boot 与 MyBatis 路线

| 课程 | 项目增量 |
| --- | --- |
| Java 基础 | 使用 Employee、Department 类练习对象和集合 |
| SQL | 创建共享逻辑模型对应的数据表和查询 |
| MyBatis | 实现 EmployeeMapper 和 DepartmentMapper |
| Spring Boot | 实现 Controller、Service 和统一异常 |
| Validation | 对请求 DTO 执行字段校验 |
| Security | 实现登录、认证和角色权限 |
| Test | 使用 JUnit 和 Mock 验证业务与接口 |
| Deployment | 构建、配置并在 Linux 或容器运行 |

Java 内部使用 camelCase，数据库使用 snake_case。DTO、Entity 和 Mapper 字段必须明确映射。

## 七、Vue 与 React 路线

前端两条路线使用相同画面规格和接口契约：

- 登录页
- 员工列表
- 员工详情
- 员工新增和编辑
- 部门管理
- CSV 导入
- 操作日志

课程可以使用不同组件库，但必须保留：

- 加载状态
- 空数据状态
- 错误状态
- 权限处理
- 表单校验
- API 错误处理
- 可访问标签和键盘操作

## 八、数据库路线

- SQL 基础先实现部门和员工两张表
- JOIN 课程查询员工与部门名称
- 聚合课程统计各部门员工数
- 事务课程处理 CSV 整批导入
- 索引课程结合员工查询条件分析
- PL/SQL 可以实现报表或批处理补充，不改变 API 契约

## 九、Git、Linux、AWS 与自动化路线

- Git 使用员工功能作为分支和 Review 练习
- Linux 使用环境配置、进程、日志和服务调查
- Shell 使用备份、日志整理和受控批处理
- AWS 使用学习环境部署，不写入真实密钥
- 接口自动化使用员工 API 验证状态码和 JSON
- 浏览器自动化使用登录和员工查询流程

## 十、章节编写约束

新增贯穿项目示例前确认：

```text
[ ] 是否使用共享项目中的业务对象
[ ] 字段名是否与数据规格一致
[ ] API 路径和方法是否一致
[ ] 状态码和错误代码是否一致
[ ] 角色权限是否一致
[ ] 示例是否只引入当前章节的新知识
[ ] 前后章节是否使用相同样例数据
[ ] 修改契约后是否检查了其他技术路线
```

## 十一、需求变更练习

课程后期可以模拟日本项目中的改修案件：

```text
变更：员工增加 workLocation 字段
```

学员需要分析：

- 要件定义
- 画面字段
- API 请求和响应
- Python 或 Java DTO
- 数据库列
- CSV 格式
- Excel 报表
- 测试项目
- 既有数据迁移

需求变更用于练习影响范围，不应直接在各章私自增加字段。教师决定采用变更后，应先更新共享规格。

## 十二、最终交付物

学员选择的技术路线最终应交付：

- 前端代码
- 后端代码
- 数据库初始化或迁移文件
- 环境配置示例
- README
- API 文档
- 测试代码和结果
- 主要画面与接口证据
- 已知限制和后续课题
