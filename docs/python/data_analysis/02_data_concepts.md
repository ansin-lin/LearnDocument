# 数据基础概念

这一章不讲复杂代码，先讲“你手上的数据到底是什么”。

如果这一章没看懂，后面做 `merge()`、`groupby()` 时通常会一头雾水，因为你根本不知道哪张表该和哪张表连、哪些字段能算指标、哪些字段只是说明信息。

## 本章目标

学完这一章，你要能回答：

- 4 份文件分别代表什么业务对象
- 什么是事实数据，什么是主数据
- 什么是行、列、主键、关联键、粒度
- 为什么订单表能算销售额，但客户表不能直接算销售额

## 先认识 4 份数据

### 1. `orders.csv`

这是核心事实数据，也就是“发生过的业务记录”。

每一行表示一条订单明细，不是一个客户，也不是一个商品，而是“某个订单中的某一行商品记录”。

你会看到类似字段：

- `order_id`：订单编号
- `line_no`：订单行号
- `order_date`：下单日期
- `customer_id`：客户编号
- `product_id`：商品编号
- `quantity`：数量
- `unit_price`：单价
- `amount`：销售金额
- `cost_amount`：成本金额
- `gross_profit`：毛利
- `channel`：销售渠道
- `region`、`prefecture`、`store_code`：地区和门店信息

这张表最重要，因为：

- 销售额从这里算
- 订单数从这里算
- 毛利从这里算
- 退货、交货天数等分析也从这里开始

### 2. `customers.xlsx`

这是客户主数据。

它不记录每天发生了什么，而是记录“客户本身的属性”，例如：

- 客户名称
- 行业
- 客户等级
- 所属地区
- 是否活跃
- 负责人

这张表的作用不是直接算销售额，而是让你能回答：

- 哪个行业的客户贡献最大
- 哪些客户等级更容易下单
- 哪些客户已经不活跃但仍然有数据异常

### 3. `products.csv`

这是商品主数据。

主要提供商品本身的描述信息，例如：

- 商品名
- 品类
- 子类
- 品牌
- 标准价格
- 单位成本
- 生命周期状态

它的主要用途是把订单分析扩展到商品维度，比如：

- 哪个品类卖得最好
- 哪些商品毛利率高
- 哪些商品交期长但销售额低

### 4. `monthly_targets.csv`

这是目标数据，不是实际发生的数据。

它代表“计划做到多少”，例如：

- 某月某门店的目标销售额
- 某渠道某品类的目标毛利
- 目标订单数

这张表的价值在于：它让你不仅能看“卖了多少”，还能看“达成了多少”。

## 什么是事实表，什么是主数据表

在企业分析里，一个很重要的判断是：

- `orders.csv`：事实数据
- `customers.xlsx`、`products.csv`：主数据
- `monthly_targets.csv`：计划/目标数据

可以先这样理解：

| 类型 | 作用 | 典型问题 |
| --- | --- | --- |
| 事实数据 | 记录发生了什么 | 卖了多少、赚了多少、退了多少 |
| 主数据 | 说明对象是谁 | 这个客户属于哪个行业、这个商品属于哪个品类 |
| 目标数据 | 记录应该做到什么 | 本月目标是多少、是否达成 |

## 什么是粒度

粒度就是“一行数据到底代表什么”。

这是初学者最容易忽略的点，但它决定你后面会不会把数据算错。

### `orders.csv` 的粒度

`orders.csv` 的一行表示：

> 某个订单中的某一条商品明细

所以：

- `order_id` 可能重复，因为一个订单可能有多行商品
- `order_id + line_no` 更接近唯一标识

### `customers.xlsx` 的粒度

一行表示一个客户。

所以 `customer_id` 应该唯一。

### `products.csv` 的粒度

一行表示一个商品。

所以 `product_id` 应该唯一。

### `monthly_targets.csv` 的粒度

一行表示：

> 某个月、某地区/门店、某渠道、某品类的一条目标记录

所以你后面在和订单做目标对比时，必须先把订单汇总到接近同样的粒度，再去合并。

如果粒度不一致，分析结果会错。

## 什么是主键和关联键

### 主键

主键可以理解为“用来唯一识别一行数据的字段”。

在这套数据里可以这样理解：

- 客户表的主键：`customer_id`
- 商品表的主键：`product_id`

### 关联键

关联键是“用来把两张表连起来的字段”。

例如：

- 订单表通过 `customer_id` 关联客户表
- 订单表通过 `product_id` 关联商品表

这就是后面要用 `merge()` 的地方。

## 什么是维度，什么是指标

### 维度

维度是“拿来分类观察数据的角度”。

例如：

- 地区
- 门店
- 渠道
- 品类
- 客户行业
- 月份

### 指标

指标是“要统计和比较的数值”。

例如：

- 销售额 `amount`
- 订单数
- 数量 `quantity`
- 毛利 `gross_profit`
- 达成率

一句话理解：

- 维度回答“从哪个角度看”
- 指标回答“看什么数字”

## 为什么客户表不能直接算销售额

因为客户表记录的是客户属性，不是交易事实。

例如：

- 一个客户在客户表里只出现一次
- 但它可能在订单表里下过很多次单

所以：

- 销售额必须从订单表求和
- 客户表只是补充说明这个客户属于什么行业、等级、地区

这也是企业分析中非常常见的思路：

1. 从事实表算指标
2. 用主数据表补充维度
3. 用目标表做达成对比

## 本章你先记住这 4 句话

1. 订单表是核心事实数据
2. 客户表和商品表主要用于补充维度信息
3. 目标表用于比较“实际”和“计划”
4. 合并前先确认粒度，否则结果很容易错
