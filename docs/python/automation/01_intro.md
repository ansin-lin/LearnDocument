# 什么是 Python 自动化与批处理

这一章先建立自动化的基本认识。

Python 自动化不是 AI，也不是让程序模拟人点击鼠标。日本项目中更常见的是業務自動化：把固定流程、重复操作、容易出错的人工处理写成脚本，让程序按规则稳定执行。

学完本章后，你要能回答：

- 自动化在项目中解决什么问题。
- 批处理和自动化是什么关系。
- 一个自动化脚本至少应该包含哪些部分。
- 为什么“能跑一次”不等于“可以交付”。

## 一、什么是自动化

自动化就是把明确、重复、规则固定的操作交给程序执行。

例如，业务人员每天早上要做：

```text
1. 打开共享目录。
2. 检查昨天的订单 CSV 是否到齐。
3. 读取 CSV。
4. 汇总处理件数。
5. 生成处理结果文件。
6. 把结果保存到 output 目录。
7. 记录处理日志。
```

如果这些步骤每天都差不多，就适合写成自动化脚本。

```python
from pathlib import Path


# 作用：定义输入目录
# 使用场景：自动化脚本从固定目录读取文件
input_dir = Path("input")

# 作用：定义输出目录
# 使用场景：自动化脚本把结果统一保存到固定目录
output_dir = Path("output")
output_dir.mkdir(exist_ok=True)

# 作用：检查输入目录是否存在
# 使用场景：批处理开始前确认输入位置是否正确
print(input_dir.exists())  # 例如：True 表示 input 目录存在

# 作用：检查输出目录是否存在
# 使用场景：确认结果文件可以写入 output
print(output_dir.exists())  # 例如：True 表示 output 目录存在
```

这段代码还没有真正处理业务数据，但已经体现了自动化脚本的基本思想：输入位置固定、输出位置固定、执行过程可以检查。

## 二、日本项目中的自动化主要做什么

日本项目中的 Python 自动化大多围绕企业业务流程，不是为了炫技，而是为了减少人工操作、降低错误率、提高可追踪性。

| 类型 | 常见任务 | 输出结果 |
| --- | --- | --- |
| 文件处理 | 检查文件到达、改名、复制、移动、压缩、归档 | 处理后的文件、备份文件 |
| 数据处理 | CSV / Excel / JSON 转换、格式检查、简单汇总 | CSV、Excel、JSON |
| 批量操作 | 批量处理多个文件、多个日期、多个客户 | 处理结果清单 |
| 接口调用 | 调用已有系统接口，拉取数据或提交结果 | 接口响应、处理状态 |
| 定时任务 | 每天、每周、每月自动执行 | 定时执行结果 |
| 运维辅助 | 检查日志、文件大小、接口状态 | 检查报告、异常摘要 |

项目中常见说法：

| 术语 | 含义 |
| --- | --- |
| 自動化 | 自动化 |
| 業務自動化 | 业务自动化 |
| バッチ | 批处理 |
| 日次バッチ | 日批处理，每天执行 |
| 月次バッチ | 月批处理，每月执行 |
| リカバリ | 恢复处理、补救处理 |
| リラン | 重新运行、补跑 |

这些词不需要死记，但在读日本项目资料、听说明、看任务标题时会经常出现。

## 三、什么是批处理

批处理是自动化的一种典型形式。

批处理不是只处理一条数据，而是按照固定流程处理一批文件、一批记录，或者某个时间范围的数据。

典型日批处理：

```text
每天 09:00 执行：
1. 检查 input 目录是否有昨天的订单文件。
2. 读取订单文件。
3. 检查文件是否为空。
4. 统计文件行数。
5. 输出处理结果。
6. 写入日志。
```

下面是一个可以直接运行的最小批处理示例。

```python
from datetime import date, timedelta
from pathlib import Path


# 作用：计算默认处理日期
# 使用场景：每天早上处理昨天的数据
target_date = date.today() - timedelta(days=1)

# 作用：把日期格式化成文件名中常见的 YYYYMMDD
# 使用场景：根据日期查找 input 目录下的目标文件
target_date_text = target_date.strftime("%Y%m%d")

# 作用：定义输入文件路径
# 使用场景：按处理日期查找订单文件
input_file = Path("input") / f"orders_{target_date_text}.csv"

# 作用：定义输出目录并创建
# 使用场景：保存批处理结果
output_dir = Path("output")
output_dir.mkdir(exist_ok=True)

# 作用：定义结果文件路径
# 使用场景：保存本次处理状态
result_file = output_dir / f"result_{target_date_text}.txt"

if input_file.exists():
    # 作用：读取输入文件行数
    # 使用场景：确认本次处理了多少行数据
    line_count = len(input_file.read_text(encoding="utf-8").splitlines())

    result_text = f"status=success\nfile={input_file.name}\nlines={line_count}\n"
else:
    # 作用：输入文件不存在时生成失败结果
    # 使用场景：让失败原因可以被人检查，而不是静默失败
    result_text = f"status=failed\nreason=file not found\nfile={input_file.name}\n"

result_file.write_text(result_text, encoding="utf-8")

print(result_file.exists())  # 例如：True 表示处理结果文件已生成
print(result_file)  # 例如：output\result_20260726.txt
```

可能输出的结果文件内容：

```text
status=success
file=orders_20260726.csv
lines=1201
```

如果输入文件不存在，结果文件内容可能是：

```text
status=failed
reason=file not found
file=orders_20260726.csv
```

这个例子虽然简单，但已经具备自动化脚本的基本结构：

- 有输入文件。
- 有处理日期。
- 有输出目录。
- 有成功或失败结果。
- 可以重复执行。

## 四、自动化脚本和普通练习脚本的区别

普通 Python 练习只要求理解语法，自动化脚本要能在项目中稳定执行。

| 普通练习脚本 | 企业自动化脚本 |
| --- | --- |
| 手动运行一次 | 可以手动运行，也可以定时运行 |
| 路径写死 | 路径通过配置或参数传入 |
| 只处理一个文件 | 可以批量处理多个文件 |
| 出错直接停止 | 出错有日志、错误信息和处理结果 |
| 只看屏幕输出 | 会生成 CSV、Excel、日志、通知 |
| 不考虑重跑 | 要考虑失败后补跑和重复执行 |
| 不考虑交接 | 要让别人能运行和维护 |

例如下面这类写法只适合练习：

```python
# 作用：临时读取一个固定文件
# 使用场景：个人练习或快速测试
text = Path("orders.csv").read_text(encoding="utf-8")

print(text[:100])  # 例如：显示前 100 个字符
```

项目中更推荐把路径、输出、错误处理都明确写出来：

```python
# 作用：定义输入文件和输出目录
# 使用场景：让脚本路径清楚，方便后续改成参数或配置
input_file = Path("input") / "orders.csv"
output_dir = Path("output")
output_dir.mkdir(exist_ok=True)

if not input_file.exists():
    # 作用：输入文件不存在时主动报错
    # 使用场景：避免后续处理产生误导性结果
    raise FileNotFoundError(f"input file not found: {input_file}")

text = input_file.read_text(encoding="utf-8")

print(len(text))  # 例如：24500 表示读取到 24500 个字符
```

## 五、自动化项目的基本流程

企业自动化脚本通常可以抽象成 6 个阶段：

```text
输入 → 检查 → 处理 → 输出 → 通知 → 日志
```

| 阶段 | 说明 | 示例 |
| --- | --- | --- |
| 输入 | 获取文件、数据库数据或接口数据 | 读取订单 CSV |
| 检查 | 检查文件、字段、件数、空值 | 确认文件存在且不为空 |
| 处理 | 转换、汇总、调用接口 | 生成销售汇总 |
| 输出 | 保存结果 | 输出 Excel 报表 |
| 通知 | 告知处理结果 | 发送邮件或调用通知接口 |
| 日志 | 记录过程和异常 | 写入 `job.log` |

本课程后续章节会逐步补齐这些能力。

## 六、自动化脚本的最低交付标准

一个自动化脚本至少要满足下面这些要求。

| 标准 | 说明 |
| --- | --- |
| 有固定入口 | 可以通过 `python job.py` 或调度器执行 |
| 参数可配置 | 输入路径、输出路径、处理日期不要全部写死 |
| 有结果文件 | 成功后能看到 CSV、Excel、JSON、日志等结果 |
| 有错误信息 | 失败时能知道失败原因 |
| 有日志 | 能查到开始、结束、处理件数、异常 |
| 可重复执行 | 重跑不会随便破坏已有结果 |
| 操作范围安全 | 不随便删除或覆盖正式数据 |
| 可交接 | 其他成员能按说明运行和维护 |

其中“可重复执行”非常重要。

例如：

- 同一天重复执行，是否会覆盖旧结果？
- 如果会覆盖，是否符合规格？
- 如果不能覆盖，是否应该加时间戳？
- 如果处理失败，是否可以补跑？
- 补跑前是否需要清理旧的中间文件？

这些问题都是自动化项目中必须考虑的。

## 七、自动化脚本常见输入和输出

自动化脚本通常不是只在屏幕上打印结果，而是要产生可交付的文件或状态。

| 输入 | 输出 |
| --- | --- |
| CSV 文件 | 处理后的 CSV |
| Excel 文件 | 多 Sheet Excel 报表 |
| JSON 配置 | 执行结果 JSON |
| 日志文件 | 异常明细 CSV |
| 数据库查询结果 | 汇总表或报表文件 |
| 接口响应 | 通知状态、处理结果 |

后续章节会围绕这些输入输出展开。

这个项目只做安全范围内的辅助检查，不做危险的服务器操作。
