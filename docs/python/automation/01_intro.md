# 第1章 Python 自动化路线总览

这条路线讲的是“如何把重复工作交给 Python”。在日本项目现场，自动化常见的目标不是做复杂算法，也不是桌面点击脚本，而是稳定完成下面这类任务：

- 批量处理文件
- 读取数据库或接口结果并生成报表
- 按固定规则整理文本或日志
- 定时执行脚本
- 自动发送通知
- 生成运维辅助结果

## 1.1 这条路线解决什么问题

学完后，你应该能独立完成下面这类工作：

- 扫描目录并批量处理文件
- 生成 CSV、Excel、JSON 等结果文件
- 调用外部接口获取数据或发送通知
- 为脚本增加日志、错误处理和重试机制
- 把多个步骤串成一个稳定执行的自动化流程

这条路线的重点是“稳定交付”，不是单独罗列函数或库。

## 1.2 和已有路线的关系

如果你前面已经学过 [数据分析路线](../data_analysis/index.md)，两条路线可以这样衔接：

- 数据分析路线负责：读数、清洗、汇总、可视化、报表结果
- 自动化路线负责：把这些处理步骤批量化、定时化、可重复执行

一个典型的承接场景就是：

```text
数据库 -> Python 查询与整理 -> Excel 报表 -> 邮件发送 -> 日志记录
```

也就是说：

- “怎么分析数据”主要放在数据分析路线
- “怎么让它每天自动跑起来”主要放在自动化路线

如果你前面已经学过 `web/` 路线，这里也不再重复讲：

- HTTP 基础
- API 设计思路
- Web 框架开发

这里只保留自动化脚本必须会的“接口调用侧用法”。

## 1.3 适合放在这条路线里的主题

这条路线适合讲：

1. 文件批处理
2. 自动化场景下的 CSV、Excel、JSON 处理
3. 文本与日志处理
4. API 调用
5. 定时执行
6. 日志记录、异常处理和重试
7. 自动化项目整合

不适合在这里重复展开：

- Pandas 基础语法
- 数据分析指标设计
- 图表分析结论写法
- Web 应用开发流程
- 前后端分离设计

这些内容应该留在对应独立主线。

## 1.4 面向日本项目时的常见自动化任务

在日本项目里，比较典型的自动化任务包括：

- 每日或每月自动生成 Excel 报表
- 批量整理上传下载文件
- 日志文件抽取错误记录
- 对账结果输出
- 自动发送日报或异常通知
- 检查文件或任务状态

所以这条路线后面的项目，应优先围绕这些真实交付场景展开。

## 1.5 学习顺序

建议按下面顺序推进：

1. 文件与目录操作
2. CSV、JSON、Excel 读写
3. 文本与日志处理
4. 接口调用
5. 批处理和定时任务
6. 日志、异常和重试
7. 项目实战：自动化报表、日志分析、运维辅助

## 1.6 学完后的最低交付标准

完成这条路线后，至少要能交付下面这些结果：

- 一个可以重复执行的 Python 自动化脚本
- 一份自动生成的结果文件
- 一套基本日志输出
- 一种失败时可追查的错误处理方式

如果脚本只能“偶尔跑通一次”，但不能稳定重复执行，就还不算达到自动化交付标准。
