# 第6章 批处理、定时任务与配置管理

自动化脚本在日本项目里最常见的落地方式，不是手动双击运行，而是：

- 每天固定时间自动执行
- 按月、按周生成报表
- 用配置切换环境或目标日期

所以“让脚本稳定定时运行”是自动化的核心能力之一。

## 6.1 批处理思维

一个自动化任务通常不是一步，而是一串步骤：

1. 检查输入文件或查询条件
2. 读取数据
3. 清洗和整理
4. 生成结果文件
5. 输出日志
6. 归档原始文件
7. 发送通知

这就是批处理流程。

## 6.2 把入口写清楚

```python
def main():
    print("开始执行日报脚本")
    # 1. 读取输入
    # 2. 处理数据
    # 3. 输出结果


if __name__ == "__main__":
    main()
```

所有自动化脚本都建议有明确入口，方便本地执行、任务调度和排障。

## 6.3 用参数控制执行日期

```python
import argparse

parser = argparse.ArgumentParser()
parser.add_argument("--target-date", required=True)
args = parser.parse_args()

print("处理日期:", args.target_date)
```

这样做的好处是：

- 可以补跑指定日期
- 不必每次改代码
- 更适合批处理和任务调度

## 6.4 配置文件的价值

自动化脚本里常见配置包括：

- 输入目录
- 输出目录
- 数据库连接信息
- API 地址
- 邮件接收人

不要把这些值全部写死在代码里。

## 6.5 日本项目里常见的定时执行方式

常见运行方式包括：

- Windows 任务计划程序
- Linux `cron`
- 批处理脚本或 shell 脚本包装 Python

课程里不一定要把所有调度器都展开到底，但必须让学员理解：

- 脚本要能被非交互方式执行
- 运行参数要可外部传入
- 输出日志要可追查

## 6.6 可补跑比“只会自动跑”更重要

很多现场问题不是“每天跑”，而是：

- 某天失败了要补跑
- 某个月报要重做
- 某个分店数据要单独重出

所以一个成熟脚本至少要支持：

- 指定日期执行
- 指定输入文件执行
- 失败后重跑

## 6.7 本章练习

请完成一个最小批处理脚本，要求：

1. 使用 `main()` 作为入口。
2. 接收 `--target-date` 参数。
3. 打印本次执行的处理日期。

这是后面综合自动化项目的基础骨架。
