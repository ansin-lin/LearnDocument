# 示例编写规则

适用于所有技术栈中的代码、命令、SQL、配置、数据、架构、输出和错误示例。

## 示例目标与类型

- 一个示例只服务一个主要学习目标，使用清楚、稳定且有业务含义的名称。
- 明确标记完整程序、代码片段、配置片段、SQL、命令、架构图或伪代码；不得把省略关键逻辑的片段称为可直接运行。
- 完整程序包含必要导入、入口、依赖和运行方法；片段说明所属文件、类、函数、组件或插入位置。
- 第三方依赖首次出现时说明安装方式、主要版本或项目上下文。

## 独立示例与贯穿项目

- 说明示例是独立实验还是贯穿项目增量。
- 贯穿项目增量明确本章开始状态、目标文件或资源，以及新建、追加、替换或删除的范围。
- 跨章节保持目录、名称、字段、类型、接口、路由、配置和样例数据一致；必要变化说明迁移步骤。
- 不引用尚未讲解或链接的核心接口；临时占位必须说明作用和后续替换位置。
- 大段代码修改后给出关键最终状态或可核对的完整文件，避免学员无法组合零散片段。

## 运行、结果与排错

- 说明运行环境、工作目录、前置状态、执行命令和预期结果；结果不直观时展示真实或明确标注的示例输出。
- 代码、配置、路径、字段、解释和输出必须一致，不编造 API、参数、命令或执行结果。
- 声称可运行的示例应尽量实际执行；无法验证外部服务、GUI、数据库或云资源时说明未验证条件。
- 错误示例给出错误代码、异常或症状、定位方法、原因和修正方式，不只展示错误答案。
- 每个操作阶段提供至少一种成功验证；产生资源或状态变化时说明清理、回滚或恢复方式。

## 示例类别要求

- **SQL**：说明数据库或方言、表结构、前置数据和非直观结果。
- **Shell/Git**：说明操作系统、Shell、目录、前置状态和风险，不混用不同 Shell 语法。
- **云与运维**：说明前置资源、验证、成本或权限影响，以及清理或回滚。
- **前端**：说明 HTML、样式、脚本、依赖和构建上下文，覆盖必要的加载、空数据、成功和失败状态。
- **后端**：说明请求、输入、持久化、响应和异常的必要上下文，跨层名称与类型保持一致。

## 安全与企业边界

- 网络请求设置合理超时，重试必须有限。
- 删除、权限变更、历史改写、数据库写入和云资源创建必须限定范围并说明风险。
- 不使用真实密钥、密码、账号、令牌或内部地址，不把前端环境变量描述为秘密存储。
- 企业示例接近真实开发习惯，但不为显得完整引入与当前目标无关的层、库或配置。
