# 教学文档审核规则

适用于所有技术栈的检查、评价和 Review。审核时组合加载目标技术规则；包含示例、框架或依赖时同时加载对应通用规则。

## 审核顺序

1. 技术事实、安全边界和易变信息
2. 示例可运行性，以及代码、配置、解释和结果一致性
3. 文件、导航、编号、链接和 Markdown 结构
4. 最终成果、前置知识、阶段顺序和贯穿状态
5. 内容归属、缺失、重复、体量和难度
6. 学员正文边界、练习质量和实际应用
7. 标题、格式、术语及项目定位

## 严重程度

- **P0**：技术或安全错误；示例无法按原文运行；正文与结果矛盾；文件、导航、编号、引用、链接或 Markdown 结构损坏。
- **P1**：核心内容或依赖缺失；入口、路线与导航矛盾；主线频繁切换同类技术；学习顺序或难度不合理；贯穿项目状态不一致；项目大量使用未讲解接口；操作章节缺少运行或验证；最终项目为空、不可运行或无法验收；长期以复述题代替操作；大量作者视角内容干扰学习。
- **P2**：单章体量或拆分不合理；重复解释；列出不会使用的接口；基础章与项目章重复完整说明；相似术语表或现场清单机械出现；表达、标题、格式或术语质量问题；偶发作者视角内容。

不要为 P2 扩大范围或破坏正确内容；局部修复能够解决时不建议全文重写。

## 结构与成果检查

- 检查课程声明的最终成果是否由前面阶段逐步支持，最终项目是否实际整合核心能力。
- 检查每个操作阶段的开始状态、修改位置、结果和验证能否连接到下一阶段。
- 检查章节体量是否极端失衡，是否存在只有标题、目录或待补充说明的占位内容。
- 检查核心接口是否先有基础说明和最小示例，再进入项目应用；辅助依赖不要求机械独立成章。
- 检查练习是否覆盖实现、修改、验证和排错，并提供可检查结果。
- 检查企业与日本 IT 内容是否依附具体任务，而不是重复泛化描述。

## 审核方法与输出

- 先列问题，再给总结；按 P0、P1、P2 排序并提供文件、行号和可执行修复建议。
- 区分技术、安全、示例、结构、教学和风格问题，不只给分数或泛泛评价。
- 没有发现问题时明确说明，并列出未执行或无法外部验证的风险。
- 区分技术原因与课程编排原因；后者不应混入学员正文。
- 明确标记为教师指南或课程维护文档的文件不按学员正文处理。

结构、导航、共享文件或正式审核时执行：

```powershell
python skills/maintain-teaching-docs/scripts/audit_teaching_docs.py --root .
```

单课程可使用 `--scope <path>`。自动审计只能辅助定位，不能证明技术和教学内容正确。
