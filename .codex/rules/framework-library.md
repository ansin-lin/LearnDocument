# 框架、库与依赖教学规则

适用于所有技术栈中的框架、第三方库、组件库、插件和学员直接使用的关键依赖。

## 范围选择

- 先根据最终项目和常见任务确定需要使用的核心接口，再设计基础说明和示例；不以完整 API 分类代替教学路线。
- 主线只保留高频或会在后续练习、项目中实际使用的能力。替代方案、高级接口和低频配置放入扩展内容。
- 一条零基础主线保持主要框架或实现风格稳定；同类框架比较放在学员掌握一条主线之后。
- 只服务一个功能的辅助依赖可以放在对应项目章节；传递依赖和一次性小库通常不独立成章。

## 教学顺序

按“职责与边界 → 核心对象和执行流程 → 单点最小示例 → 阶段成果 → 项目综合应用”组织。

- 复杂框架按可观察成果拆分，不把全部配置、注解、组件或方法堆进一个章节。
- 进入项目应用前，先用最小输入、请求、组件或文件说明学员会直接使用的核心接口。
- 每个核心接口说明名称和类型、作用、重要参数或配置、返回值或状态变化、常见场景和错误。
- 接口表格用于查阅，不能替代最小示例、执行过程和结果说明。

## 项目应用

- 项目章节说明需求、已有状态、修改位置、调用或数据流、验证方式和常见故障。
- 项目使用的核心接口必须已经讲解或链接；项目中只做必要回顾，不复制完整基础说明。
- 基础章节介绍的核心接口应在后续练习或项目中出现；未使用的接口删除、后移或说明独立用途。
- 最终项目以整合和验收为主，不集中引入大量此前未讲的核心框架能力。

## 依赖与版本

- 说明直接依赖的安装方式、主要版本、兼容要求和必要配置；不展开与学员无关的传递依赖。
- 易变版本、默认行为、弃用接口和安全建议优先核对官方资料。
- 依赖文件、正文命令、导入方式和示例代码保持一致，并说明如何重建环境。

## 禁止事项

- 不罗列框架全部 API、属性、注解、组件或配置项。
- 不把安装成功等同于已经掌握框架。
- 不先展示大型项目，再补讲其中关键接口的含义。
- 不在相邻基础章和项目章重复完整解释同一接口。
