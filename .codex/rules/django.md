# Django 课程规则

## 主线定位

- Django 零基础主线以一条可持续运行的业务项目推进，先完成服务端渲染，再把 REST/DRF 作为后续分离式开发阶段。
- 先建立 URL → View → Response/Template 的请求链，再逐步加入 Model、迁移、Admin、ORM、Form、CRUD、查询分页、认证授权、文件、日志和测试。
- Static 与模板页面结合教学；Media 与上传下载结合教学。认证先于授权，中间件在学员理解请求流程和基础业务后讲解。

## 服务端渲染主线成果

- 学员先完成项目启动和第一个响应，再完成带样式的静态列表；不要在第一个可见结果前集中讲完全部路由或配置。
- Model 与迁移完成后使用 Admin 录入初始数据，再通过 ORM 完成列表和详情，形成页面与数据库的第一个闭环。
- 表单阶段依次完成新增、编辑、删除确认、消息提示、搜索和分页，最终形成可运行的基础 CRUD。
- 登录和 Session 先建立身份，再使用用户组和权限控制后端操作；模板按钮控制只能作为界面反馈。
- 文件阶段同时覆盖 Media、上传校验、安全命名、访问权限和下载响应，不把上传功能拆成缺少安全边界的孤立示例。
- 日志、404/500、简单中间件和测试服务于故障调查与回归验证；最终阶段包含环境重建、验收、交付和既有项目改修。

## 核心能力

- 项目和 App、配置、路由与反向解析、函数视图、模板继承、静态资源、Model 与迁移、Admin、QuerySet、`get_object_or_404()`、Form/ModelForm、CSRF、messages、`Q` 查询、Paginator、Session、权限、文件处理、日志、异常、中间件和 TestCase。
- ORM 先讲常见 CRUD、关系和查询结果，再讲性能、事务和高级表达式；项目中的查询说明返回类型和数据库访问影响。
- 表单区分输入校验、模型约束和业务规则；页面隐藏按钮不能替代后端权限检查。

## 项目连续性

- 项目名、App、模型字段、路由名、模板路径和数据库状态跨章节保持一致。
- 每个阶段给出启动、迁移、页面或测试验证；模型变化必须同步迁移步骤。
- Admin、文件上传、综合项目、日志和测试不得保留为空标题；最终项目必须可以重新搭建和验收。
- 项目交付提供依赖、配置示例、数据库准备、启动、测试、验收、已知限制和故障排查入口；不能只提供最终代码清单。

## 安全与现场任务

- 开发配置与生产配置分开，敏感信息不硬编码；说明 CSRF、XSS 自动转义、上传限制、权限、错误信息和安全部署边界。
- SES 改修任务包含规格、影响范围、既有代码定位、自测、Review 修正和交接，不只训练从零创建项目。
