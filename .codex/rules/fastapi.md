# FastAPI 课程规则

## 主线定位

- FastAPI 作为接口开发主线时，先建立请求 → 路由函数 → 校验 → 响应的最小闭环，再进入分层、数据库、认证、测试和部署。
- 明确同步与异步函数边界，不把 `async def` 描述为自动提升所有场景性能。

## 核心能力

- 覆盖路径、查询和请求体参数，Pydantic 模型，响应模型，状态码，依赖注入，Router，异常处理，OpenAPI 文档和测试。
- 参数来源、必填条件、类型转换、校验错误和响应结构必须与代码一致。
- 依赖注入先讲函数依赖和资源生命周期，再用于数据库会话、认证和公共校验。
- 数据库、事务和认证的核心接口必须先有最小示例，再组合进项目。

## 项目与安全

- API 项目保持路由前缀、模型、错误结构、数据库生命周期和配置连续，提供可执行请求与测试验证。
- 说明 CORS 不是认证或授权；密码哈希、JWT/Session、文件校验、密钥、日志和部署遵守各自安全边界。
- 最终项目包含接口规格、测试、配置、运行和验收，不只依赖自动生成文档证明正确。
